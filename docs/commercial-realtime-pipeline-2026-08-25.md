# 商业化实时面试链路实施与验证报告（2026-08-25）

## 本轮实施范围

- 桌面助手保留麦克风、系统输出两个独立逻辑声道，继续使用一个持久 WebSocket。
- 新版桌面助手通过 `media=binary-v1` 协商二进制音频帧；已发布客户端继续使用 `json-base64`，单连接不允许混用。
- 已认证连接的逐帧热路径不再查询 PostgreSQL，不再扫描全部 receipt，也不再逐帧重写全局 Redis 运行态快照。
- ASR、入口队列和冷路径线程池分别限流；最终历史、用量和会话上下文在转录事件发布后异步写入。
- SSE 首次进入或游标失效时发送完整快照，正常更新只发送增量事件。
- 浏览器按 `cursor + segmentId + revision` 单调归并，最终转录不会被迟到的部分转录覆盖。
- 仅面试官声道生成稳定问题和上下文预取；用户点击快答时冻结问题版本。预取和实时转写不会自动触发回答。

## 兼容与回滚边界

- 协议版本仍为 `2.0`，Bundle Identifier 不变。
- macOS `0.1.17` 及更早版本仍可通过 JSON/base64 WebSocket 使用当前服务端。
- macOS `0.1.18` 使用二进制音频传输；如协商失败，连接按协议错误关闭，不在同一会话内静默切换媒体格式。
- HTTP 逐帧入口暂未删除，仅保留在已有功能开关后，等待旧版本兼容窗口结束。

## 本地性能证据

使用 120 帧合成二进制音频、单持久连接和 25ms 发送节奏执行入口基准：

- 帧 ACK p50：`1.38ms`
- 帧 ACK p95：`2.11ms`
- 队列结束时剩余帧：`0`

本地没有连接真实 Qwen Realtime ASR，因此不将合成环境结果冒充真实转录 p95。生产验收继续使用统一 trace 的 `captureToIngestMs`、`queueWaitMs`、`asrTtftMs`、`captureToPublishMs` 和浏览器 delivery ACK，目标仍为转录 p95 不超过 2 秒、控制事件 p95 不超过 500ms、短暂中断 5 秒内恢复。

## 隐私
