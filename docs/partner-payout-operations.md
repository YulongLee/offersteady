# 合作伙伴人工结算操作说明

## 结算边界

- 系统只计算、冻结和登记佣金，不调用支付宝或微信自动转账。
- 合作伙伴提交结算申请后，由具备 `promotion.payout.manage` 权限的管理员审核并线下打款。
- 打款完成后，管理员填写不含敏感信息的支付参考号，再将申请标记为“已结算”。
- 退款和拒付继续通过追加冲正记录处理，不修改历史佣金账本。

## 活动入口与开关

- 用户入口只展示在官网首页底部，不进入登录后的桌面或移动端工作台导航。
- 后台“推广中心 → 合作伙伴”提供活动开关，`promotion.manage` 管理员填写原因并确认后生效。
- 关闭活动只隐藏首页入口并拒绝新用户加入；已有推广链接、归因、佣金、收款资料、结算申请和后台人工对账均保留。
- 部署环境中的 `OFFERSTEADY_PARTNER_PROGRAM_ENABLED` 仍是总开关；后台开关是日常运营控制，不替代部署级故障隔离。

## 收款资料保护

- 仅收集收款方式、实名姓名和支付宝/微信账号；不收集身份证、银行卡、收款码或图片。
- 姓名和账号使用独立的 `OFFERSTEADY_PARTNER_PAYOUT_ENCRYPTION_KEY` 加密，列表和用户页面只返回脱敏值。
- 每次修改创建新版本；结算申请固定引用提交当时的版本，避免历史结算被后来修改覆盖。
- 完整资料只能由具备结算权限且完成近期安全验证的管理员按结算单查看；成功和失败都会进入审计日志，响应禁止缓存。
- `OFFERSTEADY_PARTNER_PAYOUT_RETENTION_DAYS` 只记录计划保留期限。在法务确认清理政策前，不自动删除结算凭证。

## 上线步骤

1. 先保持 `OFFERSTEADY_PARTNER_PAYOUT_PROFILE_ENABLED=false` 部署附加迁移和应用版本。
2. 生成至少 32 字符、仅服务端可读的独立随机密钥，设置 `OFFERSTEADY_PARTNER_PAYOUT_ENCRYPTION_KEY`。
3. 使用合成账号验证保存、脱敏读取、申请绑定、管理员查看、批准、打款登记和退款冲正。
4. 观察错误率与数据库耗时后，单独开启 `OFFERSTEADY_PARTNER_PAYOUT_PROFILE_ENABLED=true`。
5. 不在日志、工单、截图、导出或支付参考号中记录完整姓名和账号。

## 密钥轮换与回滚

- 当前写入版本由 `OFFERSTEADY_PARTNER_PAYOUT_KEY_VERSION` 标记。轮换前应先实现并验证旧版本解密、新版本写入的双钥窗口，不可直接覆盖旧密钥。
- 应用回滚时先关闭收款资料开关；附加表和字段保留，不回滚或删除财务历史。
- 关闭该开关不会影响推广链接、归因、佣金投影、现有结算列表、面试或支付链路。
