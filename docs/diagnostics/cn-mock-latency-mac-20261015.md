# 国服模拟面试：下一题等待与 Mac 收音故障

检查日期：2026-10-15，北京时间。用户反馈：Mac 能连接，但麦克风和转写无反应；提交回答后下一题等待较久。

## 结论

1. **Mac 收音失败已经确认是当前安装包的签名配置缺陷。** 启用了 Hardened Runtime，但主应用与 Renderer Helper 都缺少 `com.apple.security.device.audio-input`。系统日志直接记录拒绝原因。
2. **本次下一题已经生成失败，而非仍在正常生成。** 最近测试记录有一轮已提交回答，保存 `generation_unavailable`、`provider_failures=1`，生成任务租约已释放。故障发生在文本生成或结果校验阶段；当前日志没有保留具体异常，无法进一步区分模型超时、HTTP 错误、格式或重复题校验失败。
3. **提交后的串行语音关闭增加等待时间。** 当前流程等待旧 ASR 连接关闭后，才启动下一题生成并发布状态。关闭握手超时配置为 8 秒；这是一项已复现的延迟来源，但没有本次各阶段计时，不能声称此次实际耗时就是 8 秒。

## Mac 证据

- 实际运行：`/Applications/面试稳伴随程序.app`，版本标签 `1.3.2`，于 00:39:10 启动。
- 安装包签名时间：2026-10-11 23:03:36。签名完整性校验通过，缺陷在签名权限配置。
- 对该应用及 Helper 筛选的系统 `tccd` 日志包含 31 条错误：`kTCCServiceMicrophone requires entitlement com.apple.security.device.audio-input but it is missing`。首条发生于 00:39:11，模拟面试期间 00:41:50–00:42:19 反复出现。
- 当前窗口显示连接正常，但麦克风“通道需要检查”“我的声音不可用”。系统输出通道也显示检测异常；本次仅将系统麦克风拒绝作为已确认根因，不扩大推断系统输出的故障原因。
- 内部以设备 ID 的哈希比对，确认本机就是本次模拟面试绑定的设备。未输出设备 ID、机器码或凭据。
- 当前设备登记仍为在线，麦克风能力为 `unknown`；在线仅代表登记连接存活，不代表采集成功。
- 安装包版本标签不足以识别行为：实际 renderer 已有独立模拟面试麦克风通道，并非官方早期 `1.3.2` 的纯 legacy 实现；主程序周期登记的能力又不包含该 mock 标识。
- `app.asar` SHA-256：`dea54cae3ef10812185c6f8b82987dd2613171fc1efdb27e2f5f627b0bc5ca6d`。

[Apple Audio Input Entitlement 文档](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.device.audio-input)说明该权限控制内置麦克风与 Core Audio 输入访问。已有系统麦克风授权不能替代 Hardened Runtime 所需签名权限。

## 出题与连接证据

- 唯一最近测试创建于 00:40:49，第一题回答已提交；00:58 的只读检查仍保存生成失败状态，控制与生成任务租约均已释放。
- `provider_failures=1` 的计数入口是文本生成异常、生成阶段超时或结果校验失败。单纯麦克风断连与简历读取失败不产生该计数，不能混为同一个根因。
- 当前出题使用 `deepseek-v4.1-flash`，非流式完整 JSON 返回后才发布题目。任务总截止为 45 秒，HTTP 超时为 40 秒；每轮还会重新读取所选简历版本。
- 模拟面试的生成代码将 HTTP、超时、结构化输出和重复题错误统一转换为通用失败，没有记录阶段耗时或安全错误分类。现有记录无法恢复此次更细的原因。
- 合成复现显示：给旧语音关闭加入 750 ms 延迟，下一题生成启动与状态发布随之延后约 750 ms。只使用合成数据，未调用收费模型。
- 00:41:21、00:41:26、00:41:32、00:41:43、00:46:19 有麦克风通道断连后的清理异常：`socket.close()` 抛出 `WebSocketDisconnect`，`finally` 仅捕获 `RuntimeError`。这是次生清理缺陷，不是系统拒绝麦克风的初始原因，也不能解释模型失败计数。
- 检查时后端健康、无重启，服务器未见整体负载饱和。没有证据将本次问题归因于 API P95 或本轮轻量 heartbeat 恢复。

## 修复顺序与验收建议

1. 重建 Mac 安装包，补齐主应用及 Helper 的音频输入签名权限，核对实际包内容、版本与签名。实体 Mac 验收必须包含连接后真实麦克风输入和模拟面试转写；仅源码测试或“连接正常”不能通过验收。
2. 在提交回答后先隔离旧轮音频并及时发布生成状态，避免等待上游关闭握手才启动生成。回归验证旧轮音频不会进入新题，且提交重复、暂停、结束和断连行为仍正确。
3. 为简历读取、ASR 关闭、模型请求与结果校验增加耗时及脱敏错误分类，不记录简历、问题、回答、音频、密钥或机器码。先用观测区分真实模型延迟与失败，再确定模型策略调整。
4. 修复麦克风断连清理异常与错误提示被重连提示覆盖的问题，保留用户可理解的首个失败原因。

本轮为只读诊断，未重启服务、创建收费测试面试、调用收费模型、授予系统权限或部署修复。这里只保存脱敏检查结论，没有真实用户问答、简历或音频。
