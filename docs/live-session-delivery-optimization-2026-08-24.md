# 实时面试会话交付性能优化报告（2026-08-24）

## 结论

本轮只优化网页端与后端之间的实时会话交付和断线恢复，不修改桌面助手、音频采集、ASR 模型、问题确认、快答、截图回答、回答生成、积分或支付逻辑。

主要放大因素已经消除：健康 SSE 建立后不再每秒并行请求运行态、转写、候选问题和事件四个接口；断线恢复改为一次聚合快照，并采用立即、2、4、8、15 秒的非重叠退避。同一浏览器中的同一场面试只保留一个服务端 SSE 连接，其他标签页通过 `BroadcastChannel` 接收状态。

## 优化前基线

以下数据来自优化前的线上只读观测，代表当时样本，不等同于长期 SLA：

| 指标 | 优化前观测 |
| --- | ---: |
| 空闲基础请求量 | 约 38 请求/分钟 |
| 单场面试请求量 | 约 175 请求/分钟 |
| 4 分 25 秒内四个刷新接口调用 | 456 次 |
| 控制面接口 P95 | 约 1.136–1.451 秒 |
| 后端 CPU | 常见约 14%–34%，峰值约 46.95% |
| HTTP 5xx | 观测窗口内 0 |

上述请求量主要由网页端一秒一次、每次四个接口的回退刷新放大。它与 ASR 音频传输链路是不同层次的问题。

## 实现结果

- 新增授权聚合快照 `/api/v1/realtime-speech/sessions/{session_id}/snapshot`，一次返回运行态、转写、候选问题、增量事件和连续游标。
- 保留旧的独立接口，兼容已上线客户端和现有调用方。
- SSE 只有收到首个权威快照后才进入健康状态；健康期间为零定时刷新。
- 断线时同一时刻最多一个恢复请求和一个重连计时器；恢复后立即取消全部回退计时器。
- 会话结束、页面失活、导航和组件卸载时清理连接与计时器。
- 同浏览器重复标签页通过领导者租约复用一个 SSE；独立浏览器和独立设备互不限制。
- 管理监控继续保留总 API P95，并额外区分控制 API、恢复快照和 SSE 握手，便于判断慢点来源。
- 新增的前端交付指标只记录连接、首快照、连接时长、重连、回退次数和耗时，不包含转写、问题、答案或截图内容。

## 合成恢复基准

测试使用脱敏、进程内合成会话，比较旧的四接口恢复和新的聚合快照。该数据适合比较请求放大和代码路径开销，不能替代生产网络、数据库和真实面试的 P95/P99。

| 并发恢复会话 | 旧请求数 | 新请求数 | 请求降幅 | 旧墙钟耗时 | 新墙钟耗时 | 旧 P95 | 新 P95 | 错误 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 4 | 1 | 75% | 6.26 ms | 1.86 ms | 5.93 ms | 1.79 ms | 0 |
| 5 | 20 | 5 | 75% | 23.59 ms | 7.98 ms | 19.64 ms | 7.55 ms | 0 |
| 10 | 40 | 10 | 75% | 52.99 ms | 15.39 ms | 27.80 ms | 14.89 ms | 0 |

健康连接期间旧方案理论上每场每分钟最多产生约 240 个刷新请求；新方案为 0 个定时刷新请求，只保留真实事件流、必要控制请求和断线恢复请求。实际上线降幅取决于用户操作、连接稳定性和监控采样窗口。

## 兼容性与影响范围

- 不需要重新编译或重新下载桌面助手。
- 不改变 Bundle ID、桌面版本、系统权限或本地音频捕获。
- 不改变 ASR 供应商、音频分片、转写内容、答案模型和 Prompt。
- 不改变支付、积分、会员、资料库和管理端业务行为。
- 后端旧实时接口继续可用，便于独立回滚 Web 或 Backend。

## 发布与回滚

发布顺序：先构建并更新 Backend，等待容器健康且公开 `/healthz`、计费状态接口通过；再构建并更新 Web，检查生产构建清单、公开首页和 `/api/v1/web/state`。数据库、Redis、Desktop 和 Admin 不随本轮发布重建。

回滚时保留发布前 Backend 与 Web 镜像和 Git 提交。由于没有数据库迁移，可独立恢复旧 Web、旧 Backend，或两者一起恢复。

## 上线后观察

上线后的首个真实面试窗口重点观察：

- `controlApiP95Ms`、`recoverySnapshotP95Ms` 和 `sseHandshakeP95Ms`；
- 每场面试的请求/分钟、SSE 重连次数和回退快照次数；
- Backend CPU P50/P95、HTTP 5xx 和数据库连接等待；
- 30 分钟连续面试中是否保持实时转写、快答、截图回答和结束面试功能正常。

只有生产观察窗口完成后，才应把新的线上 P95/P99 和 CPU 降幅作为商业 SLA 数据。
