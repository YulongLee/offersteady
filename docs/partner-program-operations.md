# 合作伙伴计划运营与结算

状态：开发完成，生产默认关闭

## 固定商业口径

- 一级推广，不存在下线或多级分佣。
- 访客点击合作伙伴链接后 30 天内注册，注册后 90 天内的合格支付订单参与计佣。
- 首版费率为净实收的 20%，金额统一使用整数分；费率和规则版本随每条账本快照保存。
- 支付佣金先进入 7 天观察期，观察期结束且未退款/拒付才成为可提现。
- 最低可提现 100 元，每个 `Asia/Shanghai` 自然月最多提交一次，默认申请全部可提现余额。
- 合作伙伴现金佣金和邀请积分不能叠加；同一新用户只归属一种奖励计划。

## 月末人工结算 SOP

1. 运行有界佣金投影，核对新增条目数、冲突数和最后更新时间。
2. 对照支付渠道检查申请范围内是否存在退款、拒付或异常自购。
3. 若存在退款，使用渠道退款单号作为唯一 `refund_reference` 录入冲正；相同凭证重试不会重复扣减。
4. 运营/财务审核申请并填写原因；批准后通过既有客服渠道联系用户，不在产品中收集银行卡、身份证或收款码。
5. 打款后填写不含敏感信息的支付参考号并标记已结算。
6. 按运营主体的财税要求保存付款和代扣代缴凭证；页面金额为税前佣金，不承诺税后到账额。

## 监控与异常处理

- 推广采集、身份认领或佣金投影失败只影响报表新鲜度，不得影响登录、面试、ASR、回答、截图、下单或支付。
- `rewardConflicts` 增长表示用户已经选择邀请积分，属于防止双重奖励的正常拦截，需要结合活动口径观察。
- 结算余额来自追加式账本，不允许直接修改累计数；退款使用 reversal，驳回申请使用 payout release。
- 已结算后发生退款或拒付时，冲正会形成可见的负数结转并从后续佣金抵扣，页面不得把该金额伪装为 0。
- 普通合作伙伴接口只返回聚合人数和金额，不返回被推广人的手机号、用户 ID 或行为明细。

## 上线与回滚

1. 先部署迁移和应用，保持 `OFFERSTEADY_PARTNER_PROGRAM_ENABLED=false`。
2. 验证首页入口、关闭态、管理权限和既有面试/支付回归。
3. 确认合作协议、税务和人工结算负责人后再开启开关，并用内部合成链路验证一笔完整闭环。
4. 出现异常时先关闭开关；该操作停止新加入和投影，不影响核心产品。新增账本与审计表保留，禁止破坏性回滚。
