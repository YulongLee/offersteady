# 商业化面试链路性能优化记录（2026-08-21）

## 本轮目标

在不改变“用户主动点击快答或截屏回答才生成答案”、计费规则、Prompt、资料选择和旧版桌面助手协议的前提下，缩短实时收音、快答详细回答、截屏首屏答案和跨进程状态同步的等待时间。

## 已完成优化

### 实时收音

- 非最终音频帧只负责向持久 ASR 会话追加音频，不再同步等待一次提供方 partial 回包。
- 最终帧仍执行 commit，并等待权威 completed 结果；超时、重试和迟到 partial 隔离保持不变。
- 回滚开关：`OFFERSTEADY_REALTIME_ASR_NONBLOCKING_PARTIALS_ENABLED=false`。

配置中的 partial 等待预算原为 30ms，因此本轮消除了每个非最终帧最多约 30ms 的串行等待。合成 WebSocket v2 基准 5 个样本的接收确认 P95 为 1.26ms，队列深度为 0，丢弃 partial 数为 0。该结果只代表本机内部链路；真实识别耗时仍受音频设备、网络和模型服务影响。

### 实时事件通道

- 网页会话 SSE 与桌面截屏任务 SSE 从固定 100ms 轮询改为 Redis `XREAD BLOCK` / 内存条件变量唤醒。
- 继续保留游标恢复、15 秒 keepalive、页面租约校验和旧版桌面 HTTP 兼容入口。
- 空闲时不再每秒执行约 10 次读取循环；新事件可在写入后立即唤醒连接。

### 快答与详细回答

- 在简单回答仍在流式生成时并行预取详细回答所需的知识检索。
- 只有规范化问题确定后才启动预取，检索异常仍走既有降级逻辑。
- 合成并发测试中，40ms 检索完全被 80ms 简答生成阶段覆盖，详细回答不再额外串行等待该段检索时间。
- 回滚开关：`OFFERSTEADY_CHAT_DETAIL_RETRIEVAL_PREFETCH_ENABLED=false`。

### 截屏回答

- 保持图片内联传给视觉模型，不写入 OSS；截图字节在任务完成或失败后释放。
- 视觉模型启用 SSE 流式输出，第一段非空文本立即保存并通过现有会话事件推送，后续按 120ms 节流，最终答案完整落为终态。
- 若提供方在任何文本返回前不支持流式协议，自动回退到原完整响应调用。
- 网页使用现有单调状态归并显示部分答案，不改变按钮文字、取消行为、截图题顺序和“只依据截图”的证据边界。
- 新增 `firstTextMs`、模型耗时和后台总耗时等无内容遥测字段。
- 回滚开关：`OFFERSTEADY_SCREENSHOT_VISION_STREAMING_ENABLED=false`。

此前线上内联截图模型完整返回的合成探针约为 5.98 秒。本轮不会显著缩短模型生成完全部答案的时间，但会把用户首次看到答案的时点从“完整响应结束”提前到“模型首个有效文本”。真实提升需在部署后的实际供应商流式响应中复测。

### 任务连续性

- Chat 回答任务、截屏任务、截屏请求和安全上传元数据在生产环境改用 Redis 短期保存。
- 默认 TTL 为 2 小时；服务重启后仍能读取任务，过期活跃任务会安全转为可重试失败状态。
- 终态优先且拒绝旧 revision 回写；Redis 中不保存截图或音频字节。

## 验证口径

- ASR：非阻塞 partial、延迟回包、最终结果、迟到 partial 隔离。
- 事件：发布后唤醒、无事件有界超时、游标恢复。
- 快答：检索与简答重叠、完整 quick/detail 输出、既有取消和计费回归。
- 截屏：部分答案先于终态、完整答案、流式不支持回退、内联图片不落 OSS、临时字节释放。
- Redis：进程重建可见性、终态优先、陈旧任务恢复、无媒体字节。
- 网页：部分截屏答案归并、最终答案替换、按钮和操作状态回归。

## 上线后验收

以下项目必须在真实桌面设备和生产模型上继续观察，不能由合成测试替代：

1. 麦克风与系统音频各进行至少 10 分钟连续面试，确认没有句尾丢失或长期“转写中”。
2. 使用普通题、代码题和高分辨率题各执行至少 5 次截屏，记录 `firstTextMs`、`visionModelMs` 和完整耗时。
3. 在答案生成中重启一个后端容器，确认网页能够读取 Redis 中的任务状态并给出可恢复结果。
4. 观察 Redis 内存、SSE 连接数、后端错误率和支付/积分链路，发现异常时按上述开关逐项回滚。
