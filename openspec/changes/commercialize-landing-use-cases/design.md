## Context

首页现有六张岗位卡片来自静态产品能力说明，但旧页面使用“典型使用反馈”和“非真实用户评价”同时描述它们。商业化首页不应把功能场景伪装成评价，也不应向访客暴露原型阶段的真实性免责声明。

## Goals / Non-Goals

**Goals:**

- 将六张卡片明确定位为岗位使用场景和产品工作流。
- 保留岗位代入感，同时避免任何虚构社会证明。
- 保持现有深色首页、两列卡片和移动端单列布局。

**Non-Goals:**

- 不把静态场景改写成真实用户证言。
- 不新增姓名、头像、星级、雇主或录用结果。
- 不新增用户案例采集、审核或后台管理功能。

## Decisions

### 使用“岗位场景”而不是“用户反馈”

区块标题、英文眉题和说明统一描述适用岗位、面试环节与使用方式。卡片继续采用岗位、困扰、操作和能力标签结构，但不再出现“反馈”“评价”或“情景示例”。替代方案是直接删除免责声明并继续称为反馈，这仍会把合成内容伪装成证言，因此不采用。

### 保留能力边界，不添加结果型营销话术

所有卡片继续只描述已经上线的简历与 JD、知识库、实时回答、截图回答和复盘能力。页面不承诺 Offer、通过率或具体效果，真实用户案例需在取得授权和可核验素材后另建能力。

### 只修改公开首页静态标记

本次不新增数据流或服务端配置。对应回归测试检查商业化标题、六卡结构、能力标签，以及不再出现原型免责声明和评价暗示。

## Risks / Trade-offs

- [移除免责声明后卡片仍可能被误认作证言] → 标题明确使用“岗位与面试场景”，卡片不出现人名、头像、评分、公司或第一人称评价。
- [营销力度不如真实案例] → 先准确展示使用价值，后续以真实授权素材建设独立案例区。
- [旧测试继续要求情景标识] → 同步更新语义回归测试并运行完整 Web 测试。

## Migration Plan

1. 更新首页场景区文案和卡片标记。
2. 更新回归测试并完成生产构建。
3. 仅发布 Web；回滚时恢复上一前端版本即可。

## Open Questions

无。真实用户案例不属于本次范围。
