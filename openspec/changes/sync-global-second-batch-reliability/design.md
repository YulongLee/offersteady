## Context

国际服 Backend/Web 运行第一批 `20260929-global-reliability-1`，Admin 为独立旧镜像，资料 Worker 仍为旧构建。主工作区包含国服/模拟面试未提交改动，不可整包发布。用户已批准本轮三项改进及上线。

## Goals / Non-Goals

**Goals:** 资料处理重试不被错误终结；资料页面等待可取消且有界；回答断开后收敛取消与预留；后台分页、时间和写操作保护。

**Non-Goals:** 联网、模拟面试、模型/Prompt、套餐/价格、音频、助手版本、其他地区部署、历史数据修复、磁盘清理。

## Decisions

1. 复制已核验的国际服第一批源码，并单独提取 Admin 基线、核对运行构建。仅给 Backend/Worker 覆盖各自所需文件，不把新 Backend 整包用作旧 Worker。替代整仓构建会混入未批准能力。
2. 复用现有解析和重试规则，Worker 遇到已重新排队的任务不得再次终结 durable job。Web 采用约 90 秒有界轮询、终态停止、每文档单个请求循环、卸载取消。超时说明仍在处理，保留已有资料重试按钮。不引入新的 SSE 或外部解析器。
3. 回答流记录最后任务和终态，在 producer 关闭时关闭底层迭代器并幂等取消未完成任务；正常完成不撤销。保持既有模型超时，不能承诺同步供应商 I/O 可瞬间打断。Repository 固化取消状态，保留简单内容；不改变 Global 权益规则。
4. GlobalMembersPanel 拆成独立组件，复用现有 limit/offset 搜索和会员 API。30 条一页，下一页按有界结果判断；翻页保留关键词。列表和详情显示明确 UTC 注册时间，合法毫秒值才格式化，缺失为“—”。固定 UTC 而非隐式本机时区，避免跨地区歧义。
5. 搜索/详情请求用序号拒绝旧响应；换用户清除旧详情和原因；确认框包含邮箱、用户 ID、套餐或权益。写操作同步 single-flight，失败重试按相同操作内容复用同一 idempotency key；成功但刷新失败只提示刷新，不重新写入。全程保留原后端鉴权和审计。
6. 不修饰旧基线测试失败；新回归应先在旧基线复现，独立记录全量套件遗留项。真实用户不进入测试，生产只核对聚合数量、健康和哈希。

## Risks / Trade-offs

- [Worker 替换中断解析] → 部署前要求没有运行中的资料作业，保存旧镜像；不删除任务数据。
- [已结束流的迟到结果] → 取消终态保护并测试完成/失败写入竞态。
- [后台错误用户操作] → 请求序号、清空选择、明确身份确认、稳定幂等键和 single-flight。
- [国际服能力被覆盖] → 各组件父镜像最小叠加，配置哈希不变，验证认证/语言/Creem。
- [磁盘余量下降] → 小层镜像和压缩静态包，构建前核对余量；不足则停止，不擅自清理历史资源。

## Migration Plan

规格与基线 → 合成回归 → 三项实现 → Backend/Worker/Admin/Web 构建和检查 → 空闲门禁（面试、准备、页面、音频、回答、运行资料作业）→ 仅切换四组件 → 健康/哈希/权益/下载验证。失败回退保留的第一批 Backend/Web 和原 Admin/Worker；没有新字段/迁移，不回滚数据库。
