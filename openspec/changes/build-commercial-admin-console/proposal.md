## Why

OfferSteady 已具备用户、支付积分、资料处理、面试会话和桌面助手等商业化链路，但目前缺少统一、安全、可审计的运营后台，线上故障处理仍依赖数据库、日志或服务器操作。需要在不改变现有用户端原型与公开 API 行为的前提下，补齐最小可用的商业运营、客服和技术诊断能力。

## What Changes

- 新增与用户端隔离的商业管理后台，使用独立入口、独立管理会话和 `/api/v1/admin/*` API 命名空间。
- 新增显式管理员身份、最小权限 RBAC、MFA、会话撤销和高风险操作二次确认；普通用户账号或用户名 `admin` 均不自动获得管理权限。
- 新增不可篡改的管理审计事件，记录操作者、权限、目标、原因、结果和安全摘要，不记录简历、JD、知识库、音频、截图、密钥等敏感原文。
- 新增只读运营总览，覆盖脱敏用户、订单与支付状态、积分和时长账本、资料/RAG 任务、面试会话、AI 用量与延迟、实时链路状态和桌面助手版本。
- 新增受控运营动作：封禁或恢复账号并撤销会话、通过追加账本调整积分或时长、重试支付对账、重试失败资料任务、结束异常活跃面试；所有动作要求权限、原因、幂等键和审计记录。
- 新增生产隔离开关。后台默认关闭，可独立部署到管理域名；关闭或回滚后台时，现有网站、用户 API、面试链路和桌面助手保持不变。
- 首版不提供直接修改数据库、直接编辑 OSS、任意标记订单已支付、查看用户敏感内容、自动退款或批量营销能力。

## Capabilities

### New Capabilities

- `commercial-admin-access-control`: 独立管理员身份、MFA、RBAC、会话管理、默认关闭和管理入口隔离。
- `commercial-admin-audit`: 对所有管理访问与变更建立脱敏、可追踪、追加式审计记录。
- `commercial-admin-operations`: 提供用户、账务、支付、资料任务和面试会话的只读查询及受控运营动作。
- `commercial-admin-observability`: 汇总系统健康、业务任务、AI/RAG、实时语音和桌面版本的脱敏运行指标。
- `commercial-admin-deployment`: 规定后台独立构建、路由、环境开关、渐进启用和无影响回滚行为。

### Modified Capabilities

无。现有用户端、公开 API、支付、积分、资料、面试和桌面助手的对外行为保持不变。

## Impact

- 新增独立后台前端应用及其构建产物，不修改当前用户端页面结构和视觉原型。
- 后端新增管理 API、授权依赖、管理服务和只读聚合查询；现有 `/api/v1/*` 用户接口契约不变。
- PostgreSQL 使用增量迁移新增管理员授权、管理会话和审计事件等表；现有用户、账本、订单和任务表仍为权威数据源。
- 部署层新增管理域名或独立路由、管理 CORS、MFA 与功能开关配置；默认配置不暴露管理后台。
- 不新增客户端密钥，不把用户敏感原文写入审计、指标或测试夹具。
