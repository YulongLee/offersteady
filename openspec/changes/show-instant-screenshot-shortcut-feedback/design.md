## Context

当前桌面快捷键通过设备鉴权接口创建 remote capture request，网页端每 1.5 秒查询一次本场快捷键请求。创建本身很快，但查询边界带来最多一个轮询周期的可见延迟。实时面试页已经订阅 Realtime Speech SSE，并通过同一 session 的事件游标在有新事件时刷新。

## Goals / Non-Goals

**Goals:**

- 在服务端确认创建请求后，以现有 SSE 的刷新周期把请求 ID 和受理状态送到网页。
- 立即显示与按钮截图相同的等待弹窗，并用请求 ID 去重和支持取消。
- 保留低频查询作为断线、刷新和跨设备恢复机制。

**Non-Goals:**

- 不在网页失焦时监听 DOM 快捷键。
- 不创建第二条截图、计费或模型链路。
- 不提高截图历史查询频率，不新增 WebSocket 或消息中间件。

## Decisions

### 复用实时面试 SSE 的事件游标

快捷键截图入口在成功保存 remote capture request 后记录 `screenshot-shortcut-accepted` 实时事件，payload 仅包含请求 ID 和状态。Realtime SSE 已通过 repository event version 唤醒，网页可在约一个事件刷新周期内获得受理信息。

替代方案是把 1.5 秒轮询改为 100–200ms；这会持续增加数据库读负载，并可能重新引入空闲轮询问题，因此不采用。新增独立截图 SSE 也能解决，但会重复连接、鉴权和重连逻辑，超过本轮范围。

### 实时事件只负责受理，低频查询负责权威进度与恢复

网页将实时事件映射为 `waiting-desktop` 截图任务，并记录请求 ID。现有低频查询随后以相同请求 ID 更新 uploading、generating、completed 或 failed 状态。页面刷新或 SSE 临时中断时仍可从查询结果恢复。

### 服务端成功后才发布反馈

事件在设备、live binding、互斥检查和请求持久化全部成功后发布。被拒绝的快捷键不发布事件，避免网页显示虚假的等待弹窗。

## Risks / Trade-offs

- [SSE 连接暂时不可用] → 保留可见 live 页面上的 1.5 秒低频恢复查询。
- [事件列表包含旧的受理事件] → 网页按请求 ID 与终态集合去重，且权威查询结果可覆盖旧状态。
- [受理事件已到但进度查询失败] → 弹窗保持可取消的等待状态，下次低频查询继续恢复。

## Migration Plan

1. 先部署能发布新事件的后端；旧网页会忽略未知事件。
2. 再部署识别新事件的网页；若后端未升级，仍使用原有低频查询。
3. 回滚任一端只退化为原有轮询延迟，不影响截图任务和计费。
