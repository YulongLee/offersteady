## Why

桌面助手全局快捷键创建截图任务后，网页最长要等待下一次 1.5 秒轮询才显示反馈，用户容易误判为没有触发并重复按键。快捷键受理状态应通过现有实时通道立即到达当前面试页，同时保留低频查询作为断线恢复能力。

## What Changes

- 服务端在成功创建快捷键截图请求后，向当前面试的既有实时事件流发布带请求 ID 的受理事件。
- 网页收到受理事件后立即显示与点击“截屏回答”一致的等待弹窗，并以请求 ID 合并后续进度与结果。
- 继续使用低频截图请求查询作为 SSE 断线恢复，不提高数据库轮询频率。
- 快捷键被拒绝、重复触发或设备未绑定时不显示虚假的处理中弹窗。

## Capabilities

### New Capabilities

- `instant-screenshot-shortcut-feedback`: 定义快捷键请求的实时受理通知、统一进度反馈、任务去重与断线恢复行为。

### Modified Capabilities

无。

## Impact

- 后端 Realtime Speech 事件类型与桌面快捷键截图入口。
- Web 实时订阅映射、截图任务协调逻辑及回归测试。
- 不新增数据库表、第三方依赖或截图内容持久化；不修改桌面助手安装包逻辑。
