## Context

当前截屏回答由网页创建 remote capture request，桌面助手轮询、截屏并上传，后端完成视觉回答后网页展示结果。用户在会议或在线笔试窗口中必须切回网页点击按钮，影响实战节奏。Electron 支持主进程全局快捷键，但直接在本地截屏会绕开 session、设备授权、计费与网页答案状态，因此必须继续通过现有后端任务边界。

## Goals / Non-Goals

**Goals:**

- 在助手屏幕捕捉区域提供可配置、可持久化的全局快捷键。
- 只允许当前设备的有效 live session 触发一次用户主动截屏。
- 复用现有整屏捕获、OSS、视觉回答、计费和错误处理。
- 将快捷键生成的答案同步到当前网页实时面试。
- 快捷键冲突、重复触发和无 live session 时给出明确反馈。

**Non-Goals:**

- 不提供后台定时截屏、自动截屏或绕过 macOS 权限。
- 不改变截图裁剪、模型、Prompt、RAG 或图片压缩策略。
- 不允许自定义任意字符串组合，首版只提供经过筛选的快捷键预设。
- 不改变网页已有“截屏回答”按钮行为。

## Decisions

### Electron 主进程注册全局快捷键

使用 `globalShortcut` 在主进程注册，确保网页失焦时仍可触发。Renderer 只负责选择设置，通过 preload IPC 调用主进程；不在网页或 renderer 中注册 DOM 键盘事件。

替代方案是在网页监听 `keydown`；网页失焦后无法工作，因此不采用。

### 使用白名单预设并保留旧配置

首版提供 `CommandOrControl+Shift+Space`、`CommandOrControl+Option+S`、`CommandOrControl+Shift+S` 和关闭选项。切换时若新组合被占用，重新注册旧组合并返回错误，避免设置页面显示成功但实际不可用。

### 设备凭据作为快捷键请求授权

快捷键调用新的 device-scoped Screenshot Answer API，携带固定 `deviceId + manualCode`。后端通过 Realtime Speech 的 active capture binding 校验设备、用户、session 和 live 状态，客户端不能指定任意用户或 session。

替代方案是复用用户鉴权接口并在助手保存用户 Token；这会扩大敏感凭据边界，不采用。

### 网页轻量同步已完成快捷键任务

实时面试页仅在可见且处于当前 session 时，以低频方式读取截图历史并合并带快捷键来源标记的已完成任务。任务 ID 去重，不干扰网页自己发起的截图 placeholder、取消和重试状态。

替代方案是为截图任务新增独立 SSE；会增加跨服务事件基础设施，超过本轮最小范围。

## Risks / Trade-offs

- [快捷键与其他应用冲突] → 只提供预设，注册失败时回滚旧组合并提示用户选择其他项。
- [用户连续按键产生重复计费] → 主进程触发互斥并设置短时冷却；后端同一设备存在处理中请求时拒绝重复创建。
- [网页同步增加请求] → 只在 live 页面可见时低频读取，离开页面立即清理定时器。
- [助手未连接时误截敏感屏幕] → 先验证 live binding，再创建请求和截屏；校验失败不调用 capture API。
- [本地偏好损坏] → 回退默认快捷键，不影响机器码、权限或其他助手配置。

## Migration Plan

1. 部署兼容的设备快捷键截图 API 与网页历史同步。
2. 构建包含快捷键设置和全局注册能力的新助手。
3. 旧助手继续使用网页按钮，不受新接口影响。
4. 回滚助手时只失去快捷键入口，已有截图任务和网页按钮仍可使用。

## Open Questions

无。任意按键录制和多快捷键动作留待后续版本。
