## Context

生产首页由 `apps/web/index.html` 提供初始 HTML。百度搜索资源平台要求验证标记直接位于首页 `<head>` 中，并在后续抓取时持续存在。当前线上正在提供实时面试服务，因此变更必须限定为静态 Web 内容。

## Goals / Non-Goals

**Goals:**

- 让百度抓取首页时可以读取准确的站点验证标记。
- 通过自动化检查防止验证标记在后续构建中丢失。
- 独立构建和发布 Web，不重启 Backend。

**Non-Goals:**

- 不增加百度统计、跟踪脚本或其他第三方脚本。
- 不修改页面内容、路由、API、实时面试或桌面助手。

## Decisions

- 将标记直接写入 `apps/web/index.html` 的 `<head>`，因为百度要求验证首页原始 HTML；不通过 React 运行时动态注入。
- 使用静态 HTML 回归测试检查名称和值，避免仅依赖人工查看构建产物。
- 发布时只重建 Web 镜像并验证公网源代码。相比整栈部署，这能避免触碰当前后端会话。

## Risks / Trade-offs

- [验证标记被后续模板修改误删] → 使用回归测试固定名称和值。
- [Web 发布导致短暂静态资源切换] → 使用带内容哈希的构建产物并先完成本地生产构建。
- [错误扩大到实时服务] → 禁止修改或重启 Backend、Redis、PostgreSQL 和桌面程序。

## Migration Plan

1. 完成本地静态检查、测试与生产构建。
2. 仅更新 Web 静态镜像/容器。
3. 从公网读取首页源代码并确认标记唯一且准确。
4. 若 Web 探针失败，恢复上一 Web 镜像；Backend 保持不变。
