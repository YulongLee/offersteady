## Context

桌面助手存在三种进入整屏捕获的入口：renderer 的“预览”、网页创建的远程截图请求、Electron 全局快捷键。当前主进程只用 `inFlight` 和短时冷却保护请求执行阶段；成功上传后立即解除，因此用户可以在没有确认或取消上一份截图的情况下继续触发，造成多个视觉回答任务并行。renderer 也没有权威锁状态，单纯禁用按钮无法阻止全局快捷键。

## Goals / Non-Goals

**Goals:**

- 所有桌面截图入口共享一个由主进程持有的单实例锁。
- 成功捕获后持续锁定，只有用户点击“取消当前截屏”才释放。
- 锁定期间不创建新的快捷键任务、不重新捕获、不上传第二张图片。
- 捕获失败自动释放，应用重启也回到未锁定状态。
- renderer 明确显示锁定原因并禁用会改变截图来源或再次截图的控件。

**Non-Goals:**

- 不取消已经上传并进入视觉模型处理的后端任务。
- 不改变网页截图按钮、截图内容、压缩策略、模型或计费。
- 不保存截图锁到磁盘，也不持久化截图内容。

## Decisions

### 主进程是截屏锁唯一事实源

新增小型 `ScreenshotCaptureLock` 状态机，主进程在实际读取屏幕前原子获取锁。renderer 通过 IPC 查询、订阅和释放锁，不能自行宣称已经解锁。全局快捷键在创建后端请求前检查同一个锁。

替代方案是只使用 React state 禁用“预览”按钮；全局快捷键和网页远程请求仍可绕过，因此不采用。

### 成功保持、失败释放

成功获得有效截图时保持锁，等待用户显式取消。没有可用屏幕、权限失败或空缩略图时立即释放，避免一次失败导致助手永久不可用。锁状态只保存布尔值和安全提示，不保存图片。

### 取消只释放本地下一次截屏资格

“取消当前截屏”停止本地预览流、恢复所选屏幕的静态缩略图并释放主进程锁。若上一张图已经上传，取消不会撤销服务端视觉回答任务，避免引入跨服务取消竞态。

## Risks / Trade-offs

- [用户忘记取消后无法再次截图] → 按钮持续可见，预览按钮显示禁用状态，快捷键提示明确要求先取消。
- [renderer 重载导致锁仍在主进程] → renderer 启动时读取权威锁状态并继续显示取消入口。
- [捕获成功但 renderer 通知丢失] → 主进程保存状态；重新查询仍能恢复，快捷键也继续被拦截。
- [已上传任务无法被本地取消] → 文案使用“取消当前截屏/允许下一次”，不宣称撤销已提交回答。

## Migration Plan

1. 同一助手版本同时发布主进程 IPC、preload 和 renderer，避免接口错配。
2. 新版本启动时锁默认为释放，不迁移旧本地状态。
3. 回滚到旧助手只会恢复原有短时互斥，不影响后端截图任务兼容性。

## Open Questions

无。服务端任务取消属于独立需求，不包含在本轮本地互斥中。
