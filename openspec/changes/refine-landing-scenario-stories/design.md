## Context

首页已有六张两列场景卡，但卡片以功能解释为主，缺少用户提供参考图中“身份—场景—体验”的案例阅读节奏。现有规范同时要求这些内容不得冒充真实用户评价，因此本次需要在商业代入感与真实性边界之间保持清晰区分。

本次只调整公开首页 React 标记、CSS 和测试。继续复用当前深色设计变量、Phosphor 图标、公共页面宽度和 720px 响应式断点。

## Goals / Non-Goals

**Goals:**

- 让六张场景卡在视觉和信息层级上接近案例卡，便于访客快速代入自己的岗位。
- 使用岗位身份、面试阶段、典型困扰、情景叙述和能力标签构成完整故事。
- 在区块级和卡片级同时明确“情景示例，非真实用户评价”。
- 保持桌面两列、小屏单列、键盘阅读顺序和 320px 无横向溢出。

**Non-Goals:**

- 不伪造真实用户、头像、评分、雇主、Offer 或效果数字。
- 不引入用户评价后台、反馈提交接口或数据模型。
- 不修改首页其他区块、业务路由、后端或桌面助手。

## Decisions

### 用岗位徽记替代人物头像

每张卡片继续使用现有 Phosphor 岗位图标作为圆形徽记，避免生成或盗用人物头像。参考图的头像槽位仍通过图标、岗位名称和面试阶段保留相同视觉层级。

替代方案是使用 AI 生成人像，但即使注明合成，也更容易让访客误认为存在对应真实用户，因此不采用。

### 用案例叙述替代五星评价

卡片正文采用第一人称风格的“情景演绎”，描述遇到的问题、使用动作和可观察体验；顶部显著显示“情景示例”，底部显示实际使用能力标签。卡片不显示星级，避免形成未经证实的评分背书。

替代方案是完全复制参考图的姓名、公司和五星结构，但会构成虚假社会证明，因此不采用。

### 保留六卡两列结构并强化扫读层级

桌面保持两列三行，小屏切换单列。卡片增加身份标题、面试类型、副标签、重点句和能力标签，使用更充足的内边距和一致的最小高度；不改变当前深色品牌主题。

替代方案是缩减为三张卡片，但用户已经明确希望按参考图的六案例方式展示，因此保留六张。

### 用静态合成内容且不新增数据流

示例内容继续随前端构建发布，不读取用户数据或后台配置。真实性约束通过可见标识和回归测试保护。

## Risks / Trade-offs

- **案例式排版仍可能被误读为真实评价** → 区块标题旁和每张卡片都显示“情景示例”，区块说明明确“非真实用户评价”。
- **第一人称叙述增强代入感但接近证言语气** → 使用“如果遇到/可以”等情景措辞，不出现具体结果、企业或人物身份。
- **卡片信息增加导致移动端页面更长** → 正文控制在两至三句，标签数量限制为三项，小屏降低卡片内边距。
- **首页原有内容已经较长** → 只替换现有六卡区，不新增第二个重复的成功案例区。

## Migration Plan

1. 替换现有场景区标记和样式，并补充回归测试。
2. 本地运行测试、类型检查、生产构建和视觉 QA。
3. 提交并部署 Web 服务；若需要回滚，恢复单个前端提交并重新构建 Web 镜像。
