## Context

`PrototypeProvider` 当前在浏览器已有会话时仍启动公开状态加载，同时另一条 effect 执行会话恢复和受保护状态加载。较快失败的公开请求会先设置 `loadError`，导致错误页短暂出现。设置页的字号下拉框使用 `defaultValue` 且没有状态或持久化；CSS 又在回答区域写死多个字号和深色背景。

显示偏好不属于业务数据，也不含个人信息，适合保存在当前浏览器并在首次渲染前应用。实现需要兼容测试环境中缺少或损坏的 `localStorage`，同时保持默认深色外观不变。

## Goals / Non-Goals

**Goals:**

- 消除已有会话进入应用时由并发加载导致的错误页闪烁。
- 让回答字号在实时面试区域立即且一致地生效。
- 提供完整可读的高亮浅色主题，并避免刷新主题闪烁。
- 用独立、可单测的偏好模块完成读取、校验、应用和持久化。

**Non-Goals:**

- 不将显示偏好同步到账号或 Backend。
- 不改变公开首页的品牌视觉，不新增任意颜色选择器。
- 不修改回答内容、模型提示、支付、录音或桌面助手。

## Decisions

### 1. 由会话存在性决定唯一加载所有者

公开状态 effect 检测到已有会话时立即退出，只由恢复 effect 执行 `restore` 和随后一次受保护 `loadState`。恢复完成前继续显示中性加载页，只有恢复和状态加载最终失败且没有可用状态时才显示集成错误。

替代方案是保留并发请求并对错误增加延时。它仍存在竞态，只是掩盖闪屏，因此不采用。

### 2. 偏好存储为一个带版本边界的 JSON 对象

新增 `appearance-preferences.ts`，使用固定 localStorage key 保存 `{ answerFontSize, theme }`。读取时逐字段 allowlist 校验；存储不可用、JSON 损坏或值未知时回退为 `{ normal, dark }`。不把偏好加入服务端 `WebAppState`，避免无意义的 API 和数据库改造。

### 3. 用根元素 data 属性和 CSS 变量驱动外观

在 `document.documentElement` 设置 `data-theme` 和 `data-answer-font-size`。主题通过变量和必要的硬编码颜色覆盖实现；字号通过实时工作台作用域中的 CSS 自定义变量统一控制回答正文、结构化回答、列表、代码与公式。

替代方案是向 `AnswerWorkspace` 层层传 props。它会把纯展示偏好耦合进回答业务组件，也更容易漏掉 Markdown 子元素。

### 4. React 首次挂载前应用保存值

`main.tsx` 在 `createRoot().render` 前调用一次偏好应用函数，设置页再通过受控组件更新。这样刷新浅色主题不会先绘制深色页面。

### 5. 初始化使用无文案静默过渡层

会话恢复期间仍保留独立的 `status` 语义，供辅助技术判断页面尚未完成初始化；可视层只绘制与当前主题一致的背景，不显示技术性加载标题或说明。最终初始化失败仍进入已有错误页，避免静默掩盖真实故障。

## Risks / Trade-offs

- [浅色主题仍有历史硬编码深色颜色] → 为应用壳、实时工作台、输入框、卡片、浮层和正文补充集中覆盖，并以页面测试检查关键对比关系。
- [localStorage 在隐私模式下抛错] → 所有读写均捕获异常，界面仍使用内存中的安全默认值。
- [大字号导致小屏拥挤] → 只放大回答内容，不放大全部控制；使用相对变量和现有滚动容器避免撑破布局。
- [会话恢复失败时静默过渡持续过久] → 保留现有请求失败处理，只有正在恢复时不显示错误，最终失败仍明确提示或回到登录状态。

## Migration Plan

1. 先上线纯 Web 代码，不需要数据库或 Backend 变更。
2. 验证无会话、有效会话、过期会话三种首次加载路径。
3. 验证两种字号和两种主题在刷新后保持，非法存储回退正常。
4. 仅重建 Web；若需回滚，恢复上一 Web 镜像即可，已保存的偏好会被旧版本忽略。

## Open Questions

无。首版固定提供“深色”和“明亮”两种主题，以及“标准”“较大”两档回答字号。
