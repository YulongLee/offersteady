## Why

2026-10-16 下午国服综合 API P95 达到 1,106ms，高频 performance-ack、心跳和状态请求贡献了主要慢尾，实际回答启动也变慢。[只读诊断](../../../docs/diagnostics/cn-api-p95-20261016.md)确认通用鉴权仍重复建连、读取和写入 last-used，部分异步状态路由直接执行同步读取；现有证据尚不能将任何单条 SQL 或执行器认定为唯一根因。

## What Changes

- 在每次受保护请求内合并权威会话与用户可用性/限制状态读取，去掉授权结果不使用的完整用户/身份绑定加载；保留原有安全判定和绑定变更导致的会话撤销流程，不增加跨请求正鉴权缓存。
- 将登录会话最后使用时间限制为至多每 60 秒更新一次；更新仅触及元数据，不能复活或覆盖并发撤销、过期、改密或轮换后的状态。
- 为高频只需生命周期字段的状态读取提供轻量投影；完整会话读取中的资料校验仅在本次请求内去重，后续请求仍读取权威状态。
- 将选定异步状态路由内的同步服务读取移出事件循环，保持响应字段、错误、归属、权益和资料新鲜度合同。
- 使用合成数据进行安全竞争、查询/建连/写入计数、事件循环响应、API 合同和区域兼容自测；记录实际国服运行镜像基线及本地最小候选保护检查。

用户已明确授权本地优化开发和自测。**本轮不部署、不重启生产服务、不上传 Git；晚上上线由用户另行决定。** 非目标还包括客户端上报合并、模型/Prompt/收费/功能开关变化、指标口径调整、数据库迁移和新依赖。没有新增音频、转录、资料正文或用户数据保存行为。

## Capabilities

### New Capabilities

- `authoritative-efficient-authentication`: 在保持逐请求即时鉴权的前提下合并读取，限频且竞争安全地维护最后使用元数据。
- `fresh-lightweight-state-reads`: 轻量权威状态投影、请求内资料读取去重，以及异步状态路由的同步 IO 隔离。
- `local-auth-state-verification`: 使用合成安全/并发/区域回归与实际镜像基线候选检查验证改动，并限定本轮仅本地交付。
- `cn-auth-state-protected-release`: 仅适用于 2026-10-17 新授权阶段；核对实际运行基线后，将已验收八文件最小候选安全发布到 CN Backend，保护既有功能、配置与非目标组件，并提供受控回滚。

### Modified Capabilities

无。`openspec/specs/` 已有入口、恢复和资料权限合同保持不变；本轮新增可验证的内部效率与安全保证，不修改这些用户行为要求。

## Impact

- Backend 通用鉴权服务及内存/PostgreSQL 仓库、依赖注入与其测试；高频 telemetry/control/state 受保护请求间接受益。
- Backend 会话/网页状态服务、仓库投影与异步路由及其测试；公开路由、请求/响应模型和状态码保持一致。
- CN 为本轮性能目标；共享实现必须兼容 Global 用户与密码/会话生命周期，保留 Global 独立权益。既有问题预取、轻量心跳、ACK 缓存和实时资源清理不得回退。
- OpenSpec、合成本地验证及发布前基线记录；不修改运行配置、线上数据库或其他组件。
