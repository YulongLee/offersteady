## Context

生产证据显示 Electron 到 Backend、持久 Qwen Realtime ASR、Redis XADD/XREAD 和 Backend SSE yield 均持续推进；延迟集中在页面首次订阅和浏览器消费。当前 Web 使用 `BroadcastChannel` 选举单个标签页领导者，但领导权不感知 `document.visibilityState`。后台旧标签页可继续持有 SSE 并向新页中继，受到后台调度限制时形成 5–24 秒长尾。与此同时，`fetch()` 收到 SSE 响应头后可永久等待首个权威快照，现有 0/2/4/8/15 秒重试只有在流结束或抛错后才生效。

修复必须保持每个浏览器同一面试最多一个健康 SSE、音频发布与网页生命周期解耦、游标单调归并、健康流零轮询以及内容无关的诊断边界。

## Goals / Non-Goals

**Goals:**

- 可见面试页在有资格订阅时快速成为领导者，后台页不得阻塞可见页。
- SSE 在限定时间内没有首个权威快照时明确失败并进入一次聚合快照恢复。
- 恢复成功后立即重建 SSE；持续失败时仍使用有界退避，避免请求风暴。
- 用确定性测试覆盖可见性切换、领导权交接、首快照超时、恢复和清理。

**Non-Goals:**

- 不修改桌面采集、WebSocket 音频协议、VAD、ASR 模型或字幕文本处理。
- 不恢复高频 runtime/transcripts/candidates/events 轮询。
- 不改变跨浏览器的服务端页面租约规则，也不新增数据库或 Redis 模型。

## Decisions

### 1. 领导者资格显式绑定页面可见性

`LiveSessionLeaderCoordinator` 增加资格状态。页面隐藏时立即释放领导权并停止领导者心跳；页面恢复可见时重新发起探测/选举。收到当前领导者的 `release` 后，合格跟随者立即接管，不等待五秒 watchdog。多个同时可见页面继续使用既有确定性 page ID 规则维持单领导者。

选择显式释放而不是让后台页继续中继，因为浏览器会对后台任务、网络读取和消息调度限速，无法提供实时 SLA。也不选择所有标签页各自连接，因为会放大 SSE、ACK 和状态竞争。

### 2. 首个权威快照使用独立的 2 秒期限

SSE 响应成功并不等于产品流健康。订阅适配器在解析到首个 `snapshot` 前启动 2 秒计时器；超时后取消 reader 并抛出可识别的网络错误。计时器在首快照、外部取消或流终止时始终清理。

2 秒明显高于正常局域/公网握手和 Backend 快照耗时，同时远低于用户感知到的 30 秒。相比仅依赖 fetch 超时，它能覆盖“响应头已返回但 body 没有首事件”的半开连接。

### 3. 首快照失败先恢复状态，再快速重建流

页面订阅失败后继续调用现有聚合 `snapshot` 恢复。恢复成功即应用权威状态、重置重连退避并立即重建 SSE；恢复失败才进入 2/4/8/15 秒有界退避。健康 SSE 建立后不运行定时快照。

选择复用聚合快照而不是四个旧接口，避免重现请求放大。选择“成功恢复后立即重连”而不是永远轮询，保证后续 partial 仍通过推送到达。

### 4. 页面可见性变化同时驱动订阅生命周期

领导页隐藏时取消当前 stream；重新可见并取得领导权后先刷新服务端页面租约，再订阅。音频 publisher 不受影响。卸载、替换、离线和既有终止 HTTP 状态仍沿用当前清理规则。

### 5. 验收以首次交付行为和请求约束为准

单元/组件测试使用合成事件和可控时钟验证：单页隐藏保持既有流、可见 follower 探测后立即接管、2 秒首快照超时、恢复成功后零延迟重连、健康态没有快照轮询、所有 timer/reader/AbortController 被清理。生产门禁检查 HTTP 5xx、SSE 连接、回退次数和首句话可见延迟，不记录字幕正文。

### 6. 单页隐藏不再主动销毁健康流

2026-08-28 的真实会话证明，页面短暂失焦/隐藏后的销毁与完整恢复会把已经写入 Redis 的 partial 延后数秒。协调器因此改为“保留现任、可见页优先”：没有其他可见页时，隐藏的当前 leader 保持既有流；收到可见 follower 的 probe 时立即 release，由 follower 接管。真正卸载、租约撤销和会话结束仍然关闭流。

### 7. 首屏水合合并为一次授权读取，诊断改为 best-effort

路由已经在建立流之前校验页面租约，首 snapshot 不再并行调用三个各自重复查询 Session 的公开 service 方法，而由一个专用 bootstrap 方法在一次授权检查后读取 transcripts、candidates 和最新状态事件。首 snapshot 发出后才异步补 runtime；runtime 计算失败只记录无内容告警，不能结束 SSE。重连带有效 cursor 时继续使用 Redis 的有界游标索引，只读取缺失事件。

### 8. SSE 使用独立代理配置

实时字幕路径从通用 `/api/` location 中分离，显式清空 `Connection`，关闭 buffering/cache/gzip，并保留 3600 秒读写超时。WebSocket 音频路径继续使用原有 upgrade 配置，二者互不影响。

## Risks / Trade-offs

- [隐藏页面长期持有流] → 只有当前 leader 保留一条连接；可见 follower probe 会立即接管，卸载和服务端租约仍负责最终清理。
- [2 秒在极慢网络上可能误判] → 首次超时只触发一次聚合恢复；持续失败仍有退避，不形成循环风暴。
- [两个可见窗口同时竞争] → 保留确定性 page ID 选举和服务端页面租约作为双重约束。
- [旧 Web 与新 Backend 混合发布] → 不改变 API；Web 可独立回滚到发布前镜像。

## Migration Plan

1. 先完成 Web/Backend 回归、Web 类型检查和生产构建；先发布只扩展指标枚举的 Backend，再发布 Web。
2. 上线后验证首页、Web state、登录态接口和实时流未出现 4xx/5xx 风暴。
3. 使用真实前台面试页验证首句话 partial，并观察恢复指标和浏览器 ACK。
4. 若出现连接放大、状态回退或首快照误超时，立即恢复发布前 Web 镜像；Backend、Redis、Desktop 和数据库无需回滚。
