## ADDED Requirements

### Requirement: Actual Global baseline and regional behavior are preserved
The increment MUST derive from freshly verified actual Global Backend/Web images, complete source/static/schema inventories and effective configuration. Only approved screenshot and written UI deltas SHALL change. Global English, commerce, membership, mock and resume rules, authentication/performance/Prefetch/companion behavior, prompts, dependencies, database, private settings and all other components MUST remain unchanged. CN MUST NOT be published.

#### Scenario: Candidate is prepared
- **WHEN** the approved source and static overlays are built onto actual fixed Global images
- **THEN** full inventories, effective settings and all unrelated API schemas/inputs match the fresh baseline with only explicit compatible changes

### Requirement: Synthetic verification precedes protected publication
The candidate MUST pass relevant backend, English Web and actual compiled artifact checks, strict OpenSpec validation and an actual-image isolated synthetic probe. Tests MUST NOT use real personal data, create production interviews, alter production billing or pressure-test production. Any optional real provider QA MUST be one bounded synthetic call, separately recorded. Desktop physical-device validation MUST NOT be claimed from a synthetic probe.

#### Scenario: Candidate verification completes
- **WHEN** deployment is considered
- **THEN** exact candidate inputs bind passing no-side-effect capture/batch/usage/race and existing-feature tests before preflight

### Requirement: Active work and ownership protect cutover and recovery
Every cutover and recovery MUST verify immutable payload/images, complete original configuration and ownership, and repeat independent active-user/lease/audio/answer/screenshot/material/resume/financial and established-connection guards. Active work SHALL defer; unreadable or changed state SHALL stop. No user work may be terminated or protection relaxed. Recovery MUST restore only pinned owned old images without restoring user data or overriding later releases.

#### Scenario: Users are active or gates cannot be read
- **WHEN** any required gate is busy or unreadable
- **THEN** the existing service is preserved and switching is deferred or stopped for diagnosis

### Requirement: Independent verification and short aggregate observation close release
After cutover the operator MUST independently verify complete source/static/API/settings/configuration and other component identities, correct public route hashes, existing product entries and anonymous guards, and the multi-capture policy. At least 180 seconds of bounded ERROR/traceback/HTTP5xx aggregate observation SHALL be recorded without raw user logs or private configuration export. A completed release SHALL preserve exact receipts and source restoration material without an unsolicited Git action.

#### Scenario: Deployment is complete
- **WHEN** the new fixed images are live and independent checks and observation pass
- **THEN** the release is recorded with actual identities and evidence, and the user receives the Global test entry and remaining real-device validation boundary
