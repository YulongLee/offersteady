## Context

现有日级运营快照适合业务分析，但不适合判断实时容量。进行中面试的数据库状态、网页和设备心跳、音频帧、后端请求耗时以及容器资源分散在 PostgreSQL、Redis 和进程运行时中。

## Goals / Non-Goals

**Goals:**

- 使用统一时间轴展示当前实例的真实容量信号。
- 采样与用户请求解耦，任何监控故障不影响业务主链路。
- 只保存聚合值，并提供清晰的采集口径和可配置关注阈值。

**Non-Goals:**

- 不替代 Prometheus、Grafana 或云厂商主机监控。
- 不承诺仅凭单个并发数字得出绝对容量上限。
- 不保存用户、设备、会话、音频或请求正文。

## Decisions

### 1. 后端后台任务每 30 秒采样

FastAPI lifespan 启动独立异步任务，数据库和文件读取在线程中完成。任务失败只记录安全日志，不向用户请求传播异常。

### 2. Redis 保存短期聚合曲线

样本写入有序集合并保留 6 小时，管理端默认读取最近 60 分钟。Redis 不可用时退化为进程内有界队列，重启后短期曲线可以重新积累。

### 3. 真实业务口径优先于状态字段

进行中面试必须同时满足 `status = live`、未删除且最近 20 分钟有活动；在线网页、助手和音频流必须满足各自心跳或帧新鲜度。

### 4. 容器资源读取 cgroup

CPU 和内存按部署容器实际限额计算，而不是误用宿主机总资源。无法读取限额时指标标记为不可用。

### 5. 请求质量使用滚动窗口

中间件只在内存中保留最近 5 分钟的状态码和耗时，计算请求速率、P95 和 5xx 错误率；健康检查和容量接口自身不计入样本。

## Risks / Trade-offs

- 单实例进程内请求窗口不能跨多个后端实例合并；当前部署为单后端实例，扩容时应迁移到 Prometheus。
- 关注阈值是运营预警线，不等于压测确认的硬容量上限。
- 首次采样无法计算 CPU 增量，下一采样周期后恢复。

## Migration Plan

1. 部署后端容量采集和只读接口。
2. 确认 Redis 样本、数据库口径和容器资源均可读取。
3. 部署管理端容量区块。
4. 若需回滚，仅隐藏前端区块并停止采样；已有业务数据和用户功能不受影响。
