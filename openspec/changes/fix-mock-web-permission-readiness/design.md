## Context

状态：apply-ready。用户2026-10-30已授权开发此前讨论的网页/后端修复，仅限模拟面试，不改助手，不部署。基线及证据见 [proposal](proposal.md)。

正式1.3.5设备初始登记unknown，授权结果可能等下个15秒登记才更新。Mac超时错误上报denied无法由网页独立验证真实OS状态。本次不虚构权限、不主动启动采集来绕过检查。

## Goals / Non-Goals

目标：让未知状态成为可等待、可原地恢复的状态；每次准备更新和开始仍读权威设备；播放受限时说明是网页声音并可点击恢复。

非目标：修改任何桌面源码/分发、OS权限、ASR/TTS/模型、计费/截止时间/报告、普通面试/笔试/资料/SEO/国际服、通用性能优化；不新增服务器轮询或缓存，不更改数据库，无线上操作。

## Decisions

1. 国服专用 runtime 内，专用mock协议的缺失/unknown/无法识别值返回 `mock_microphone_checking`；仅 denied/restricted 返回现有 `mock_microphone_required`。继续阻止开始和音频attach，不修改设备记录。旧v2且无专用mock标志的历史deferred规则保留；不将其扩展到新助手。
2. 复用现有5秒控制heartbeat，publish和start继续读取最新权限。页面第一次等待显示“正在检查麦克风”，30秒后转为“尚未收到…可重新检查”指引，持续接收已有心跳恢复。30秒只是UI等待提示，不是权限失败、额外请求或开始门槛豁免。
3. “重新检查麦克风”只发送一次现有heartbeat，不创建/绑定/结束/开始面试。等待期间保留简历与绑定；成功、断开、换场次、卸载均清理本地计时/错误状态。重复点击有本地节流；准备状态恢复清除过时的权限错误，不清除其他错误。开始后也不自动续听或自动收费重试。
4. 浏览器播放独立于麦克风；需要点击时有明确播放提示和朗读恢复。播放器unlock确认实际running且有界等待，异步结果以连接、题目、phase及操作代际判定是否仍有效。自动/手动恢复不能重复speak；失败后按钮可重试，pause/skip/end/断线/卸载撤销旧操作。保持点击回调直接调用resume以保留浏览器用户手势。
5. 所有新增状态仅在MockInterviewPage及专用客户端中实现，不修改共享Auth/App/普通音频逻辑。测试只使用假WebSocket/AudioContext和合成资料。
6. 用户随后要求精简页面声明，继续不部署：准备区不再常驻两段助手/音频说明，改为开始按钮下方默认收起的“使用说明”；保留必要的短状态、恢复按钮与AI身份标识。等待超时和播放提示删去重复解释，本地测试面板/记录也默认收起。仅调整呈现，不修改任何权限、计费或控制逻辑。
7. 随后的本地复查发现三个实际边界缺陷：旧资料选择HTTP可回填另一场或已结束页面；结束命令未立即撤销1.5秒收音等待；全部音频已排队后系统挂起播放会使朗读重试被锁住。修复继续限定专用网页：异步操作按页面/连接代际及会话版本隔离；控制意图立即清理本地收音计时；播放器仅在当前上下文持有活动音频时通知播放中断，页面暂停当前提问并保留手动继续入口。关闭、空闲与旧上下文不能触发替代场次动作。

## Risks / Trade-offs

- 助手真的拒绝或错误上报denied → 页面据实提示当前上报状态，并指引已授权者重新检查/重开助手；不宣称本轮能修复OS/桌面采集。
- 设备始终unknown → 不无限spinner，不放行或自动重建，30秒后给可操作恢复入口。
- 声音resume回调晚到 → 代际与题目隔离，真实AudioContext状态校验；不因晚回调启动新题。
- 当前Web包含历史独立增量 → 本地构建仅作源码验证；未来发布须以实际运行静态图做最小增量，不能全量覆盖线上包。

## Migration Plan

本轮只本地验证并交付记录。后续部署需用户另行授权，重新核对目标组件实际镜像/完整清单与所有用户工作门禁；保持可回滚且不迁移/回写用户数据。

## Open Questions

无阻塞需求问题。真实Windows/Mac系统权限、物理麦克风与浏览器策略仍需用户设备验收，不将合成测试等同硬件验收。
