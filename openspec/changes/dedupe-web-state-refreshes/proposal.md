## Why

国服当前 API P95 的主要可疑路径是 Web 聚合状态接口。页面初始化、登录恢复、资料处理刷新和面试操作可能在同一时间重复请求 `/api/v1/web/state`，而该接口会同时读取账单、资料、会话和发布信息，重复请求会放大数据库与 Backend worker 的排队。需要先在 Web 端消除同一时刻的重复状态请求，并在短时间内复用同一份状态，降低请求量而不改变需要最新数据的业务操作。

## What Changes

- 为 Web 状态读取增加按认证模式隔离的并发请求去重；同一时间的重复调用共享一个请求结果。
- 为非强制刷新增加很短的成功结果复用窗口，避免页面初始化和相邻组件重复读取完整聚合状态。
- 保留显式业务操作后的强制刷新能力；上传、删除、重试、创建或结束面试、账单变化和登录切换不得继续使用过期状态。
- 增加前端回归测试，覆盖并发合并、认证模式隔离、短窗口复用、强制刷新和失败请求不污染缓存。
- 仅本地验证，不在本次变更中部署国服或修改后端接口契约。

## Capabilities

### New Capabilities

- `web-state-refresh-efficiency`: Web 聚合状态读取的并发去重、短窗口复用和强制刷新边界。

### Modified Capabilities

- 无

## Impact

- 影响 `apps/web/src/backend-adapter.ts` 及其前端测试和调用类型。
- 不改变 `/api/v1/web/state` 响应结构、鉴权方式、数据库、计费、面试会话或实时音频行为。
- 缓存只保存在当前页面 JavaScript 内存中，不写入 localStorage、服务端或用户资料；不缓存失败结果。
