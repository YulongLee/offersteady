## Why

实时面试目前只能由用户逐次点击“快答”，持续面试时容易错过操作时机。产品需要提供一个默认关闭、由用户明确启用的会话级自动回答模式，同时保留当前稳定的手动快答链路和性能基线。

## What Changes

- 在实时面试页顶部新增“自动回答”开关，默认关闭；关闭时维持现有手动快答行为。
- 用户开启后，只对当前启用时间之后、来自面试官系统声道且已被高置信度确认为完整问题的候选问题自动发起回答。
- 自动回答复用现有快答的语言、编程语言、资料检索、流式输出、计费、取消和错误处理链路，不新建模型或 Prompt 分支。
- 服务端持久化会话开关和开启时间，并对候选问题执行所有权校验、单题认领、幂等去重和单任务并发保护。
- 关闭开关仅阻止后续自动触发，不中断已经生成中的回答；会话结束、页面租约失效或面试官声道不可用时停止自动触发。
- 不修改桌面伴随程序、ASR 模型、音频分片、字幕合并、截图回答或现有手动快答入口。

## Capabilities

### New Capabilities

- `session-auto-answer-control`: 定义会话级自动回答开关、合格问题门禁、自动触发幂等性、现有回答链路复用及降级行为。

## Impact

- Web：实时面试页头部控件、会话状态适配、问题候选消费和自动触发编排。
- Backend：Interview Session 持久化/API、问题候选认领、Live Answer 自动触发校验和事件字段。
- Database：为会话增加默认关闭的自动回答状态和开启时间字段。
- AI：复用现有 Prompt 和模型；增加自动触发链路评测用例，不改变回答内容策略。
- Privacy：不新增音频、转录或个人资料存储，不扩大日志中的问题正文范围。
