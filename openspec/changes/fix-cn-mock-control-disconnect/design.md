## Goals / Non-Goals

目标：预期断连不再形成二次未捕获异常；旧控制器退出不影响替代控制器，取消和真实清理错误仍可传播；所有既有功能保持。

非目标：更换助手/网页、增加重连策略或重试、改变心跳/截止/计费/模型/存储/线程池；不扩展到9秒控制或知识库慢请求；不部署国际服、不提交推送Git。

## Decisions

1. 在控制端点最终socket.close这一最窄边界捕获(RuntimeError, WebSocketDisconnect)。不使用except Exception/BaseException，不更改receive/send/attach/detach逻辑；真实detach失败与CancelledError必须可见。
2. 保留既有shield、pump取消等待、runtime.detach的对象身份判断和资源释放顺序。通过合成路由及真实runtime替代连接回归验证这些保护，不另增自动结束、重启或重连行为。
3. 从实际1724镜像只覆盖1个业务文件；新候选238输入/237原字节保持。新专用控制器复用已经审阅的冻结Compose、七个业务门禁、CN实体只读门禁、严格TCP0与单writer/归属证明；原1724为固定回退，不调用旧发布入口。独立实际镜像探针必须无网络、只读、禁真实DB/模型。
4. 发布/恢复均重复空闲和归属检查；发现用户工作则等待自然结束。漂移、unknown或读取失败停止，不终止工作、不放宽门禁。验证完整203Schema/344配置/44依赖、辅助格式、d7助手、366Web和七非目标。

## Risks / Trade-offs

- 只消除收尾异常，不能声称修复最初断线或所有长尾 → 交付明确边界。
- 宽泛捕获掩盖错误或吞取消 → 仅两种异常、仅close处处理，补充反例测试。
- 与旧补丁混包 → 对照新鲜实际运行清单，仅复制单文件并锁定完整候选及回退镜像。
- 切换可能有短暂启动空档 → 空闲门禁和固定回退，分别记录启动窗口与之后的实际5xx。
