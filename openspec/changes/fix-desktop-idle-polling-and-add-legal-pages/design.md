## Context

桌面主进程和 renderer 当前各自拥有一个 1.2 秒远程截图轮询器，renderer 还以 1 秒间隔查询绑定。远程截图 `next` 接口在查询待处理任务前调用会抛出 404 的 capture-binding 校验，因此正常的未绑定/空闲状态被记录为领域告警。线上已经出现请求风暴、数据库死锁和 500。公开站点只在首页提供简短隐私说明，Nginx 的 SPA allowlist 和 React 路由都没有 `/terms`、`/privacy`。

## Goals / Non-Goals

**Goals:**

- 每个桌面实例只保留一个远程截图轮询所有者。
- 未绑定或非 live 时不查询截图任务，并以低频、可恢复的方式探测绑定。
- 兼容旧客户端：旧客户端继续调用 `next` 时，正常空闲返回 200 + `data: null`，不产生告警。
- 降低同一设备并发读取绑定/截图表的概率，同时保持网页发起截图后可接受的响应速度。
- 提供无需登录、可刷新、可链接的用户协议与隐私政策页面。

**Non-Goals:**

- 本次不引入 WebSocket/SSE 推送桌面截图任务，也不改变截图上传和视觉回答协议。
- 不修改 Developer ID 签名、公证或 macOS TCC 权限实现。
- 不给出法律意见，不承诺系统当前没有执行的自动保留期限、导出或删除 SLA。
- 不修改账号、积分和支付的结算规则。

## Decisions

### 1. 主进程成为远程截图查询的唯一所有者

删除 renderer 中重复的截图任务轮询 effect，保留主进程捕获、上传和失败回报链路。主进程已经持有设备身份、屏幕捕获能力和上传逻辑，且窗口隐藏时仍能处理真实 live 面试请求。选择主进程而不是 renderer 可以避免窗口生命周期和 React effect 重建导致重复计时器。

替代方案是仅删除主进程轮询并由 renderer 处理；该方案在窗口销毁、重载或隐藏时更脆弱，也会把屏幕捕获协调继续分散在两个进程中，因此不采用。

### 2. 使用 pairing-status 门控和状态化递归定时器

renderer 通过返回 200 的 `pairing-status` 维护权威连接展示，并经现有 IPC 把 `capturing` 状态发布给主进程。主进程只有收到该 live 状态才查询 `capture-requests/next`，后端在接口内再次确认绑定；非 live 时主进程只保留本地定时器，不发起绑定或截图网络请求。live 状态采用约 1.2 秒间隔保证截图响应；renderer 已登记但未绑定/非 live 状态采用 10 秒探测；网络或服务错误采用 5、10、20、30 秒的有上限指数退避。每次请求完成后再安排下一次，禁止请求重叠。

renderer 的绑定状态展示仍需探测连接变化，但改用同样的非重叠递归计时器：live 约 5 秒、已登记等待约 10 秒、连续失败最多退避到 30 秒；页面可见性变化或绑定状态变化时重置到快速探测。它不再查询截图任务。

替代方案是立即引入长连接推送；长连接能进一步减少请求，但会扩大协议、部署和断线恢复范围，不适合本次紧急止血。

### 3. 后端把正常空闲建模为成功空结果

`GET .../capture-requests/next` 使用 pairing status 判断设备和绑定状态。未登记、未绑定、绑定过期、非 live 或没有待处理请求都返回标准成功 envelope 且 `data=null`。上传、认领、快捷键创建等会改变状态的接口继续执行严格 capture-binding 校验，身份不匹配和非法写操作仍返回 4xx。

这样旧客户端无需升级也会立即停止制造 404 告警，同时不会放宽截图上传授权。

### 4. 法律页面是公开只读路由并使用共同结构

在公开布局中增加 `/terms` 和 `/privacy`，使用可阅读的标题、更新时间、目录式章节和客服联系方式。登录页同意文案分别链接两页，首页页脚也提供入口。Nginx allowlist、SEO 回归脚本和路由测试同步更新，法律页面允许直接访问但设置 `noindex, follow`，避免短期草案被当作搜索落地页。

页面文字只描述当前可验证行为：手机号认证、用户资料、转录、截图、设备信息、支付订单、第三方模型/语音/存储处理、原始音频默认不保存、用户可通过现有入口管理/删除数据。正式商业发布前仍需法律专业审核。

## Risks / Trade-offs

- [Risk] 空闲探测从 1 秒放慢到 10 秒后，用户刚输入连接码时助手状态可能延迟数秒 → 在前台可见性恢复、手动操作和状态变化时立即探测；10 秒作为最坏普通等待。
- [Risk] 主进程与 renderer 对绑定状态各有用途，仍会存在两个低频 pairing-status 请求 → renderer 只负责 UI/音频状态，主进程只负责截图，二者不再重复查询截图表；后续可通过 IPC 共享单一绑定状态。
- [Risk] 把无效绑定返回空结果可能隐藏被盗机器码的探测 → 接口不返回绑定内容，写接口仍严格鉴权，并保留请求限流和设备登记审计。
- [Risk] 法律文本与真实实现演进不一致 → 将页面内容保持在独立组件/数据结构，变更数据行为时把法律页回归列为发布任务。

## Migration Plan

1. 先部署后端空闲成功响应，使现有已安装客户端立即停止产生 404 告警。
2. 部署 Web 法律路由与 Nginx allowlist，验证 `/terms`、`/privacy` 直接访问、刷新和登录页链接。
3. 发布新版桌面助手，观察 capture-binding 告警、请求量、数据库死锁和截图响应延迟。
4. 若桌面端出现截图遗漏，可只回滚桌面包；后端成功空结果和法律页面保持向后兼容。
