## Context

实时面试页的业务状态集中在 `LivePage`，桌面与手机当前渲染同一组组件，仅通过 CSS 在窄屏改成纵向排列。真实手机浏览器中，这会让对话、手动输入、回答操作和答案同时占用一个滚动容器，并与浏览器工具栏、安全区及固定会话栏竞争空间。桌面伴随程序的图标资源则直接进入 Electron 打包产物，旧资源带白底和细小文字，缩小后不清晰。

## Goals / Non-Goals

**Goals:**

- 让手机用户默认看到答案，并能在答案与实时对话间快速切换。
- 将提问、快答和截屏操作固定在手机底部安全区内，避免遮挡和重复状态。
- 保持同一个 `LivePage` 业务状态和请求函数，避免响应式切换造成任务重建。
- 让新图标在 macOS 与 Windows 正式安装包中生效并可从网页下载。

**Non-Goals:**

- 不改变桌面 Web 双栏布局、分栏比例或组件业务语义。
- 不改变 ASR、回答生成、截图识别、积分计费或后端 API。
- 不实现客户端自动更新或新的代码签名体系。

## Decisions

### 使用同一业务状态的条件渲染，而不是维护两套页面

`LivePage` 继续持有对话、答案、草稿、截图和请求控制器。桌面断点渲染现有双栏，手机断点渲染回答/对话页签及底部操作栏。选择这一方案是为了避免两套状态同步；仅靠 CSS 隐藏原有长页面无法解决 DOM 顺序、焦点和安全区问题。

### 手机端默认回答页签并在任务开始时回到回答

手机进入页面时默认显示回答；用户可切到对话查看完整转录。当快答、自动回答或截屏回答开始/到达时，界面切回回答页签。页签切换只改变可见区域，不修改答案 ID、历史位置或草稿。

### 复用现有提交函数，新增紧凑移动端操作组件

移动端操作栏只负责采集输入和触发 `submitManual` / `beginInstantScreenshot`，所有幂等、取消、积分和流式状态仍走现有链路。桌面继续使用 `ManualQuestionComposer` 与 `AnswerActionBar`。

### 低频危险操作放入更多菜单

手机顶部保留收音暂停/恢复；账户、积分与结束面试进入“更多”菜单，减少首屏宽度占用。结束操作沿用现有服务端结束逻辑，不新增会话状态。

### 图标以单一高分辨率透明资源派生

使用 1024px RGBA 源图供 Electron Builder 生成平台图标，并生成 256px 渲染资源。图形仅保留盾牌、麦克风和确认标记，移除小字号文字。相比继续使用白色画布，这在 Dock、任务栏和启动器中更清晰。

## Risks / Trade-offs

- [移动页签隐藏内容可能让新对话不易察觉] → 在对话页签显示转写中/新内容状态，生成回答时自动回到回答。
- [软键盘改变可视视口] → 操作栏使用 `100dvh`、`env(safe-area-inset-bottom)` 和内部滚动区域，不依赖固定像素高度。
- [Electron 图标缓存导致升级后短暂显示旧图] → 发布新版本号和新安装包；产物内检查 ICNS/图标资源，必要时用户重新固定 Dock 图标。
- [跨平台打包时间较长] → 分平台构建与校验，只有全部目标元数据和校验和生成后才更新线上清单。

## Migration Plan

1. 先发布 Web 移动端结构并运行组件、类型和生产构建回归。
2. 将桌面版本递增，分别构建 macOS arm64、macOS x64 和 Windows x64 安装包。
3. 校验包内图标、签名/安装器结构、SHA-256 与发布元数据。
4. 上传 OSS、更新桌面发布清单、提交 Git 并部署 Web/Backend。
5. 线上验证移动端静态资源、健康检查和三个下载入口；异常时回滚 Git/清单到上一版本。
