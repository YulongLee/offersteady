## Context

本地 2.0.0 现有的合成演示验证了浮窗、透明度和登录位置。国服官网已提供真实账号和面试全流程。

## Goals / Non-Goals

让用户使用独立测试包测试现有国服。线上代码、配置、下载入口及正式发布超出范围。

## Decisions

1. 从已发布的 1.3.6 包应用菜单和版本增量。原助手渲染文件保持相同。测试版使用独立的本地助手目录和机器码。
2. 本地工具条和官网视图分别使用独立内存会话。官网视图仅允许国服同源请求和导航，不暴露原生接口，也不请求采集权限。原助手按既有流程负责采集。
3. 同一原生窗口的官网视图从受保护的面试入口开始，由官网处理登录、账号管理、准备、绑定和会话控制。仅在浮窗本地覆盖版式。
4. 仅浮窗启用原生置顶。窗口首次打开时透明度为 0%，滑块可在 0% 至 60% 之间调节。关闭时释放网页实例，在助手本次运行期间保留官网登录会话。失败时提供重试。
5. 回环夹具验证登录跳转、面试导航、断开和重试。国服验证只读取匿名公开入口，由用户在自己的账号下测试真实会话。

6. 仅对受信站点的面试准备路由，在浮窗内隐藏机器码输入和历史设备入口。隔离脚本等待官网确认可连接且本场未绑定，复用当前助手身份触发一次官网验证。保留现有绑定、冲突提示及官网失败后的重试入口。开始面试仍由用户操作。
7. Mac 候选包沿用国服正式包的应用 ID、Developer ID 和权限签名要求。只重签外层应用，保留原版内嵌组件、采集授权声明及签名，复用正式签名和音频 entitlement 校验。App 和 DMG 分别公证并附加票据。候选包在独立目录测试，仍使用 2.0.0 测试数据目录。
8. Mac 候选包的预览、截屏快捷键和截图回答共用过滤截屏入口。单次 ScreenCaptureKit 截图按运行进程识别助手应用，排除该应用的全部窗口。无法确认来源或取得过滤画面时提示失败，保留原有锁、超时和图片处理。
9. 原有「预览」直接展示过滤后的单次截屏，保持原有界面。移除独立共享窗口、菜单和持续采集进程。第三方会议软件各自选择和采集共享来源，助手预览的过滤只对助手自己采集的画面生效。
10. Mac 浮窗工具条提供「收起」。本地工具条隐藏原窗口并保留官网视图和窗口设置。现有菜单恢复该实例。收起期间官网视图继续执行可见页面的实时更新逻辑。系统关闭按钮仍负责关闭浮窗。
11. Mac 本地测试版在主窗口和浮窗显示前请求系统窗口捕获保护。调整浮窗透明度后重新请求。保护状态只记录窗口的系统请求结果，飞书需以实际接收端的整屏画面验收。

## Risks / Trade-offs

Windows 和 macOS 的捕获保护效果依赖接收端所用的会议软件和系统采集方式。
