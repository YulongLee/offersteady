## Why

知识库报价目前把原始文件字节数直接除以 4 当作 Token 数。该近似对纯文本偶尔接近，但会把 PDF 的图片、字体、压缩流和页面结构误算为正文，导致相同内容的 PDF 比 MD 出现数量级更高的积分报价，并可能错误阻止用户建立索引。

## What Changes

- 知识材料先由服务端解析、规范化，再按实际可索引 Markdown 正文生成 Token 报价，不再按 PDF、DOCX 等容器文件大小计费。
- 将“上传并获取服务端报价”与“确认报价并建立索引”拆分，最终报价包含 Token 数、计费单位、点数、权益来源和预计余额；用户确认前不预留积分或会员额度。
- 报价绑定用户、文档版本和已上传内容；内容变化、报价缺失或不匹配时拒绝确认。
- 解析后的规范化正文作为预报价产物缓存，正式索引复用该产物，避免 PDF 被重复解析。
- 空白、无法解析或没有可索引正文的文件返回明确错误，不生成最低消费报价；重试仍按规范化正文重新报价。
- 更新知识库上传界面，PDF 等二进制格式不再展示基于文件体积的虚假即时价格，而是展示服务端解析状态和最终报价。

## Capabilities

### New Capabilities

- `content-based-knowledge-index-quote`: 定义跨 PDF、DOCX、DOC、TXT、MD 的正文解析计数、两阶段报价确认、报价绑定与解析产物复用行为。

## Impact

- 后端：知识材料上传、文档解析、索引计费与重试链路；新增预报价接口和报价绑定校验。
- 前端：知识库上传对话框及材料上传适配器改为两阶段流程。
- 数据与隐私：继续只持久化原始对象和受控的规范化产物；报价与日志不得保存正文。
- 兼容性：已确认历史报价不重算；旧客户端完成请求保留安全的服务端解析回退，但新 Web 客户端必须展示最终服务端报价。
