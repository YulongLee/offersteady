## Context

Web 设备页当前同时承担助手下载与账号设备状态中心两种职责。状态中心会在页面加载时请求设备列表，并展示心跳、权限和诊断信息；用户已确认这些内容没有实际使用价值，希望页面回归下载与安装这一单一目标。设备关联接口仍被准备页和桌面助手运行链路使用，不能随界面一起删除。

## Goals / Non-Goals

**Goals:**

- 让设备页只呈现助手下载、版本选择、安装与授权说明。
- 停止设备页加载账号设备列表，移除关联状态与诊断界面。
- 保证准备页绑定、助手心跳和面试连接行为保持不变。

**Non-Goals:**

- 不删除设备关联 API、适配器方法或数据库记录。
- 不修改桌面助手代码、协议或发布包。
- 不重新设计下载中心的视觉结构。

## Decisions

### 在页面层停止请求，而非删除领域能力

`DevicesPage` 将不再调用 `listDesktopDevices`，也不再持有设备列表、加载、错误和诊断展开状态。领域适配器及后端接口继续保留，因为准备页、运维排查或后续产品决策仍可能依赖真实设备关联。

替代方案是删除完整设备中心能力，但这会扩大到后端和桌面助手，并可能破坏面试绑定链路，不符合本次仅移除页面内容的范围。

### 保留原设备路由并让下载中心成为唯一主体

继续使用 `/app/devices`，避免导航和已有入口失效；页面标题和说明改为下载导向，主体只渲染 `DownloadCenter`。

替代方案是删除设备菜单与路由，但用户仍需要稳定入口下载与更新电脑助手。

### 用页面级回归测试锁定“不请求、不展示”

测试既断言下载内容仍可见，也断言设备列表接口未被调用且状态中心文案不存在，避免未来只隐藏界面却保留无意义请求。

## Risks / Trade-offs

- [用户暂时失去 Web 端设备在线诊断入口] → 保留安装授权说明与后端能力；若未来有真实使用需求，可在明确场景下重新设计诊断入口。
- [旧 OpenSpec 仍描述设备状态中心] → 在提案中明确本变更取代其 Web UI 要求，并以新能力规格记录当前设备页行为。

## Migration Plan

1. 更新页面、样式和回归测试。
2. 运行 Web 测试、构建与 OpenSpec 严格校验。
3. 正常发布 Web 应用；无需数据库迁移或桌面助手发版。
4. 如需回滚，仅恢复 Web 组件与样式即可，后端接口始终保留。
