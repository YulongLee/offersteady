## Context

2.0.0 浮窗原型以国服 1.3.6 为基础；不同平台的本地测试包产生于不同修订，Mac 最终测试版本申请窗口捕获保护。测试版使用独立设备数据目录。用户要求封装正式候选，部署另行进行。

## Goals / Non-Goals

**Goals:** 统一三平台功能范围，保留正式设备身份与原有功能，明确签名、采集保护和验证状态，形成可审阅的本地交付物。

**Non-Goals:** 部署、上传、切换下载清单、改动服务端或官网、修复 Zoom 隐藏限制、对所有会议软件承诺隐藏。不得创建真实会话或支付来测试。

## Decisions

1. 对照已发布 1.3.6 的实际构建输入及现有测试变更，构造同一冻结候选后分别生成三平台；不以旧测试 ZIP 简单重命名为正式包，避免不同修订混用。
2. 正式模式沿用正式数据目录和设备身份迁移、bundle identity、后端地址及权限声明；测试模式保持隔离。仅通过合成目录验证迁移和不覆盖既有凭证，不触碰真实设备数据。
3. 复用正式 Mac Developer ID、App/DMG 签名、公证、staple 与 Gatekeeper 验收；验证程序及原生采集组件的架构和签名。Windows 构建安装程序并如实标注未签名状态，不能假称签名或实机验收。
4. 保留现有浮窗与助手的预览/截图过滤实现及第三方保护申请；如实记录 Zoom 共享和录制曾显示浮窗，接收端结果依赖采集方式，不以请求成功当作隐藏成功。替代方案为新增共享专用画面，但用户已明确不采用该交互。
5. 构建前后进行桌面回归、功能保护对照和包内检查；真实采集权限、Windows 实机、跨会议软件行为与用户真实场景没有证据时明确待验收。

## Risks / Trade-offs

- [Mac 系统及第三方采集差异] → 明确 Zoom 限制，避免“所有会议软件隐身”的声明。
- [测试身份误入正式版] → 合成升级与已存在身份检查，冻结包内配置并验证。
- [正式证书、公证或某平台构建不可用] → 保留部分制品及失败证据，不标记该平台正式候选完成。
- [现有用户流量] → 本变更不访问或更改线上状态，测试使用隔离和合成数据。
