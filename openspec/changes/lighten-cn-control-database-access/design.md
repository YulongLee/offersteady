## Context

当前实际CN Backend镜像为`2f2c8935…`，Web为`9261bdb4…`；本轮继续叠加尚未部署的`reduce-cn-state-read-overhead`候选，不能回滚它或10月27日SEO。本次扩展开始前保存157份Backend/依赖/构建输入快照至本地证据目录。16:09–16:14峰值控制请求和用户操作一起变慢，稍后全库短连接约36.81次/秒，但尚未证明建连、SQL或排队是唯一原因。

现有心跳15秒、绑定轮询10秒、单飞/退避、状态语义去重、服务端心跳写节流、pairing短缓存及预取合并已存在。本轮不重复实现或调整频率。`_compute_desktop_pairing_status.session_state`只需status/mode/audio，却通过`get_session`触发资料刷新和可能写回；这提供直接可验证的减负点。

## Goals / Non-Goals

**Goals:** CN控制查询仅读必要字段、无资料读取或附带写入；在auth/session两个热点仓库保留权威逐次SQL并复用受限连接；以真实隔离数据库证明输出/事务/权限和资源边界保持。

**Non-Goals:** 不修改线上、Git提交/推送、模型、Prompt、收音、轮询/心跳间隔、收费、SQL schema/索引或Global；不关闭预取或添加资料/用户/权益TTL。billing、document及worker的连接路径保持，避免一次扩展全部事务模式。未测定生产池大小，不承诺线上P95降幅。

## Decisions

### 1. 专用控制投影

新增不可变`SessionControlState`，含session_id/owner/status/session_mode/interview_audio_mode，不扩充已有heartbeat投影。PG读取明确5字段并排除软删除；内存仓库同样生成投影。Service按原404/403校验owner，保留legacy空模式默认。CN pairing局部使用该方法，其余分支和原有单请求session_states去重保持；Global用原`get_session`。

不缓存投影，结束/删除/模式变化在既有pairing缓存的新鲜度边界内继续权威可见。原`get_session`及正式回答、捕获授权、资料变更、收费路径仍独立读取完整会话，不能借展示投影跳过实际业务检查。替代方案为复用heartbeat投影，会扩大既有心跳合同；跨请求缓存则增加失效风险，均不采用。

### 2. 显式Backend生命周期内共享一只连接池

固定`psycopg_pool==3.3.3`运行依赖。新增开关默认关闭，Global即使误配开启也继续短连接。仅CN FastAPI lifespan显式激活，使同配置auth/session两个仓库共用一个有界池；worker仅继承环境开关不得激活。其它仓库保持原连接。默认实验参数min=0/max=4/最大等待16/借用超时3秒，可配置且校验上下界；这不是生产调参结论。

连接提供器只替换`_connect`上下文入口，默认tuple行及autocommit=False保持，cursor级dict_row和原显式commit/rollback不变。依赖池上下文正确提交/异常回滚归还，不自动重放SQL、写入或绕过失败扩张短连接。连接每次使用仍查询当前DB数据，连接复用不缓存身份或计费结果。

配置身份包含DSN/连接参数/池限制，不能误借其它配置连接。进程内共享总上限，不为每仓库额外分配max；同配置多个app引用计数，冲突配置必须安全拒绝或不误共享。PID/fork守卫禁止继承父进程活连接。用外层生命周期包装覆盖启动异常、正常关闭及持有连接归还，避免yield前初始化失败泄漏。开关关闭不导入可选运行逻辑且原短连接参数保持。

替代方案为全局monkeypatch psycopg或一次替换所有仓库，会扩大worker与账务事务范围，拒绝；每仓库独立池难以控制总连接数，拒绝。更长空闲轮询会增加新绑定发现等待，本轮不改。

### 3. 可复核计数、分项和功能矩阵

专属localhost合成PostgreSQL，固定相同SQL/会话/资料和并发，比较完整控制读取与轻量投影、短连接与实际仓库池路径。记录网络无变化条件下的资料/查询/连接/写入次数、样本、错误和P50/P95。计量建连/借用及查询分项时使用测试观测或固定数值计数，不代理全部业务cursor或记录SQL参数。

补充池关闭、事务回滚/显式提交、错误后恢复、连接断开、等待超时/队列边界、同配置共享、不同配置隔离、worker/Global关闭、fork及身份撤销/收费新鲜度等测试。完整运行先前状态读取、鉴权、资料、模拟/普通面试和收费相关回归。线上既有指标不因本次本地测试变化，不把同机实验结果等同生产收益。

## Risks / Trade-offs

- [控制轻读漏owner/删除/legacy模式] → 明确投影字段和过滤，wire对照及多分支回归。
- [复用导致事务/状态残留或借错库] → 原上下文不改，失败回滚、配置身份隔离、持有归还测试；不得缓存权限结果。
- [池等待伤及用户] → 总量/等待有界、分组并发测试、默认关闭；晚间发布需重新校准并评估是否开启。
- [启动异常/多app/fork泄漏] → 外层生命周期、引用计数/PID检查、资源清理回归。
- [指标失真/日志泄露] → 固定组件标签及数字，不输出DSN/SQL/用户数据；区分本地和生产、借用与SQL执行阶段。

## Migration Plan

本轮仅本地交付，保留所有现有服务。晚间用户授权后重新冻结实际Backend/Web镜像，包含前一轮候选的最小增量；池开关默认关闭，是否启用及上限需当次发布记录。核对旧功能/私有配置与用户工作门禁、固定镜像和回退；不得直接全量覆盖静态包、停止用户或修改国际服/worker。
