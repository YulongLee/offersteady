## Context

开发分支 `codex/cn-written-multi-screen` 从用户确认的 `release-cn-20261019.1`（4cdd557）新建，已封版工作区保持干净。既有 `ScreenshotAnswerService.answer_screenshots(image_ids)`、预处理器和视觉网关支持顺序多图，默认最多4张；远程捕获当前将上传和生成串在一起。桌面助手仅依赖原上传端点的HTTP成功，不需要升级。

现有Web封版包含冻结静态增量，研发源码不能当作全量重建的线上等价证明。本轮仅改动笔试及截图入口并本地测试，不部署整包覆盖。

## Goals / Non-Goals

**Goals:** 顶部开关、底部双按钮、最多4张顺序暂存、一次显式提交/生成/结算、可移除/取消/清理和旧单图兼容。

**Non-Goals:** 不改普通/模拟面试、简历、国际服、助手分发或已有收费；不做跨设备屏幕选择、后台自动截屏、拼图、OCR改造、模型供应商或Prompt改造；桌面助手全局快捷键仍走原单图接口，页面快捷键跟随当前按钮模式。

## Decisions

1. 远程捕获增加默认false的 `captureOnly` 和响应 `capturedImageId`，原桌面上传完成时capture-only分支立即终态，不运行AI、不生成历史/账本。采集仅允许进行中的written会话。复用现有内存暂存/TTL，避免浏览器持有dataURL或新增持久存储。
2. 新增 `POST /sessions/{id}/batch-answer-requests`，接收有序 `captureRequestIds`。服务验证同用户/同written会话、已完成未取消且图片有效、无重复/未被其他批次占用。服务锁内以有序来源ID去重并创建processing父请求，只有首次请求排入背景工作，避免双击与并发重复生成。对已受理批次的重试返回原请求，不重新消费图片。
3. 父请求复用远程截图事件与恢复查询，背景调用既有多图生成链路并在首次task更新时绑定task ID，以便取消。每批只调用一次已有计费服务，不在采集时预扣。输入在服务端预检后再受理，过期/缺图须重截，不能无声自动重试。
4. capture-only完成态可通过既有cancel入口释放未使用图片；图片被正在生成的批次占用时不被独立清理破坏。取消、上传及任务更新需在状态写入前检查终态，处理晚到回调，原临时字节清理仍作为兜底。结束会话保留已有session release。
5. Web只保存capture request ID、image ID和显示名。笔试顶部复用现有开关样式；底部复用操作栏，增加数量和删除chip。采集期间禁用重复截屏/回答，提交期间禁用开关和重复操作。清理作用域绑定session及页面租约；unmount同步abort，再尽力cancel，TTL兜底。
6. 不改视觉Prompt。已存在的gateway会把多图顺序发送在同一条message中；新增合成评测/契约测试验证图序、共享上下文和单次调用。相比客户端多次单图生成后合并，此方案保留原图上下文并少收一次任务费用。

## Risks / Trade-offs

- 多图时延及token增加 → 沿用4张和单文件限制，展示生成状态和终止入口，不做生产压测。
- 采集后停留过久会TTL过期 → 后台预检及时报重截，不收费；不增加长期截图存储。
- 请求并发/用户离开/晚到上传 → 服务锁、来源占用与终态保护；前端epoch/AbortController和最终清理测试。
- 服务重启丢失内存采集 → 明确报错重截，不新增数据库恢复复杂度。
- 冻结Web与源码差异 → 本轮本地验证不能代替未来发布前实际镜像/静态/既有路由核对。

## Migration Plan

首阶段无DDL、无外部新依赖、无生产部署。旧客户端省略字段即原单图流程。用户已追加国服上线授权，发布依照[生产追加流程](production-release.md)执行；必须先复核实际镜像和源码差异，按保护门禁执行。功能回退恢复记录的组件镜像，既有资料/账本不回滚。

## Open Questions

无阻塞项；采用既有最多4张和按一次截图回答计费。用户要求的多屏指连续截取当前所选屏幕的多个画面，不自动选择/捕获多个物理显示器。
