## Context

状态：apply-ready，用户已于2026-11-02授权当前助手上线。客户端来源为[Local-r3交付](../../../docs/releases/companion-1.3.6-local-r3-20261101.md)，版本仍1.3.6；正式版本将替换国服三平台1.3.5下载条目。旧本地-only文档保留作为历史证据，本变更只授权Desktop分发。

新鲜基线保存于`artifacts/companion-cn-1.3.6-20261102/baseline/`。当前实际Backend运行镜像为`sha256:c62df7ddbb92627de83c7c2733574c862678b120a11d051b346b9d13abfcf58a`，容器为`edd16865e5d5c0b1e57f33a696faf28cdffc340846db65e70150bb77a418a4dd`；正式清单SHA-256为`76ba8b6009071d4c4c0b824b6bbbf1c05c7d848f95c1ab08649c9e9e05c4a76a`。发布每次均须重新验证，不能把文档值当作跳过漂移检查的依据。

实际Compose用固定镜像SHA，`compose-backend:latest`已经不同于运行镜像。旧1.3.5控制器假定运行`Config.Image=compose-backend`且latest等于运行镜像，不适用于本次；不得修改旧发布控制器或盲目重打latest标签。

## Goals / Non-Goals

目标：三个架构同一已测试源码、正式签名与诚实信任元数据、完整对象校验、无重启原子发布、保留未来重建与精确回滚材料。

非目标：新的助手功能、协议或依赖升级、Web/Backend笔试业务配套上线、其他组件/国际服/Git发布、关闭真实面试、修改采集授权或系统隐私提示、保证所有硬件与网络场景均已实测。

## Decisions

1. **正式包与源码冻结。** 保持1.3.6、Electron42.5.0、国服bundle/team/协议及生产HTTPS默认值。先复核Local-r3冻结源和当前输入，Mac两架构顺序构建/核验，避免共享`dist/native`混架构；最终产物的非native dist与已测试版本逐字比较，native编译载荷按既有验签归一化规则比较。不能因公证/封包重做而混入其他工作树改动。无local-test-runtime、Global覆盖、测试文件或服务端凭据。
2. **Mac发布资格。** 使用既有Developer ID与正式打包/验证流程，分别验证实际App和全部Mach-O签名、版本/架构、主/Helper原生音频输入权限、App与DMG的公证/staple/Gatekeeper、DMG内实际载荷、最终大小/hash。Local-r3本地DMG未公证，不能仅更名或改metadata。签名或Apple服务失败时保留旧官网清单，不绕过系统验证。
3. **Windows真实状态。** 可使用与Local-r3冻结源/dist匹配的最终NSIS包；验证外/内归档、实际x64 PE和所有安装文件。继续分发真实unsigned状态，不声明Authenticode或实体设备音频验收通过。
4. **OSS对象先准备。** 使用国服`desktop-releases/<platform>/<architecture>/1.3.6/<official filename>`不可变路径。存在相同对象时完整读回确认相同字节后复用；已存在不同字节停止。新对象上传后完整读回比对长度和SHA-256，三个全部通过才允许官网清单切换。现有官网与版本门禁均只读取容器内发布清单，不读取OSS三个latest文件；本轮不写这些非当前官网来源的指针。不得运行会自动改latest的通用上传器，也不得将上传成功或分片ETag当作完整校验。
5. **实际运行清单CAS。** 专用1.3.6控制器默认只读，显式发布模式才暂存和切换。核对实际容器ID/镜像/Config.Image/启动时间/重启数、业务文件和全部预期输入、无新增挂载及健康状态；保留八个组件生命周期基线。待替换文件必须在同目录、非symlink、0644，以锁+旧hash比较+fsync+原子rename切换三条目。下载元数据与版本检查按请求读清单，因此不重启Backend/Web/worker。新绑定/开始面试的1.3.5用户会收到现有升级提示；已绑定采集不被主动关闭。
6. **未来重建材料。** 从实际运行固定SHA制作仅单COPY新清单的一层镜像，验证Config全等、RootFS旧层前缀和完整运行输入，保存专属候选及回滚标签。输出固定候选SHA的`backend-image.compose.json`，用于未来经新一轮授权及保护门禁的显式重建；本轮不执行Compose up，不改历史Compose或`compose-backend:latest`。热清单在容器可写层，普通restart可保留；仅生成材料并不会改变历史Compose的recreate行为，今后重建必须显式携带此覆盖或将新清单纳入后续候选。
7. **漂移、丢失回执与回滚。** 保存旧清单精确字节、不可变对象证据、实际基线、控制器和候选校验结果。每步重验，发生源码/镜像/配置/清单/对象漂移停止。SSH回执丢失先读实际状态：仅已知旧/新清单与匹配组件允许确认完成或受控CAS恢复，不盲重放。不识别的状态不自动覆盖。回滚只恢复已知发布状态中的旧清单；保留不可变安装包和旧latest原字节，不回退业务镜像、不结束用户会话。
8. **公开验收与记录。** 三平台公有state、真实下载API Range及整包大小/hash/MIME、公开健康/登录和既有模拟面试保护路由验证；前后容器生命周期与业务输入不变。不打印签名下载URL、原始用户日志或配置，不调真实模型/面试或生产压测。记录Windows/Intel硬件和真实网络/音频未由结构验证覆盖，以及本地Web/Backend配套未上线。

## Alternatives

- 重建整个Backend或Web：超出助手发布范围，且可能将尚未上线的业务改动带入生产；拒绝。
- 复用旧控制器并改几个版本常量：旧镜像/标签前提与实际固定SHA冲突；采用独立控制器保留旧证据。
- 修改历史Compose/重打latest作为持久化：会悄然改变其他发布的重建来源；采用独立固定SHA覆盖材料，明确今后recreate需携带。
- 将未公证本地DMG作为正式包：不满足已确认的Mac正式分发规范；必须通过正式流程。

## Risks / Trade-offs

- 升级清单同时提高既有新绑定/开始门槛：三平台全部可完整下载后再切换；用户需要完全退出旧助手并安装新版本，既有会话不主动断开。
- 可写层与镜像内清单不同：保存只增加清单的固定候选及Compose覆盖，公开记录未来重建的显式步骤，后续基线必须读取实际清单。
- 公证/下载服务不稳定：有界操作并保留阶段证据，正式资格或完整校验失败时不改当前官网。
- 实体硬件覆盖有限：沿用既有来源与合成/原生验证证据，不将结构和签名检查解释为所有用户环境已通过。

## Migration Plan

核对实际生产与旧清单 → 冻结正式源及完成三包终检 → 上传/完整读回不可变版本对象 → 制作并核验manifest-only候选和未来重建覆盖 → 重复基线检查 → CAS更新官网三平台清单 → 验证公有下载和无重启事实 → 记录完成状态与回滚材料。OSS三个latest文件不写入。任何未知状态或漂移停止后报告，不放宽保护。
