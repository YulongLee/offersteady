## Context

生产样本中 `active-connection` 与 `device-status` 占普通 API 请求的大多数；等待绑定阶段固定 250ms 探测，已绑定探测又在每次成功响应后重复提交相同设备状态。后端单 worker 内部分异步路由直接调用同步 Redis/PostgreSQL，频繁控制面请求会与业务 API 争用事件循环。截图请求使用 SSE，但捕获状态变化会反复重启连接；管理监控又将截图 SSE 的连接持续时间计入普通 API P95。

当前 Redis 实时语音仓库保留进程内状态，尚不具备安全横向增加 Uvicorn worker 的条件。本轮必须先降低请求放大并修正观测口径，不能通过多 worker 掩盖一致性风险。

## Goals / Non-Goals

**Goals:**

- 降低空闲和已绑定伴随程序产生的控制面请求量。
- 保证绑定进入 live、设备状态变化和截图请求仍能及时到达。
- 避免短暂捕获状态造成截图 SSE 重连风暴。
- 让普通 API P95 只反映请求/响应 API，将 SSE 持续时间单独统计。
- 保持失败退避、授权、单会话约束和现有响应协议不变。

**Non-Goals:**

- 不修改 ASR 模型、音频分片、VAD、字幕、快答、截图回答生成或计费链路。
- 不增加 Uvicorn worker，不迁移实时状态仓库，不引入数据库连接池。
- 不改变伴随程序布局、颜色、权限或用户操作。
- 不持久化新的用户内容或敏感数据。

## Decisions

### 1. 使用服务端建议与有界客户端间隔

等待绑定阶段以服务端 `refreshAfterMs` 为优先并设置 1 秒下限；已绑定稳定状态保留既有 2 秒租约探测。请求完成后才安排下一次，失败沿用现有 5–30 秒退避。相比固定 250ms，这可显著减载，同时绑定进入 live 的最坏新增探测延迟保持在 1 秒量级，且不降低会话内租约恢复性能。

替代方案是改为新的绑定 SSE。它能进一步降低请求，但会增加协议、鉴权、代理和旧客户端兼容范围，不适合本轮低风险优化。

### 2. 设备状态按语义变化上报并保留周期保活

客户端对规范化状态 payload 生成稳定指纹。指纹变化立即发送；相同状态在上次成功后的 15 秒内跳过，超过时限发送保活；失败不更新成功时间并按下一次轮询重试。这样不会丢失异常与恢复转换，也不会把每次绑定查询放大为一次写请求。

替代方案是只在变化时发送。该方案请求更少，但后端无法区分长期稳定与客户端失联，因此保留低频保活。

### 3. 截图 SSE 只在连接资格跨边界时调整

捕获内部状态在 capturing/error/reconnecting/paused 之间切换时复用当前 SSE；只有从非运行态进入运行态且没有连接时立即启动，或明确离开有效运行态时停止。任何时候最多一个 AbortController 和一个重连计时器。

替代方案是让 SSE 永久在线。未绑定设备会持续产生拒绝或空连接，反而扩大服务负载。

### 4. 普通 API 与流式连接使用互斥统计类别

实时语音和截图 `/stream` 路由统一分类为 `sse_stream`。普通 API P95 排除该类别；监控继续提供 SSE 连接数和连接持续时间分位值。现有健康/控制 API 指标字段保持兼容，只新增可选拆分字段。

替代方案是只在前端隐藏异常值。该方案会保留错误数据，无法用于容量判断，因此不采用。

### 5. 不在本轮增加 worker

单 worker 保持不变。先通过请求减载和正确观测验证瓶颈；只有实时状态完全外置并具备跨进程一致性测试后，才能单独评审多 worker。

## Risks / Trade-offs

- [等待绑定探测从 250ms 增至至少 1 秒会增加最多约 750ms 的发现窗口] → 遵循后端 1 秒建议值，进入 live 后继续使用既有 2 秒租约刷新，状态变化上报立即执行。
- [状态指纹实现错误可能跳过必要事件] → 只规范化协议内字段，变化即时发送，失败不提交缓存，并增加异常/恢复/保活测试。
- [SSE 生命周期调整可能造成进入运行态后未启动] → 跨资格边界时主动唤醒，并覆盖启动、复用、停止和失败重连测试。
- [指标口径变化造成历史曲线不可直接同比] → 保留总请求数，明确发布时点，并同时展示普通 API 与 SSE 持续时间。

## Migration Plan

1. 先部署后端兼容性与指标分类；旧伴随程序继续按原协议工作。
2. 构建并发布补丁版伴随程序，服务端保持向后兼容。
3. 发布前确认无活跃面试，或在可控窗口替换单 worker 后端；验证健康检查和核心接口。
4. 对比发布前后 15–30 分钟 `active-connection`、`device-status` 请求率、普通 API P95、错误率和 SSE 重连数。
5. 若健康或核心链路回归，回滚后端镜像/提交；客户端改动不改变协议，可回退至上一补丁版本。
