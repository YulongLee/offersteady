## Context

国服 Web 已有静态公开内容体系：源页面位于 `apps/web/public/seo`，共用 `public-search.css`，由 Nginx 将简洁公开路径映射到静态 HTML。首页同时有 React 公开布局和 `index.html` 的无 JS 预渲染内容。首批文章已经整理在 `content/cn-resource-center-20261011/`，但还没有可访问的公开页面。

本变更只增加公开、无登录依赖的内容入口。简历、JD、音频、截图、支付和面试会话不进入资源中心；文章中的示例数据均为合成说明。

## Goals / Non-Goals

**Goals:**

- 提供 `/resources` 目录和 5 个稳定的文章 URL；
- 使用现有静态页面视觉体系，保证桌面和手机可读；
- 让每篇文章有唯一标题、描述、H1、canonical、Article 与 BreadcrumbList JSON-LD；
- 将资源中心加入首页“查看更多资源”和公开页脚；
- 将新 URL 纳入 sitemap，并增加本地静态构建与链接回归检查；
- 不依赖业务 API、登录态或新的运行时依赖。

**Non-Goals:**

- 不新增 CMS、后台编辑、评论、搜索、推荐或订阅能力；
- 不把 Markdown 在浏览器端动态渲染；
- 不改动首页主体布局、现有产品功能、登录、支付、面试或桌面助手；
- 不在本轮部署国服或修改国际服；
- 不宣称文章发布后必然收录、排名或带来注册。

## Decisions

### 1. 使用静态 HTML，而不是新建博客运行时

将目录和文章输出为 `apps/web/public/resources/**/index.html`，复用 `public/seo/public-search.css`。这样搜索爬虫可直接读取正文，页面不需要登录或业务 API，也不会增加主业务 JS 包。

替代方案：在 React 中新增文章路由。该方案会让公开文章依赖应用启动和路由 JS，与现有静态公开内容架构不一致，因此本轮不采用。

### 2. 使用目录页 + 文章目录 URL

目录为 `/resources/`，文章为 `/resources/<slug>/`。目录展示分类、摘要和更新时间；文章页通过明确的“继续了解”内链承接产品功能。

替代方案：继续把文章放在 `/guides` 下。该方案会混淆操作指南和产品问题报告，也不利于后续维护独立的技术报告栏目，因此不采用。

### 3. 通过显式静态路由暴露页面

在 `infra/nginx/default.conf` 增加 `/resources` 和 `/resources/<slug>` 的精确允许列表，未知 slug 返回 404。Vite 本地开发直接读取 `public/resources`，可以用 `/resources/` 预览。

替代方案：将所有未知路径回退到 `index.html`。这会把拼写错误的文章地址交给应用路由，降低公开内容的 404 可观察性，因此不采用。

### 4. sitemap 和回归检查以单一清单为准

在 Web 公开静态测试中维护资源 URL、文件和 metadata 的清单，sitemap 同步加入 6 个新 URL（目录 + 5 篇文章）。测试检查每个页面有唯一 H1、canonical、JSON-LD、正文和站内链接。

替代方案：只手工更新 sitemap，不加测试。该方案容易出现页面已发布但 sitemap、Nginx 或静态文件遗漏，因此不采用。

### 5. 文章源稿与发布 HTML 分离

`content/cn-resource-center-20261011/` 保留可编辑 Markdown 草稿和内链计划；`apps/web/public/resources` 保留本轮可预览的静态 HTML。正式发布前需人工核对两者内容一致，不在浏览器端读取 Markdown。

## Risks / Trade-offs

- [内容同步风险] Markdown 与 HTML 可能不一致 → 在发布清单中记录文章 slug、标题和最后复核日期，构建前做标题/slug 对照检查。
- [页面数量增加] sitemap 和静态验收范围扩大 → 使用单一资源清单生成/校验文件，未知页面保持 404。
- [静态页面样式复用] 共用 CSS 的调整可能影响既有公开页 → 本轮只复用现有类名，不新增全局样式覆盖；本地检查首页和资源页。
- [SEO 预期过高] 结构化数据和内链不保证排名 → 页面文案明确只提供技术整理，发布后单独观察收录、展现、点击和注册。
- [隐私边界] 文章可能引用线上问题 → 只使用合成示例和已公开的通用排查方法，不写用户标识、原始日志、密钥或音频。

## Migration Plan

1. 添加 OpenSpec 约束、资源源稿和静态目录/文章页面。
2. 增加首页资源入口、sitemap、Nginx 路由和静态回归测试。
3. 本地执行类型检查、资源测试、SEO 静态检查和生产构建；通过后用本地预览地址查看 `/resources/`。
4. 本轮不执行线上发布。后续若用户确认内容和页面，再按国服无进行中面试的发布流程部署。
5. 回滚时删除资源导航、资源静态文件、sitemap 条目和 Nginx 资源路由即可，不触碰业务数据。

## Open Questions

- 正式上线时栏目名称是否保持“技术报告”，还是使用更宽的“资源中心”？本轮默认使用“资源中心”。
- 文章更新时间是否按发布日统一，还是在每次内容复核时更新？本轮使用固定的首发复核日期。
