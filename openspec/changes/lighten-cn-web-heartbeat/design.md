## Context

国服运行代码的 `record_web_session_heartbeat` 经 `reconcile_idle_session` 和显式 `get_session` 重复读取会话；`get_session` 还刷新绑定资料。已获用户批准本轮只消除心跳开销，不做连接池、runtime 执行器或遥测改造。

## Goals / Non-Goals

**Goals:** 一次正常心跳一次五字段权威查询，零资料刷新；保持原空闲时间计算、404/403/409、超时清理及租约响应；合成测试后仅国服空闲部署。

**Non-Goals:** 无缓存、建连策略/线程池/采样/轮询调整；无数据库迁移、Web、助手、模型、AI 行为、音频、计费或国际服线上变更。

## Decisions

1. 新增不可变 `SessionHeartbeatState`，仅含会话 ID、所有者、状态、开始时间及最后活动时间。内存仓库投影现有记录；PostgreSQL 单次指定字段 SELECT 并保留软删除过滤。拒绝缓存，因为无需引入结束失效或跨进程一致性风险。
2. `SessionService.heartbeat_idle_status` 校验存在和归属后计算状态；原 `idle_status` 仍走完整会话读取，两者使用同一纯计算方法，避免更改其它资料检查路径。
3. 心跳先完成归属校验，再触碰本进程活动信息。expired 继续调用原终止/资源清理流程，然后返回原 ended 错误；清理失败不伪装成功。preparing/live 租约分支不变，ended 不保存心跳。正常路径不读资料，不写会话/计费。
4. 发布从实际运行镜像仅移植五个文件内的新增类/方法及两个明确修改的方法；AST 验证其它节点未变、镜像配置及模型/环境未变。保留原镜像作为回滚，不覆盖本地 Global 代码或其它脏文件。
5. 性能对比仅用合成记录及本地隔离 PostgreSQL；报告查询次数、资料读取数、样本量和 P50/P95/P99，不把局部自测等同于整体线上 P95。

## Risks / Trade-offs

- [原心跳顺带刷新资料] → 仅移除心跳副作用，保持真正读取/确认资料和回答链路原路径，增加回归。
- [超时清理仍昂贵] → 异常路径继续权威终止；不为降低指标跳过清理或计费结算。
- [并发结束/接管] → 不缓存状态、保留租约原子操作及现有清理机制；结束后下一次心跳读取权威状态并拒绝，不新增强一致承诺。
- [本地与线上源码不同] → 针对实际镜像 AST 小范围移植并在候选镜像自测；任一基线漂移拒绝发布。
- [活动用户恰好进入] → 切换前重复检测普通/模拟面试、页面、音频及后台任务；有活动即延后，不主动结束用户。

## Migration Plan

完成合成回归和查询/性能对比；构建基线覆盖镜像；候选验证后重复空闲门禁，仅重建 backend；检查健康、来源 hash、模型/环境及非目标容器。失败恢复原镜像，不改数据库和 Redis 数据。
