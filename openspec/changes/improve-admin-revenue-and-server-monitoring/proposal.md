## Why

管理后台当前把“实收金额”建立在延迟的每日快照和本地 `paid` 状态上，支付渠道已收款但回调验签或身份校验失败时，运营人员既看不到真实待对账金额，也难以安全恢复订单。现有容量区块也不足以回答服务器 CPU、内存、磁盘、依赖服务和应用健康是否正常，需要补齐可操作、脱敏且不影响用户链路的运营能力。

## What Changes

- 在运营总览增加直接读取权威订单表的“今日支付”实时摘要，明确区分已入账、待确认、回调异常和已关闭金额；历史趋势继续使用日快照并标注更新时间。
- 在订单管理增加待对账队列、回调诊断、支付宝权威主动查单和单笔安全对账入口；只有渠道响应验签、订单身份及金额全部一致时才允许入账和发放权益。
- 拆分支付通知的签名、应用身份、商家身份、金额与订单状态诊断结果，后台只展示安全错误分类，不保存或返回回调原文、密钥和完整渠道交易号。
- 改进支付渠道配置状态，提示 AppID、Seller ID/PID、通知地址和密钥用途，并展示最近一次真实通知/主动查单的验收结果；静态格式通过不得冒充真实支付验收通过。
- 新增独立“服务器监控”区域，展示应用实例 CPU、内存、磁盘、运行时长、API 延迟与错误率，以及 PostgreSQL、Redis、分析任务等依赖健康和最近更新时间。
- 服务器监控采用只读、聚合和有界采样，不挂载 Docker Socket、不返回环境变量、进程命令、数据库凭证、主机文件或用户业务数据；采集失败不得影响面试、支付和用户请求。
- 为支付恢复、实时营收和服务器监控增加回归测试、运维说明与生产灰度验收。

## Capabilities

### New Capabilities

- `admin-payment-revenue-operations`: 覆盖今日实时实收口径、支付异常诊断、待对账队列、权威查单、安全补单和渠道验收状态。
- `admin-server-health-monitoring`: 覆盖服务器与应用资源、依赖服务健康、刷新与降级状态、访问控制和敏感信息边界。

### Modified Capabilities

无。当前主规格目录尚未收录对应管理能力，本变更以新增能力契约补齐现状。

## Impact

- Backend：管理端统计与订单诊断 API、支付宝通知诊断模型、支付对账服务、服务器健康采样与权限控制。
- Admin：运营总览、订单管理、支付设置和新增服务器监控展示。
- PostgreSQL：可能增加脱敏的支付校验结果字段或事件表迁移；不修改既有订单金额和账本不可变原则。
- Runtime：复用现有 PostgreSQL、Redis、cgroup/进程与 API 指标；不引入 Docker Socket 或新的外部监控平台依赖。
- Deployment：仅涉及 Backend、Admin、数据库迁移及监控采集配置，不涉及用户 Web 流程或桌面助手发行包。
