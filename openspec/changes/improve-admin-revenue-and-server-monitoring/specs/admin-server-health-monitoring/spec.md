## ADDED Requirements

### Requirement: 展示服务器与应用资源状态
系统 SHALL 向具备 `observability.read` 权限的管理员展示应用实例 CPU、内存、磁盘、系统负载、运行时长、采样时间和状态阈值。

#### Scenario: 查看服务器监控
- **WHEN** 已授权管理员进入服务器监控页面
- **THEN** 页面展示当前资源值、最近 60 分钟曲线、正常/关注/严重状态及最后更新时间

#### Scenario: 资源读取不受运行环境支持
- **WHEN** 某项 `/proc`、cgroup 或磁盘信息在当前运行环境不可读
- **THEN** 该指标显示“不可用”且其他监控指标继续返回

### Requirement: 展示关键依赖健康
系统 SHALL 使用有界只读探针展示 Backend、PostgreSQL、Redis、运营分析任务和支付配置服务的健康、延迟与最近成功时间。

#### Scenario: PostgreSQL 可用但连接接近阈值
- **WHEN** 数据库探针成功且连接使用率达到关注阈值
- **THEN** 页面显示数据库可连接但容量需关注，并展示脱敏连接数量和阈值

#### Scenario: Redis 不可用
- **WHEN** Redis PING 超时或失败
- **THEN** 页面将 Redis 标记为不可用且不得读取、展示或修改任何 Redis 键值

#### Scenario: 分析任务延迟
- **WHEN** 最近一次运营聚合成功时间超过预期调度窗口
- **THEN** 页面显示聚合延迟及最近安全错误摘要，不把业务指标缺失误报为零

### Requirement: 监控采集不得影响用户链路
服务器健康采集 MUST 独立于面试、支付、资料和用户 API 请求执行，并 SHALL 对每个采集器设置超时、频率限制和独立降级。

#### Scenario: 监控采集失败
- **WHEN** CPU、磁盘、数据库或 Redis 任一采集器抛出异常
- **THEN** 系统记录安全监控错误并返回部分结果，用户端请求和其他采集器不受影响

#### Scenario: 多个管理员频繁刷新
- **WHEN** 多个管理会话在短时间内重复请求服务器健康
- **THEN** 系统复用有时效的采样结果或限流，不为每次页面刷新执行高成本主机探测

### Requirement: 限制基础设施信息暴露
系统 MUST 只返回标准化聚合指标和服务别名，MUST NOT 暴露 Docker Socket、环境变量、密钥、数据库连接串、主机文件、进程命令、容器控制能力或用户业务数据。

#### Scenario: 管理员读取监控接口
- **WHEN** 具备权限的管理员请求服务器健康数据
- **THEN** 响应不包含环境变量、文件路径明细、IP 凭证、用户标识、请求正文或容器管理操作

#### Scenario: 未授权访问监控接口
- **WHEN** 普通用户、无效管理会话或缺少 `observability.read` 权限的管理员请求服务器健康
- **THEN** 系统拒绝访问且不返回任何基础设施指标

### Requirement: 提供独立且可恢复的监控体验
管理平台 SHALL 提供独立服务器监控导航和响应式页面，并 SHALL 在加载、数据过期、部分不可用和请求失败时给出明确状态与重试入口。

#### Scenario: 部分依赖不可用
- **WHEN** 服务器资源可读但数据库或 Redis 探针失败
- **THEN** 页面保留可用的资源卡和曲线，并只在对应依赖卡显示故障

#### Scenario: 监控接口整体失败
- **WHEN** 服务器监控 API 无法加载
- **THEN** 页面显示可重试错误且订单、用户、支付设置和其他后台功能仍可使用
