## Context

`AlipayPaymentProvider._canonical` 当前同时服务出站请求签名和通知验签，并排除 `sign_type`。支付宝网关错误页给出的待验签字符串包含 `sign_type=RSA2`，官方 SDK 生成的官方网关请求也把该参数放在签名请求参数中；通知验签则按通知规则排除 `sign` 与 `sign_type`。

## Goals / Non-Goals

**Goals:**

- 让电脑网站支付和主动查单请求使用支付宝官方网关要求的 RSA2 参数集合。
- 保持异步通知验签的既有参数过滤规则。
- 通过独立公钥验签测试证明请求签名，而不是调用同一个内部规范化函数自证。

**Non-Goals:**

- 不改密钥、AppID、PID 或商品配置。
- 不发起真实扣款作为自动化测试。
- 不改变支付宝响应体签名验证。

## Decisions

新增请求专用规范化函数，仅排除 `sign`；保留通知专用规范化函数排除 `sign` 和 `sign_type`。相比给旧函数增加隐式条件，两个显式入口更容易审查并避免再次混用。

## Risks / Trade-offs

- [风险] 通知验签规则被意外改变 → 保留通知专项测试并明确调用通知规范化函数。
- [风险] 本地测试再次自签自验 → 测试从最终支付 URL 解析参数，用公钥对独立构造的完整请求字符串验签。

## Migration Plan

只部署 Backend。新订单和主动查单立即使用新签名；历史订单数据不变。回滚为上一 Backend 镜像即可。
