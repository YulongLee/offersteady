## Context

现有工作区已经包含控制面轮询降频和单飞调度的本地改动，但桌面包版本仍为 1.2.17。用户需要以 1.3.0 作为本地测试版本，同时明确不发布线上。

## Goals / Non-Goals

**Goals:**

- 让 Electron 应用和本地包元数据统一显示 1.3.0。
- 验证绑定轮询、失败退避、单飞调度和现有音频链路的回归行为。
- 产出并启动本机开发版，方便用户直接测试。

**Non-Goals:**

- 不修改后端 API、数据库、Redis、ASR 模型或协议。
- 不上传 OSS、不生成线上发布清单、不部署或重启任何线上服务。
- 不改变界面布局、权限、音频采集或截图回答行为。

## Decisions

### 1. 版本来源以桌面工作区 package.json 为准

Electron 使用 `apps/desktop/package.json` 的版本生成应用元数据；只更新该本地桌面包版本，根工作区保持 0.0.0，历史发布文档和线上清单不改动。

### 2. 复用既有控制面策略

不另造一套轮询实现，沿用 `src/main/polling-policy.ts` 与现有 renderer 单飞逻辑。稳定等待/live 状态使用 10 秒，失败沿用有界退避；用户主动操作仍可即时唤醒。

### 3. 本地验证优先

执行桌面端测试、类型检查和构建。构建成功后使用本地开发启动脚本打开 Electron，不调用任何发布或线上部署命令。

## Risks / Trade-offs

- 10 秒控制面间隔可能使纯后台状态发现窗口变长；即时唤醒和 live 状态的单飞控制保证用户操作与音频链路不被阻塞。
- 本地 ad-hoc 包可能触发 macOS 权限提示；这是本机开发包特性，不代表线上签名状态。

## Migration Plan

1. 更新桌面包版本并补齐回归测试。
2. 运行桌面测试、类型检查和构建。
3. 启动本地伴随程序供用户测试。
4. 不执行线上发布；后续是否发布由用户另行确认。
