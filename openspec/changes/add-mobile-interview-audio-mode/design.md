## Context

实时面试目前把音频来源和说话人角色固定绑定：Mac 麦克风视为候选人，电脑系统音频视为面试官。这个模型适用于电脑会议，但手机外放场景中，面试官声音只会经 Mac 麦克风进入系统，因而不会进入问题确认和回答链路。该变更横跨会话模型、Web 准备流程、桌面采集器和后端实时语音路由，并且必须保持现有电脑面试行为不变。

手机外放的单麦克风音频天然可能混入候选人声音、环境噪声和回声。本设计不声称能够做可靠说话人分离，而是显式展示其来源语义，并通过最终转录、问题形态、稳定窗口和去重约束控制误触发。原始音频仍不持久化。

## Goals / Non-Goals

**Goals:**

- 让用户在进入准备阶段前选择电脑面试或手机面试，默认保持电脑面试。
- 让手机面试只依赖 Mac 麦克风，即可完成转录、问题确认、快答和自动回答。
- 保持电脑面试的麦克风/系统音频双通道及既有语义完全兼容。
- 让 Web、Backend 和 Desktop 对同一个会话模式达成一致，并在开始后锁定。
- 明确手机模式是“现场声音”而不是可靠的面试官/候选人分离。

**Non-Goals:**

- 不开发手机 App、手机网页采集或手机直连服务端。
- 不实现声纹识别、说话人分离或通话录音保存。
- 不修改资料检索、语言选择、计费、截屏回答和答案生成提示词。
- 本地实现阶段不部署、重启或修改线上服务。

## Decisions

### 1. 使用独立的会话级音频模式字段

会话增加 `interviewAudioMode: "computer" | "mobile"`，数据库默认值为 `computer`，且仅允许在准备中修改。开始面试后模式锁定。

选择独立字段而不是复用 `sessionMode`，因为实时面试/笔试描述的是产品工作流，电脑/手机描述的是音频采集拓扑，两者可以正交演进。也不使用仅客户端本地状态，避免网页和桌面助手对同一场会话采用不同采集方式。

### 2. Backend 是模式事实来源

Web 创建或更新会话时持久化模式；桌面助手通过现有配对状态接口读取该模式。Desktop 不根据设备名称或系统音频可用性自行推断模式。

相比在配对请求中临时传参，这种方式可保证重连、刷新和换设备后仍使用同一模式，并允许服务端在音频进入问题链路前做第二层校验。

### 3. 手机模式仅启动麦克风发布器

Desktop 的实时发布器已经支持按来源启用通道。手机模式传入仅麦克风通道，电脑模式沿用双通道默认值；准备阶段的本地检测也只把麦克风作为手机模式的开始条件。

相比继续采集系统音频再由服务端丢弃，该方案减少权限失败、无效音频、带宽和服务端处理开销。Backend 仍忽略手机模式下意外到达的系统音频，以防旧客户端或异常客户端绕过采集约束。

### 4. 手机麦克风在问题链路中使用“现场声音”语义

底层协议继续使用既有 `candidate` / `interviewer` 角色，避免扩展所有历史数据和消费方。手机模式下，Mac 麦克风的最终转录在问题候选链路中按可提问来源处理；Web 根据会话音频模式把对应可见标签渲染为“现场声音”。

没有选择新增第三种协议角色，是因为“现场声音”描述的是混合采集来源，不是新的真实说话人身份。答案仍明确是 AI 建议，不把混合音频宣称为可靠面试官文本。

### 5. 手机问题触发采用更严格的资格条件

手机麦克风只有最终且非空的转录可以成为问题候选；候选还必须满足现有问题完整性、稳定窗口、重复抑制和最短内容条件。手动快答允许用户主动确认当前问题；自动回答继续受会话开关控制且默认关闭。

相比对所有麦克风片段直接触发，这降低候选人自述、回声和半句转录造成误回答的风险。相比引入新的模型调用做每句说话人识别，该方案保持延迟、成本和供应商可替换性。

### 6. 采用加法迁移和向后兼容默认值

数据库新增非空默认 `computer` 的列，旧会话、旧 Web 和旧桌面助手全部继续走电脑模式。服务端响应新增字段但不移除已有字段。回滚应用时新增列可以保留，不影响旧版本读取。

### 7. 资源生命周期沿用现有会话清理边界

结束、取消、过期和断开重连仍走现有实时会话清理机制。新增的模式缓存必须在相同清理路径中删除；手机模式不会新增常驻音频对象或原始音频持久化。

## Risks / Trade-offs

- [手机麦克风可能同时收进候选人声音并误识别为问题] → 使用“现场声音”诚实标注、最终转录门槛、问题形态判断、稳定窗口和去重；自动回答默认关闭。
- [手机距离过远或外放过小导致识别率下降] → 准备页提供摆放、外放音量和信号检查，麦克风不可用时阻止开始并给出可操作提示。
- [旧桌面助手不知道手机模式而继续双通道] → Backend 忽略手机模式的系统音频；准备页提示用户使用支持该模式的助手版本。
- [会话模式在 Web 与 Desktop 间短暂不一致] → 以 Backend 持久化值为准，Desktop 每次配对/重连读取最新值，开始后禁止修改。
- [底层仍使用 interviewer 角色可能被其他消费方误解] → 仅手机模式在用户界面统一显示“现场声音”，并通过会话模式使诊断和测试可区分来源。

## Migration Plan

1. 先应用数据库加法迁移与 Backend 兼容字段，默认所有现有会话为电脑模式。
2. 将支持模式采集的 Desktop 作为 `1.3.1` 发布，并通过国服准备页既有的最新版校验阻止旧助手进入新面试。
3. 在确认没有进行中的线上面试后，发布支持模式选择的 Web 和 Backend；只重建并切换相关服务，不重启 PostgreSQL、Redis 或无关容器。
4. 用合成/脱敏音频验证电脑双通道回归与手机单麦克风链路。
5. 观察问题候选误触发率、麦克风转录成功率和实时回答启动率后再考虑扩大自动回答使用。
6. 回滚时可先回滚 Web/Desktop；Backend 默认电脑模式且保留新增列，不需要破坏性数据库回滚。

## Resolved Release Decision

- 手机模式的最低正式桌面助手版本为 `1.3.1`；国服准备页继续以已发布清单中的最新版作为强制准入版本。
- `1.3.2` 修复手机单麦克风模式仍以 `mixed` 身份创建传输发布者而被 Backend 拒绝的问题；手机模式发布者使用 `microphone`，电脑双通道继续使用 `mixed`。
