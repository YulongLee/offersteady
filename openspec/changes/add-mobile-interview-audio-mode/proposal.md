## Why

OfferSteady 当前只支持电脑会议场景：麦克风固定代表候选人，电脑系统音频固定代表面试官。用户通过手机参加电话或视频面试并使用外放时，面试官声音只会进入 Mac 麦克风，现有角色路由不会把它作为可回答的问题，因此需要一个显式、会话级的手机面试音频模式。

## What Changes

- 在实时面试创建与准备流程中增加“电脑面试 / 手机面试”选择，默认保持电脑面试。
- 将设备模式作为独立会话字段保存并在开始面试后锁定，不复用实时面试/笔试或面试语言字段。
- 电脑面试继续使用麦克风和系统音频双通道，保持现有角色与回答链路不变。
- 手机面试只要求桌面助手的 Mac 麦克风；电脑系统音频不作为开始条件，也不参与该场转写和回答。
- 手机面试允许麦克风最终转录进入问题确认、快答和自动回答链路，并使用更严格的问题完整性与去重门槛降低候选人自述误触发。
- 手机面试的混合声音在界面中显示为“现场声音”，不虚假声称已可靠区分面试官和候选人。
- 准备页增加手机外放、摆放距离、音量、耳机限制和麦克风信号检查说明；资料、语言、编程设置、计费、截屏回答、复盘和资源回收沿用现有能力。
- 不引入手机 App、手机浏览器采集、手机与服务端直连或声纹识别。

## Capabilities

### New Capabilities
- `mobile-interview-audio-mode`: 定义手机外放由桌面麦克风采集时的模式选择、准备检查、来源路由、问题触发、界面语义和安全降级。

### Modified Capabilities
- `streamlined-interview-entry`: 在实时面试进入准备阶段前保存设备模式，并根据模式展示对应音频准备要求与开始条件。

## Impact

- Web：创建/准备页模式选择、手机模式提示、准备状态与实时转录标签。
- 协议与会话模型：新增可持久化的 `interviewAudioMode`（`computer` 或 `mobile`），默认 `computer`。
- Backend：会话读写、音频来源准入、角色映射、问题候选和自动回答资格判断。
- Desktop companion：根据会话模式仅发布所需通道；手机模式继续使用当前麦克风权限，不申请新的敏感权限。
- AI：沿用现有回答提示词和资料检索；新增手机混合音频问题检测评测，不记录原始音频。
- 测试：覆盖默认兼容、模式锁定、手机单通道、候选人陈述误触发、语言/资料复用和电脑模式回归。
