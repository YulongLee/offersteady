## Why

管理前端的反向代理会在 Backend 容器重建后继续使用旧容器地址，导致管理员短信验证码请求出现 502；同时登录页不记忆手机号、短会话过期和模糊错误提示增加了重复输入与误判成本。需要在不改变用户端 API、面试、支付和桌面助手行为的前提下，提高后台登录连续性与故障可理解性。

## What Changes

- 让管理前端反向代理通过 Docker DNS 动态解析 Backend，Backend 容器地址变化后无需重启管理前端。
- 为管理登录增加可选择的手机号记忆，只在浏览器本地保存规范化手机号，不保存验证码或管理令牌。
- 增加短信发送冷却倒计时和网关故障的明确提示，避免管理员重复点击或误认为短信供应商故障。
- 将管理会话的默认有效期调整为一个工作日，并继续对高风险操作保持短时二次验证约束。
- 补充配置契约、回归测试和运维文档；发布范围保持 Admin/Backend 独立，不改变用户端构建物。

## Capabilities

### New Capabilities

- `admin-login-continuity`: 管理员登录偏好、短信发送反馈、会话连续性和 Backend 重建后的代理恢复行为。

### Modified Capabilities

无。既有商业管理后台规范仍位于未归档变更中，本次以独立能力补充连续性要求，不重写其访问控制和部署边界。

## Impact

- 影响 `apps/admin` 登录界面和 API 错误映射、`infra/nginx/admin.conf`、Backend 管理会话默认配置、示例环境变量与管理运维文档。
- 不改变公开认证接口契约、短信供应商配置、用户端会话、支付、面试、资料或桌面助手链路。
- 不新增数据库迁移，不持久化新的服务端个人数据；手机号记忆完全由管理员浏览器自愿控制。
