## ADDED Requirements

### Requirement: Backend 重建后管理代理自动恢复
系统 SHALL 使独立管理前端在 Backend 容器地址变化后重新解析服务地址，且 SHALL NOT 要求重启用户端网站或改变公开 API 契约。

#### Scenario: Backend 容器地址发生变化
- **WHEN** Backend 容器被安全重建并通过同一 Compose 服务名重新上线
- **THEN** 管理前端在 DNS 有效期内把后续 API 请求发送到新地址，用户端构建物保持不变

### Requirement: 管理员可选择记住手机号
系统 SHALL 允许管理员选择在当前浏览器保存规范化手机号，并 SHALL NOT 因此保存短信验证码、管理令牌或 MFA 信息。

#### Scenario: 选择记住手机号后再次打开登录页
- **WHEN** 管理员选择记住手机号并完成一次短信发送或登录后再次打开管理登录页
- **THEN** 登录页预填该手机号，验证码保持为空

#### Scenario: 取消记住手机号
- **WHEN** 管理员取消记住手机号
- **THEN** 系统立即删除本地手机号偏好且不清除当前管理会话

### Requirement: 短信发送反馈可操作
系统 SHALL 遵守短信接口返回的冷却时间，并 SHALL 区分代理暂不可用、验证码业务错误和普通请求错误。

#### Scenario: 短信发送成功
- **WHEN** 短信接口返回冷却秒数
- **THEN** 发送按钮在该时间内保持禁用并显示剩余秒数，到期后自动恢复

#### Scenario: 管理代理暂不可用
- **WHEN** 管理 API 返回 502、503 或 504
- **THEN** 页面提示后台连接暂时不可用且无需清除已填手机号或现有管理会话

### Requirement: 日常会话与近期验证分离
系统 SHALL 默认允许管理会话覆盖一个 8 小时工作日，并 SHALL 对高风险操作继续要求不超过 5 分钟的近期验证。

#### Scenario: 普通管理查询持续工作
- **WHEN** 管理员在管理会话有效期内执行获授权的普通查询
- **THEN** 系统接受现有会话且不要求重新输入手机号

#### Scenario: 高风险验证已过期
- **WHEN** 管理会话仍有效但近期验证窗口已过期，管理员执行高风险动作
- **THEN** 系统要求重新验证且不因较长管理会话绕过该要求

### Requirement: 用户端链路保持隔离
系统 SHALL 将本次改动限制在 Admin、管理会话配置和管理代理，不改变用户端登录、支付、资料、面试或桌面助手行为。

#### Scenario: 仅构建管理优化
- **WHEN** 本次变更完成构建与测试
- **THEN** 用户端公开路由和现有 API 契约测试继续通过
