## Context

生产管理前端是独立 Nginx 容器。当前 `proxy_pass http://backend:8000` 在 Nginx 启动时解析一次 Docker 服务地址，Backend 容器重建并更换 IP 后，管理端仍访问旧地址并返回 502；用户端 Nginx 是否同时重建与该问题无关。管理登录页同时只在内存中保存手机号，短信发送冷却没有倒计时，会话默认 30 分钟，导致后台维护过程中重复输入和重复发送。

## Goals / Non-Goals

**Goals:**

- Backend 容器地址变化后，管理代理自动重新解析服务地址。
- 管理员可自愿在当前浏览器记住手机号，验证码和管理令牌继续按原安全边界处理。
- 短信请求失败时区分网关不可达与验证码业务错误，并落实服务端返回的冷却时间。
- 管理会话覆盖一个正常工作日，同时高风险动作仍要求短时近期验证。
- 通过独立测试证明用户端构建和公开 API 契约未改变。

**Non-Goals:**

- 不修改阿里云短信参数、普通用户登录、管理员 RBAC 或 TOTP/短信校验流程。
- 不把管理令牌改为长期本地存储，不绕过高风险动作二次验证。
- 不在本次任务中修改或重启线上服务。

## Decisions

1. 管理 Nginx 使用 Docker 内置 DNS `127.0.0.11` 和变量形式的 upstream，使每次代理连接可按短 TTL 重新解析 `backend`。相比固定 upstream，这不依赖管理容器跟随 Backend 一起重建；相比把宿主机地址写死，也保留 Compose 服务发现。
2. 手机号偏好保存到独立 localStorage 键，必须由“记住手机号”复选框控制；管理令牌继续保存在 sessionStorage。相比永久登录，这仅减少手机号输入，不扩大令牌泄露窗口。
3. 管理会话采用 8 小时空闲有效期：每次成功的普通管理认证原子更新 `last_used_at_ms` 和 `expires_at_ms`，持续使用时滑动续期；闲置超过 8 小时、管理员停用或授权版本变化后仍立即失效。近期高风险验证仍为 5 分钟且不随普通查询续期。两个窗口分别解决日常后台连续性和敏感操作安全，不能相互替代。
4. 将 502/503/504 映射为管理代理暂不可用提示，其他业务错误继续采用服务端 detail。登录页依据 `cooldownSeconds` 禁用发送按钮并倒计时，避免重复请求。
5. 回归测试覆盖 Nginx 配置契约、登录偏好纯函数、API 错误映射和 Backend 会话 TTL；不引入新依赖或数据库迁移。

## Risks / Trade-offs

- [变量形式 `proxy_pass` 的 URI 拼接错误] → 显式追加 `$request_uri` 并用配置契约测试验证完整路径。
- [浏览器共享设备暴露管理员手机号] → 默认仅保存掩码之外的手机号在管理员明确选择的本地浏览器中，并提供取消记忆立即清除。
- [滑动会话扩大普通管理会话窗口] → 令牌仍为标签页会话存储；只有成功认证的后台请求才续期，闲置 8 小时、授权版本变化或停用仍会撤销，高风险操作继续受独立的 5 分钟近期验证限制。
- [Docker DNS 短暂不可用] → 使用短 TTL 和明确的 502/503/504 提示；不降级到旧 IP 或绕过后端。

## Migration Plan

1. 本地完成 Admin、Backend 和 Nginx 配置测试。
2. 后续经用户明确批准部署时，先发布 Backend 的默认配置，再仅重建 Admin 容器；不重建 Web 或桌面助手。
3. 发布后以合成管理员账号验证发送验证码、登录、刷新及 Backend 单容器重建后的代理恢复。
4. 如有异常，回滚 Admin/Backend 镜像；无数据库迁移需要回滚。
