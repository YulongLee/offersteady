## Context

支付渠道配置服务当前直接使用 `serialization.load_pem_*` 校验密钥，而支付宝支付适配器自身会为无头尾的 Base64 文本补齐 PEM。运营人员从支付宝开放平台直接复制密钥时，保存阶段因此会误报，且原始文本已经被加密保存为草稿。

## Goals / Non-Goals

**Goals:**

- 接受支付宝直接复制的 PKCS#8/PKCS#1 RSA 私钥和 SubjectPublicKeyInfo RSA 公钥文本。
- 同时保持完整 PEM 输入兼容。
- 在加密存储前统一转换成规范 PEM，避免校验与运行时解释不一致。
- 不在响应、错误和日志中暴露密钥正文。

**Non-Goals:**

- 不支持支付宝公钥证书模式或从 X.509 证书中提取公钥。
- 不自动判断“应用公钥”和“支付宝公钥”的业务身份；真实身份仍由支付宝签名验收确认。
- 不修改微信支付配置格式、订单状态或回调协议。

## Decisions

1. 规范化放在 `PaymentChannelService.save` 的服务端边界。相比只放宽前端校验，这能覆盖所有管理 API 调用方，并保证数据库始终保存可直接使用的 PEM。
2. 对无 PEM 头尾输入先移除空白并严格 Base64 解码，再用密码学库解析 DER；对已有 PEM 直接解析。成功后将私钥重序列化为未加密 PKCS#8 PEM，将公钥重序列化为 SubjectPublicKeyInfo PEM。
3. 校验解析出的对象必须是 RSA 密钥。相比只检查 `MII` 前缀或字符集，这能拒绝损坏内容、EC 密钥和证书正文。
4. 已加密保存的原始 Base64 草稿在下次保存时也进入同一规范化流程，因此运营人员部署后可以直接再次保存，无需再次粘贴。

## Risks / Trade-offs

- [风险] 证书模式材料继续被拒绝 → 错误提示明确要求 RSA2 应用私钥和支付宝公钥，不把证书静默当作公钥。
- [风险] 重新序列化改变文本外观 → 密钥数学内容不变，并通过签名/验签单元测试证明兼容。
- [风险] 错误处理意外泄露密钥 → 只返回字段级固定错误，不包含解析异常或输入摘要。

## Migration Plan

先部署后端兼容逻辑和后台提示。现有完整 PEM 配置无需迁移；现有 Base64 草稿由运营人员点击“保存配置并校验”触发规范化。回滚只需恢复旧代码，已经规范化为 PEM 的配置仍可被旧版本读取。
