## Context

国际服线上基线为 20260929-global-reliability-2，国服新增功能仍在混合工作区中。通用部署脚本从当前源目录全量构建，缺乏可验证的源包合同。已有专用发布采用四组件增量镜像及运行时配置保留；不能用老通用脚本替换该流程。

## Goals / Non-Goals

**Goals:** 核验源包、回归结果与镜像基线；让历史镜像保留范围可解释、可复查；消除已确认的测试假失败。

**Non-Goals:** 不自动部署，不添加收费功能，不改变实时链路，不删除生产数据，不把历史镜像规划当作磁盘自动清理器，不以通过检查代替人工审批和在线面试检查。

## Decisions

1. 使用 Python 标准库实现离线校验。清单包含 edition、release、源文件 SHA256、完整指定源码根、组件基线镜像 ID、测试证据文件哈希及通过状态。核验文件必须位于源包内且非符号链接；不接收 .env 或私钥文件。任意源文件变化、遗漏、新增文件均失败。工具不自动把失败结果标记为通过，不为当前混合工作区自动生成已批准清单。
2. 旧通用脚本在任何修改前要求有效清单，且限定适用服务集合。专用增量发布的清单用于自己的校验流程，不能误喂给老脚本。保留通用脚本既有后续流程，但明确其仍不能替代空闲检查、配置保留及回滚。
3. 保留策略只生成 JSON 计划：Docker 只读采集镜像与所有运行/停止容器的引用；每个国际服组件保留最近两个不同镜像，额外保护容器引用及显式回滚引用。不删除任何镜像；不处理卷、源目录、日志或数据。混合标签/无法确认创建时间/未知组件/悬空镜像保守保留。替代方案自动 prune 无法解释影响范围，故不采用。
4. 本轮测试记录当前国际服已部署基线：新增当前静态与客户端内容/套餐对齐断言，不能通过移除全部断言或跳过来掩盖回归。发现历史首页 Spec 提及反馈展示而当前未挂载，须在交付文档记录差异，不能因此擅自重做页面或修改历史 Spec；独立反馈组件和原数据测试仍保留。

## Risks / Trade-offs

- 人工填写“通过”不是可信测试执行器 → 清单验证证据哈希并要求已审查证据；它提供防误部署而非防恶意签名保证。
- 只校验文件不验证生产负载 → 发布仍必须单独查空闲、服务基线和配置，真实设备/并发验收仍列为待办。
- 容器或镜像在计划之后变化 → 计划无执行功能，任何人工清理前必须重新采集并复核；本轮不清理。
- 保守保护使保留量超过两版 → 业务连续性优先，报告保留原因。

## Migration Plan

本地测试脚本和前端回归，无数据库迁移或线上服务切换。部署工具只有被下次显式使用时生效；不将当前混合源码发往线上。后续新功能需独立批准的 Global 变更、套餐规则和供应商验证。

## Open Questions

国际服新功能的收费、免费次数、模拟面试语言及日配额时区另行确认，不阻塞本变更。真实设备连续面试验收需要用户参与。
