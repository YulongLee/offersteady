## Context

“积分与会员”页面当前把聚合后的全部积分明细直接展开。随着用户流水增加，列表会持续拉长页面并挤压支付保障与订单内容。前端已经负责将消费流水按业务类型聚合并按最新时间排序，本次只调整展示容器，不改变账本数据或聚合规则。

## Goals / Non-Goals

**Goals:**

- 积分明细默认占用约五条标准记录的高度。
- 超出五条后在明细区域内部纵向滚动，并保留全部记录。
- 鼠标、触控板、触屏和键盘均可操作滚动区域。
- 桌面端和小屏设备保持一致、稳定的布局。

**Non-Goals:**

- 不对账本接口增加分页或截断。
- 不修改积分排序、消费聚合、余额计算或会员权益。
- 不修改支付渠道、后端、数据库或桌面助手。

## Decisions

### 使用 CSS 限高而不是截取数据

组件继续渲染 `ledgerEntries` 的全部结果，专用样式类使用五条标准记录高度作为最大高度，并在溢出时启用纵向滚动。这样不会让第六条之后的记录从 DOM 或辅助技术中消失，也不会引入新的服务端状态。

曾考虑只渲染前五条并增加“查看更多”，但这会增加展开状态、额外操作和历史记录不可直接搜索的问题，因此不采用。

### 将列表标记为可访问的滚动区域

积分明细列表使用带中文名称的 `region`；记录超过五条时加入键盘焦点，使方向键和 Page Up/Page Down 可以滚动。容器使用 `overscroll-behavior` 限制滚动串联，并保留清晰的焦点样式。

### 保持记录内容自然高度

不裁剪描述或时间文本。容器高度按现有标准记录的五行高度设置；如果用户字体或内容换行使单条记录更高，可视区域可能显示不足五条完整记录，但完整内容仍可滚动访问。该取舍优先保证信息完整与字号可访问性。

## Risks / Trade-offs

- **不同字体或长描述导致可视条数略少于五条**：不固定裁剪单行内容，以免丢失信息；通过标准高度变量保持常规场景为五条。
- **嵌套滚动区域可能被忽略**：保留当前总条目提示，并让溢出列表可聚焦且显示浏览器滚动条。
- **移动端滚动手势影响整页**：使用触摸惯性滚动和滚动边界约束，确保手势在列表边界后仍符合平台预期。
