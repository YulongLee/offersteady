## Why

同一用户打开新面试时，旧的 live session、桌面发布通道和网页轮询可能继续运行，既造成实时转录延迟和无效请求，也会让设备在多个面试之间被静默切换。需要在准备阶段让用户明确选择继续旧面试或结束旧面试，并由后端统一执行单活切换。

## What Changes

- 准备面试时检查当前账号是否存在另一场进行中的面试，并在绑定设备和开始面试前展示阻断式选择窗口。
- 支持继续上一场面试，或明确结束上一场后继续准备当前面试。
- 后端提供权威的冲突查询和幂等接管能力，并拒绝绕过确认直接绑定设备或启动第二场 live session。
- 接管时结束旧 session、失效旧设备绑定和发布器、关闭旧 ASR 运行时，使旧网页停止心跳、订阅和轮询。
- 桌面助手把绑定代际纳入连接身份，切换后立即停止旧发布链路并连接新 session。
- 保留历史面试、资料选择、回答记录和现有设备授权，不改变其他产品功能。

## Capabilities

### New Capabilities

- `single-active-interview-session`: 定义用户级单活面试冲突检测、显式接管、旧链路回收和网页交互行为。

### Modified Capabilities

无。

## Impact

- 后端 session 与 realtime-speech 服务新增冲突查询、接管和并发防护 API。
- 网页面试准备页新增冲突窗口和连接门禁。
- 桌面助手连接身份增加绑定代际，避免复用旧发布进程。
- 增加后端与网页回归测试；不新增外部依赖，不迁移现有数据库结构。
