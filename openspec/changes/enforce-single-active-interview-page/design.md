## Context

当前系统已经保证同一用户只有一个 live 面试 session，但 Web 实时消费者没有页面实例身份。用户打开新标签页或进入新面试后，旧页面仍可能继续发送 heartbeat、SSE 订阅和兜底轮询，造成无效请求风暴并干扰桌面助手的活跃 session 判断。

## Goals / Non-Goals

**Goals:**

- 每个用户同一时刻只有一个可写、可订阅实时数据的面试页面。
- 新页面可以明确接管，旧页面立即停止实时请求并保留为只读页面。
- 同浏览器快速通知，跨浏览器由后端权威校验。
- Redis 部署下的接管操作保持原子性。

**Non-Goals:**

- 不改变桌面音频采集、ASR、截图和回答模型实现。
- 不删除历史面试或旧页面已经显示的转写内容。
- 不持久化页面实例以外的新增用户数据。

## Decisions

### 用户级租约由实时仓储原子接管

live heartbeat 携带随机 `pageInstanceId`。仓储按用户查找当前最高 `leaseGeneration`：同一页面续租时保持代次，新页面接管时递增代次。Redis 仓储在现有分布式锁内完成读取、递增和写入。

替代方案是仅在 Service 中先读后写，但多实例并发时可能产生两个相同代次，因此不采用。

### BroadcastChannel 只负责快速通知，后端租约是最终依据

同一浏览器标签页通过用户级频道广播 `claim`。旧页面收到后立即暂停。跨浏览器、频道不可用或消息丢失时，heartbeat 和 SSE 的租约校验会返回终止错误。

替代方案是只使用 BroadcastChannel，但无法覆盖不同浏览器或设备，因此不采用。

### 被替换页面保留内容并进入只读状态

页面被替换后终止 SSE、heartbeat、轮询以及未完成的回答和截图请求，禁用开始、快答、截图和文本输入，但不跳转、不清空已显示内容。

替代方案是自动跳转首页，但会打断用户查看刚才的记录，也不利于解释为何页面停止，因此不采用。

### 终止错误不自动重连

租约不匹配使用 HTTP 409；session 已结束或被新 session 替换使用 410；SSE 已建立后失效发送 `revoked`。前端将 404、409、410 视为终止状态，不再进入退避重连。

## Risks / Trade-offs

- [新页面误打开会接管旧页面] → 页面明确显示“已在其他页面继续”，旧页面内容仍可查看。
- [浏览器刷新会生成新页面实例] → 刷新被视为一次安全接管，旧连接由后端终止。
- [旧版前端未携带租约] → 当用户已有活跃租约时拒绝无身份 SSE，部署时应同步更新前后端。
- [租约自然过期] → 当前页面下一次 heartbeat 可继续以相同实例重新取得租约。

## Migration Plan

1. 先发布同时兼容 preparation heartbeat 和旧数据快照的后端结构。
2. 同一版本发布携带页面实例身份的 Web 前端。
3. 观察 409、410、SSE revoked 和每用户并发 stream 数量。
4. 回滚时可回退前后端版本；新增心跳字段均有默认值，不需要数据迁移。
