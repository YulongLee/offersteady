## Context

当前 `CompanionApp` 会把 Electron 提供的屏幕缩略图直接写入主页面的 `preview-row`，手动预览获取的图片或媒体流也复用同一区域。该区域同时放置截屏锁定后的取消按钮，因此不能只删除 JSX，还需迁移取消入口并明确预览生命周期。

## Goals / Non-Goals

**Goals:**

- 主页面不常驻显示任何屏幕画面。
- 手动点击预览后立刻获得弹层反馈，并在其中展示最新画面、加载状态或错误。
- 弹层关闭时停止临时媒体流；正式截屏任务仍由既有锁和取消机制管理。
- 键盘快捷键及网页任务不得意外打开本地预览弹层。

**Non-Goals:**

- 不改变 Electron 主进程的截图格式、图片质量或上传协议。
- 不改变屏幕权限申请逻辑、快捷键配置和网页端截图回答流程。
- 不新增截图或预览内容持久化。

## Decisions

1. 使用 `isScreenPreviewDialogOpen` 独立控制弹层可见性。手动按钮先打开弹层并显示加载状态，再异步获取画面，避免用户等待期间没有反馈。备选方案是在获取成功后才打开弹层，但这会延续“点击后没有反应”的问题。
2. 保留现有图片和媒体流两种预览适配路径，将其渲染节点移动到 modal；关闭时调用统一的 `closeScreenPreview` 停止媒体轨道并清理可见状态。Electron 预生成的 source thumbnail 只可作为弹层初始画面，不在主页面展示。
3. 截屏锁定时复用屏幕控制区的操作按钮作为“取消当前截屏”。备选方案是另设常驻状态行，但会再次引入用户要求移除的冗余区域。
4. 正式截屏的锁状态监听不修改弹层状态；只有 `previewScreen` 这个手动事件处理器打开弹层，从而保证快捷键与远程触发不弹窗。

## Risks / Trade-offs

- [关闭弹层时视频流仍占用屏幕捕捉资源] → 所有关闭路径统一停止 tracks，并在组件卸载时继续执行清理。
- [异步获取完成时用户已经关闭弹层] → 预览结果可以更新本地缓存，但不重新打开弹层；媒体流路径检测弹层意图并及时停止。
- [取消按钮迁移后不够显眼] → 锁定时使用明确的“取消当前截屏”文案和警示样式，占用原预览按钮的固定位置。
- [弹层覆盖小尺寸窗口] → 使用受视口约束的宽高、`object-fit: contain` 和可滚动内容区。
