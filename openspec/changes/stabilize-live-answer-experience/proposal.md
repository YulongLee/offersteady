## Why

实时面试中的回答展示、快答、截屏回答和自动问题触发没有形成一致、可信的反馈闭环：流式正文看起来断续卡顿，操作缺少明确的按钮与进行中状态，自动问题可能停在等待确认，答案区域还可能继续显示旧问题。用户无法判断系统是否已经收到操作、正在回答哪个问题，直接影响现场可用性。

## What Changes

- 让实时回答以稳定的渐进展示更新，避免逐个微小分片造成视觉抖动、正文闪烁或占位文案反复出现，同时保持可停止和失败恢复能力。
- 把“快答”和“截屏回答”呈现为明确的主要操作按钮，并提供按下、处理中、成功、失败和防重复点击反馈。
- 对满足最终、完整、唯一和系统声道条件的面试官问题自动开始回答；只有低置信度或不完整问题才保留人工确认，不让正常问题停在“需要再按回答”。
- 统一当前问题、活动回答任务、答案分页和截图任务的选择规则；新任务必须立即成为当前答案，旧任务完成或迟到事件不得把界面切回旧问题。
- 快答、自动回答、手动回答和截屏回答使用同一套“请求标识 + 当前任务归属 + 单调状态”前端规则，避免竞态覆盖。
- 使用合成问题和截图进行前后端、组件与浏览器回归测试；不读取或保存真实用户面试内容。

## Capabilities

### New Capabilities

- `stable-live-answer-interaction`: 定义实时回答平滑展示、明确操作反馈、可信自动触发，以及当前问题与答案任务不会被旧事件覆盖的行为。

## Impact

- 主要影响 `apps/web` 的实时工作台、回答状态归并、SSE/流式更新、快答和截屏回答操作及其样式与测试。
- 可能影响 `apps/backend` 的实时问题确认与回答事件幂等/排序逻辑；不改变账号、资料、支付或积分费率。
- 截图、问题与回答仍属于敏感数据；测试只使用合成内容，日志不得新增完整问题、回答或截图正文。
- 部署需要 Web 与 Backend 回归测试、生产构建、Git 提交和线上健康检查；不得重启 PostgreSQL 或 Redis，也不得中断无关线上服务。
