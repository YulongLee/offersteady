## Why

实时面试中的回答展示、快答和截屏回答没有形成一致、可信的反馈闭环：流式正文看起来断续卡顿，操作缺少明确的按钮与进行中状态，语音识别还可能在用户没有操作时自动生成答案，答案区域也可能继续显示旧问题。用户无法判断系统是否已经收到操作、正在回答哪个问题，直接影响现场可用性。

## What Changes

- 让实时回答以稳定的渐进展示更新，避免逐个微小分片造成视觉抖动、正文闪烁或占位文案反复出现，同时保持可停止和失败恢复能力。
- 把“快答”和“截屏回答”呈现为明确的主要操作按钮；截屏按钮文案保持固定，处理反馈由回答区或处理弹窗承载，并继续通过禁用按钮防止重复点击。
- 语音识别只记录对话并整理可供快答使用的问题，不自动调用回答模型；只有用户点击快答或截屏回答才生成答案。
- 统一当前问题、活动回答任务、答案分页和截图任务的选择规则；新任务必须立即成为当前答案，旧任务完成或迟到事件不得把界面切回旧问题。
- 快答、手动回答和截屏回答使用同一套“请求标识 + 当前任务归属 + 单调状态”前端规则，避免竞态覆盖。
- 使用合成问题和截图进行前后端、组件与浏览器回归测试；不读取或保存真实用户面试内容。

## Impact

- 主要影响 `apps/web` 的实时工作台、回答状态归并、SSE/流式更新、快答和截屏回答操作及其样式与测试。
- 可能影响 `apps/backend` 的实时问题确认与回答事件幂等/排序逻辑；不改变账号、资料、支付或积分费率。
- 截图、问题与回答仍属于敏感数据；测试只使用合成内容，日志不得新增完整问题、回答或截图正文。
- 部署需要 Web 与 Backend 回归测试、生产构建、Git 提交和线上健康检查；不得重启 PostgreSQL 或 Redis，也不得中断无关线上服务。
