## ADDED Requirements

### Requirement: 管理员安全维护支付渠道配置
系统 SHALL 允许具备 `payments.manage` 权限且完成近期 MFA 的管理员分别保存微信和支付宝配置草稿，并 MUST 使用服务端加密密钥加密敏感字段。读取接口 MUST NOT 返回完整密钥、私钥、API v3 密钥或证书正文。

#### Scenario: 保存支付宝配置草稿
- **WHEN** 授权管理员提交支付宝应用身份、密钥、商户身份和回调地址并提供原因与幂等键
- **THEN** 系统加密敏感字段、保存新配置版本、返回掩码状态并记录不含明文的审计事件

#### Scenario: 普通管理员查看支付设置
- **WHEN** 缺少 `payments.manage` 权限的管理员请求修改支付配置
- **THEN** 系统拒绝修改且不返回任何可用于恢复商户密钥的信息

#### Scenario: 编辑时不替换已有密钥
- **WHEN** 管理员更新公开字段但敏感字段保持为空且未请求清除
- **THEN** 系统保留已有加密密钥并只更新明确提交的字段

### Requirement: 支付渠道独立验证和启停
系统 SHALL 分别维护微信与支付宝的配置完整性、验证状态和启用状态，并 SHALL 允许零、一或两个渠道同时启用。配置不完整或加密材料不可解析时 MUST 拒绝启用。

#### Scenario: 只开启支付宝
- **WHEN** 支付宝配置完整且验证通过、微信保持关闭
- **THEN** 用户端只获得支付宝渠道且微信支付不可创建订单

#### Scenario: 同时开启两个渠道
- **WHEN** 微信与支付宝配置均完整且管理员分别启用
- **THEN** 用户端同时获得微信和支付宝选项，任一渠道失败不自动伪装成另一渠道订单

#### Scenario: 配置不完整时尝试启用
- **WHEN** 管理员启用缺少私钥、商户身份或 HTTPS 通知地址的渠道
- **THEN** 系统拒绝启用、保持原状态并返回不含敏感值的字段级错误

#### Scenario: 关闭已有渠道
- **WHEN** 管理员关闭一个已经启用的渠道
- **THEN** 系统阻止该渠道创建新订单，但继续处理关闭前订单的合法回调和状态查询

### Requirement: 支付配置变更可审计
系统 MUST 对支付配置保存、验证、启用、禁用和敏感字段清除记录操作者、时间、原因、渠道、配置版本及前后状态，且 MUST NOT 把敏感值写入审计或应用日志。

#### Scenario: 管理员轮换微信密钥
- **WHEN** 管理员提交新的微信商户私钥或 API v3 密钥
- **THEN** 审计记录字段已轮换和配置版本变化，但不记录旧值、新值或可逆摘要
