## Context

国服现有用户接口接受 `search`、`limit`、`offset`，按用户名与用户 ID 模糊查询。旧前端未传 search；通用操作面板只能选择当前页。国际服已有独立会员面板，本次不改动。

## Goals / Non-Goals

**Goals:** 全库分页搜索、清晰选择目标、可确认且不可误重放的积分调整；通过现有管理权限和服务端账本命令操作。

**Non-Goals:** 不更改积分价格、余额计算、账本、面试、助手或国际服；不增加手机号搜索，不加载全部用户到浏览器。

## Decisions

1. 增加独立国服用户面板和 `adminApi.listUsers`，复用既有搜索接口。按回车/按钮查询，避免每次输入请求或前端只筛当前页。
2. 面板自行管理分页、加载、请求序号和目标选择。新查询/翻页立即清除旧目标与列表，晚到响应不得覆盖新结果。
3. 每行提供“调整积分”，表单显示用户名、ID 和脱敏手机号。用户必须明确选择后操作；积分为非零整数、原因为至少 6 字；确认对话框包含目标和带符号数量。
4. 同一操作保留幂等键用于网络不确定后的重试，提交中同步锁定，已成功表单清空。编辑目标/原因/数量视为新操作。现有封禁、恢复、时长入口保留并按各自权限显示。
5. 仅发布基于线上国服 Admin 源码的增量构建。保留现有静态资源、Nginx 配置与回滚镜像，单独切换 Admin，禁止顺带重建 Backend/Web。

## Risks / Trade-offs

- 同名误操作 → 显示用户 ID 与手机号提示，未选中不可提交，二次确认。
- 搜索结果过期 → 请求序号与卸载保护，失败清空旧列表，重新查询不保留旧目标。
- 调整成功但刷新失败 → 写入与刷新错误分离，明确成功消息，不提示再次调整。
- 基线差异 → 对比生产源码与本地，打包只携带本次改动，不覆盖国际服或其他功能。

## Migration Plan

合成数据回归、国服/国际服构建、严格 Spec 校验后，验证线上接口契约和发布基线。只部署国服 Admin 静态产物；检查 HTTPS、资产、代理和其他容器身份未变。回滚仅切回旧 Admin 镜像，无数据库迁移。

## Open Questions

无；用户已确认本轮范围和测试通过后上线。

## 2026-09-27 注册时间增量

- 用户要求“用户与权益”展示注册时间。列表新增“注册时间（北京时间）”列，选择用户后的身份核对区也显示同一时间；字段来源仅为现有接口 `created_at_ms`，不可用最后登录时间代替。
- 固定 `Asia/Shanghai` 时区及 `YYYY-MM-DD HH:mm:ss` 格式，不随管理员电脑时区变化。缺失、非法或无效时间显示“—”，不伪造注册日期、不暴露原始毫秒数。
- 保持现有提交式搜索、50 条分页、身份选择、权限和幂等扣费命令不变；不为显示时间增加请求或依赖。窄屏保留表格内部横向滚动。
- 新增用户统计只读核对：默认 30 天日快照汇总，不是累计注册人数；自然日滚动和尚未生成的日快照会影响该值。本次不静默修改范围、快照任务或展示口径。
- 本增量已先本地自测，用户随后于 2026-09-27 明确授权部署；发布只更新国服 Admin，保留旧镜像、旧哈希资源和 Nginx 配置，验证其他业务容器未重启。
