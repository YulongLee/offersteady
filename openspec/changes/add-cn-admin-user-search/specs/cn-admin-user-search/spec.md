## ADDED Requirements

### Requirement: 国服用户搜索
管理页面 SHALL 按提交的用户名或用户 ID 向服务端查询并分页，不得仅过滤当前页；SHALL 不在每次按键时请求。

#### Scenario: 模糊搜索与分页
- **WHEN** 管理员输入关键词并回车或点击搜索
- **THEN** 请求使用去除两端空白且 URL 编码的关键词，从第一页查询；后续翻页保留关键词，清空搜索恢复全量分页列表

#### Scenario: 过期响应和失败
- **WHEN** 新查询先返回、旧查询晚返回，或新查询失败
- **THEN** 页面不展示旧查询结果或保留旧操作目标，失败提供重试入口

### Requirement: 显式用户积分调整
系统 SHALL 从搜索结果明确选择用户后调整积分，显示用户名、ID 和脱敏手机号，并保留操作原因、权限与二次确认。

#### Scenario: 同名用户
- **WHEN** 管理员选择同名结果中的一名用户
- **THEN** 表单和确认消息显示该用户唯一 ID、脱敏手机号和实际增减积分，命令只发往该用户 ID

#### Scenario: 输入及权限校验
- **WHEN** 无 billing.adjust 权限或积分不是非零整数或原因少于六字
- **THEN** 禁止提交积分调整；有 billing.adjust 而无 users.suspend 的管理员仍可调整积分但不可封禁

#### Scenario: 重复点击和网络重试
- **WHEN** 操作提交中重复点击，或相同内容因网络不确定而重试
- **THEN** 提交中只发送一次请求；重试使用相同幂等键，成功后清空表单并刷新结果

#### Scenario: 搜索改变后操作
- **WHEN** 管理员搜索其他用户或翻页
- **THEN** 清除原选中用户和表单，不得对不可见旧目标继续提交

### Requirement: 发布隔离
本次变更 SHALL 保持服务端账本、鉴权、审计接口及面试行为不变，SHALL 只部署国服管理前端。

#### Scenario: 国服独立更新
- **WHEN** 测试通过并发布本变更
- **THEN** Backend、Web、数据库及助手无需重启或升级，国际服会员入口保持原行为

### Requirement: 展示用户注册时间
国服“用户与权益” SHALL 在列表及已选用户身份核对区展示现有 `created_at_ms` 对应的注册时间，固定为北京时间，且 SHALL NOT 增加查询、改变搜索分页或权益调整语义。

#### Scenario: 真实注册时间及跨日
- **WHEN** 用户记录有有效的毫秒注册时间，即使管理员电脑使用其他时区或记录另有最后登录时间
- **THEN** 显示注册时间的 `Asia/Shanghai` 日期及 `HH:mm:ss`，标明北京时间，选中后仍显示同一注册时间

#### Scenario: 时间不可用
- **WHEN** 记录缺失注册时间，或时间为非法值、零、负数、超出有效范围
- **THEN** 时间位置显示“—”，不显示 Invalid Date、不使用当前时间或最后登录时间冒充，其他行与操作保持可用

#### Scenario: 注册时间增量本地验收
- **WHEN** 本次时间展示完成开发及测试
- **THEN** 在获得新的部署授权前不切换线上服务，不修改用户数据或运营快照
