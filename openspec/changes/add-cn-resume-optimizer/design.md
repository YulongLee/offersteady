## Decisions

### 1. 基于实际国服组件做最小移植

使用实际运行 CN Backend 镜像的完整源/Prompt/迁移/完整 OpenAPI 和实际 Web 构建作为基线；与已发布 Global optimizer 做逐文件、逐接入节点增量。既有注册、依赖、生命周期和资料删除函数仅最小接入，不用 Global 整文件覆盖国服。代码默认关闭专属 CN 开关；本地显式启用，用户批准的国服生产发布也仅显式启用此开关，其他运行配置保持。Global 的开关、UTC 额度、无积分政策和已部署源完全保持。

替代方案：直接合并国际服目录。拒绝，因为区域会员、支付、模型和已发布性能补丁不同，目录版本字符串不能代表运行组件。

### 2. 免费额度优先，报价确认后原子创建

权威有效时间会员使用 CN 现有 starts/ends、active/revoked 及管理员授予权益语义，包含 1 天/周/月，不沿用其他功能的最短套餐阈值；纯积分余额不算会员。每日额度按服务端 Asia/Shanghai 日期独立记录，次数为 3；占用和成功使用均计入当日次数，第三次用完后才报价积分，失败仅释放对应创建日的一次。

先返回服务端免费/积分报价，包含业务日、重置时刻、100 积分费率/当前可用余额和报价状态。用户必须明确确认当次服务端报价；创建时重新算会员、日额度和余额，并与确认比较。免费被抢占、跨日或会员变化不能静默改成付费；返回报价已变化让用户再次确认。幂等重放先返回既有 job，不因午夜、会员到期或现价而重新收费。

使用既有 billing-user 事务锁，免费日额度占用或实际 -100 积分流水与 usage reserved/job 插入必须在同一 PostgreSQL 事务内完成；锁顺序为全局容量锁（需要时）→独立 optimizer-owner 锁→仅金融操作 billing-user 锁→源行锁。所有优化状态操作共用独立 owner 锁；已完成稿编辑/另存不持钱包锁做 OSS/Parser I/O，仍保持 revision、source share 和删除串行屏障。实际创建扣除确保所有旧钱包消费者立即看到扣后余额；可用余额沿用账本总和减既有回答/索引未结预留，而不是引入旧消费者无法识别的新预留。余额不足、队列满、源失效或 job 写入失败不能遗留扣费/次数。100 积分固定单次，不按分数/Token/修改/导出额外收费。wire、账本类型及锁顺序见合同，不得分两个事务声称原子。

替代方案：前端判断免费或任务建好再扣积分。拒绝，因为并发、重试、其他功能消费和跨日会导致超额或孤儿收费。

### 3. 持久计费状态与任务状态共提交

创建成功记录 `daily_pass_free|points` 原支付方式；付费写不可变 `resume_optimizer_charge=-100`，usage reserved 表示未交付而非另一份钱包预留。完整有效结果成为 completed 时，同事务将 usage settled，不二次扣分。Provider 失败、超时、取消、队列过期、中断或源删除使未交付任务终止时，同事务释放原日免费预留或写唯一 `resume_optimizer_refund=+100` 并 released，exactly-once。completed 后删除/取消/下载失败不退已完成优化费用；编辑、下载和另存不再查生成资格或重新收费，会员到期仍可操作未删完成稿。

跨日退免费只释放创建日，不能给当前日加一次；积分原路退款，不能发额外赠送。完成与取消/删除竞态采用 claim/revision/状态条件更新，先赢的终态和金融状态一致，迟到模型不能重扣或复活。迁移读取实际旧约束后仅 OR 两种精确新 kind/金额，保留全部旧合法 kind（含未知扩展）、符号规则与 immutable trigger；缺失旧约束明确失败，不用静态名单覆盖。

替代方案：异步补偿账本。拒绝，首版现有 PostgreSQL 可实现同事务，无须引入独立复杂补偿服务。

### 4. 独立有界执行和受控输入

每账号 1 个未完成、全服务最多 8 个未完成/1 个执行请求；独立 worker/provider，不使用面试回答执行池。沿用 Global 90 秒 Provider 超时、15 分钟排队寿命和中断失败释放策略，不自动盲重试。输入 ready/source version/owner 严格校验，最多简历 40,000、JD 12,000、岗位 120、稿 60,000 字符，artifact 2 MiB；边界不足明确失败不截断。

受控 `HTMLParser` 只在 optimizer 输入副本中把 MinerU table/tr/td/th/tbody/thead/tfoot/br 转为单元格有分隔文本，保留全部文字、数字、日期、联系方式、实体和顺序。未知/非法/主动资源 markup 在预留和模型前失败，不执行/抓取/静默删内容；原文件、Parser artifact 和现有快照不改。展示、引用验证、模型和保守局部替换共用同一规范化副本。

替代方案：重跑 Parser 或复用实时队列。拒绝，因为增加无关耗时/收费和面试资源竞争。

### 5. 中文诊断、事实约束、真实文件和明确另存

新增独立中文 Prompt/evals。源文引用及保守 edit quote 必须真实存在；服务器计算参考分，0–100、无 JD 不计岗位匹配，解释/提示中文、原文引用和事实稿可保留原语言。JD 不能成为候选人事实；缺少数字、技能、经历、学历只给待补充项。沿用数字/日期/联系方式/实体保真校验；允许普通中文动词/句式真实改写，不能逐字锁死全部中文而仅改排版，新增中文机构/学历/技术词、否定和责任升级守卫正负评测。明确语义事实仍须专属 Prompt/evals 与用户核实，静态规则不能证明全部事实。

纯文本/Markdown 编辑加 revision 乐观锁；原文、AI 初稿和用户稿分开，不执行 HTML。已保存稿经事实确认后导出真实 OOXML DOCX/ReportLab PDF，内置 Noto CJK 字体许可、中文断行/多页 QA，私有附件/no-store，纯数据格式模块不查资料或调用模型。显式另存通过既有资料 Service 生成独立新简历版本，重放不重复，原文和面试快照保留。

替代方案：自由 HTML 全稿、伪 PDF 或覆盖原资料。拒绝，因为不能控制事实保留、文件可用性和数据可逆性。

### 6. 权限、删除和本地交付

全部 API 从登录身份取得 owner，列表不回正文，详情/编辑/导出/另存复核源版本与删除。源/JD删除与依赖任务取消、正文清理在同一数据库事务；任务删除清空快照/结果/草稿，无导出缓存，minimal 计费/幂等元数据保留；已显式另存的独立资料按自身规则保留。日志只留固定错误、时长、计数，不留正文/联系人/Prompt/provider payload。

本地用合成输入、受控 Provider、本地隔离 PostgreSQL、真实 API 和 Chrome 验证，完成金融并发/失败/跨日、旧功能/路由/性能保护、DOCX/PDF 内容和渲染 QA、中文界面、OpenSpec strict。不得创建生产测试任务、调用生产模型、读取用户正文或生产压测。后续用户另行授权发布时必须重新冻结实际基线、只读活动门禁、固定候选/回退、独立验收；本轮不运行发布。

## Risks / Trade-offs

- [钱包和优化 job 分事务会产生孤儿预留] → 复用同一连接/事务和 billing-user 锁，故障注入、并发其他消费、重放与中断回归。
- [免费报价失效后静默扣 100 积分] → 绑定业务日和确认的费用模式，变化返回冲突，由用户重新确认。
- [会员/午夜/失败释放混淆日次数] → 创建日固化，原日释放、独立功能额度、服务端 resetAtMs。
- [中文可能绕过英文实体保真校验] → 保守 quote 局部改写、中文事实合成评测和人工核实，不声称语法验证能证明全部事实。
- [生成占用供应商容量] → 独立1并发、超时/队列上限；本地通过不承诺长期 P95。
- [导出字体缺失或中文长文断行] → 固定字体/许可、实际格式签名与中文文本提取、真实渲染逐页核查；不把网页打印当 PDF。
- [移植覆盖国服已发布优化] → 实际镜像基线、完整旧路由/方法保护摘要及旧业务回归。
