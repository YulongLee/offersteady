# 国服简历优化失败定位与严格响应兼容（2026-10-18）

## 范围与状态

用户上线正常上传的简历后反馈优化失败，并要求明确如何解决。已知历史失败仅保留公共 `invalid_output`，不足以区分返回格式、结构、引用或事实守卫；本次不推测其精确根因，不把上传成功或 MinerU 已配置等同于模型输出已验证。

本追加为现有国服功能的本地缺陷修复：补足固定、无个人信息的失败原因，并严格兼容合法 JSON 对象的少量传输包装。规划完成后由 root 复核 strict 并记录实施 GO，再进入对应任务；无新的产品选择待确认。只允许本地源码、合成测试/评测与文档，不自动生产发布、不重跑或改写用户原任务、不调用真实模型、不读取用户正文作夹具。后续如需发布，仍须针对实际运行 Backend 镜像重新冻结并执行既有生产门禁；此追加不代表已经授权或完成该修复的生产切换。

## 固定诊断及隐私

Provider SHALL 在首次确定失败的位置产生受代码 allowlist 限制的固定诊断原因，覆盖至少：响应体/外层结构、结束标记、内容 JSON、结果 schema/维度、原文依据、中文解释/待补事实、改写引用唯一性、数字、联系方式、英文事实/责任、中文事实/责任、重叠改写及最终草稿。公共错误类别保持 `invalid_output`；原有超时/不可用/中断等类别语义不变。

固定原因 MUST NOT 拼接 schema 验证明细、字段值、异常字符串、简历/JD/Prompt、原始响应、联系方式、对象 key 或用户/任务标识。未知原因 fail closed 映射为固定通用原因；异常 `str`/`repr` 及日志不携带不可信数据。只有任务 owner 的原有 `errorMessage` 根据固定原因映射成安全中文说明，区分“模型结果格式不完整”“引用不匹配”“改写未通过事实检查”等可理解类别；说明不得推断为用户上传操作出错，不返回内部诊断 payload 或部分结果。

在既有任务 JSON payload 中持久化固定失败诊断，不新增列/表或迁移。诊断、failed 终态和 usage released/唯一退款使用原 `finish` 同连接同事务提交，沿用 owner/claim/revision/源删除屏障及原支付方式。未知/旧任务无诊断时返回原通用消息；幂等失败重放不重扣、不重退，源删/任务删仍清空所有派生正文。取消胜出后的迟到失败不可写回诊断或复活内容。

## 严格传输兼容

模型内容仅允许规范化开头 UTF-8 BOM、外层空白，或整体恰好一个带 `json` 标签的完整代码围栏；围栏内仍须是单一合法 JSON 对象。不得从说明文字中搜索、截取或“修复”JSON；不得拼接多段、多对象、多个围栏、残缺内容或接受重复键。内容/响应原有限长和 `finish_reason=stop` 条件保持；非 stop、截断、非法 JSON、数组/标量或结构不符仍固定失败。

规范化只针对模型返回的传输包装，不改输入、MinerU 配置/解析、原文件/Parser 产物、Prompt 事实要求或导出。进入相同 schema、引用、语言、数字/日期、联系方式、英文/中文实体与责任、重叠及草稿守卫，任何原先不合格的事实仍失败并退款；不降级为原简历假成功，不自动重试或扩大模型预算/并发。

## 验收及交付边界

- 合成有效对象、BOM/空白及单一完整 json 围栏通过同一有效结果；围栏外说明、双围栏、多对象、重复键、非法/截断和非 stop 均失败，且无部分稿。
- 合成用例分别触发各诊断类别，保留已有全部事实正负例；AI 行为兼容变化同步更新 `ai/evals/`，不引入真实用户内容。
- 隔离 PostgreSQL 验证失败诊断与免费/积分释放同事务、重复/取消/源删竞态及旧任务回退；原创建报价、会员每日3次/其余100积分、钱包/模拟面试完全保持。
- 所有对外响应、异常和捕获日志验证无合成隐私哨兵；内部 payload 不出现在公共 wire，owner/跨账号/列表权限保持。
- 独立审查后记录精确测试命令/结果、修改文件 SHA、OpenSpec strict 和限制。本地合成兼容通过不能证明既往用户任务具体触发原因或真实模型质量，也不能称为已上线修复。
