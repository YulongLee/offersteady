## Why

当前产品把 macOS 系统权限、账号设备关系和单场面试连接混为同一个 `bound` 状态，导致用户已经授权并使用过助手后，新建或打开面试仍被误导为需要再次授权或重新登记设备。需要将三类状态拆开，形成符合桌面商业产品习惯的稳定连接体验。

## What Changes

- 明确麦克风和屏幕录制权限只由桌面助手在首次使用相应能力时向 macOS 请求，网页端不得申请或伪装申请系统权限。
- 将桌面设备身份和账号最近使用设备长期保存，不因创建、结束或重新打开面试而删除。
- 新建面试允许用户输入机器码连接本场设备，成功后记录为该账号最近使用设备。
- 历史面试允许用户选择“一键连接上次设备”或“重新输入机器码”，一键连接仍需校验设备在线且归属当前账号。
- 将单场面试绑定建模为短期 session lease；新会话可以接管同一用户的旧活动会话，但不得解除设备长期绑定。
- 调整网页和助手状态文案，分别展示系统权限、设备在线/账号绑定和当前面试连接，禁止用“未授权”描述尚未建立 session lease。
- 保持手动问答和截图回答的现有页面结构，不扩大音频、截图或转录的保存范围。

## Capabilities

### New Capabilities

- `persistent-desktop-device-binding`: 定义系统权限、稳定设备身份、账号设备关系和最近设备的持久行为。
- `interview-device-connection`: 定义新面试机器码连接、历史面试一键复用、会话接管和连接状态展示。

### Modified Capabilities

- `streamlined-interview-entry`: 将设备连接从系统授权中分离，并为新面试和历史面试提供不同的设备连接入口。

## Impact

- Web：面试准备页、历史面试恢复入口、设备连接状态及对应 API 客户端和测试。
- Backend：桌面设备注册、账号设备关系、最近设备查询、session lease 建立/接管及持久化模型。
- Desktop：权限状态和会话连接状态分开展示，保持稳定设备 ID 与机器码。
- Data/privacy：仅新增设备标识、账号关系和连接元数据；原始音频与截图仍不因设备绑定而持久化。
