## Context

当前仓库已有一套面向生产后台的百度排名监测预留代码，但生产配置默认关闭，且用户不希望把该能力放入后段管理平台。目标是提供一个与生产服务隔离的本地工具，供运营人员按需查询 `mianshiwen.cn` 或其他授权域名的百度 PC 排名，并把结果导出到当前对话继续分析。

## Goals / Non-Goals

**Goals:**

- 在本机完成单关键词和批量关键词查询，最多展示百度前 50 名结果。
- 仅从本地环境变量读取百度云市场凭据，结果中不回显凭据。
- 输出机器可读 JSON 和便于阅读的 Markdown 报告，包含查询时间、关键词、排名、标题、URL 和错误状态。
- 对鉴权失败、超时、额度限制和无结果给出可区分的安全错误。
- 与生产 API、管理后台、网站部署和用户数据完全隔离。

**Non-Goals:**

- 不把排名能力加入生产后段管理平台。
- 不自动修改网站 SEO 内容、URL、sitemap 或部署配置。
- 不抓取或保存用户简历、JD、音频、截图等敏感数据。
- 不承诺替代百度官方搜索资源平台的收录和流量数据。

## Decisions

1. **本地 CLI 优先，保留可选本地 Web 查看器。** 使用仓库现有 Python 运行环境实现命令入口，避免引入新的线上服务；如后续需要，再在 CLI 输出之上增加仅绑定 `127.0.0.1` 的查看页面。相比直接改生产后台，CLI 更容易隔离凭据和回滚。
2. **复用现有百度客户端协议，但独立配置对象。** 继续使用百度 PC 排名 API 的表单请求、签名、超时和安全错误映射；不直接依赖生产数据库或管理员会话。这样可以替换供应商而不改变报告格式。
3. **凭据只接受环境变量或本地未跟踪文件。** 支持 AccessKey/Secret 或 AppCode 之一，启动时校验完整性；禁止命令行参数、报告文件、日志和 stdout 输出凭据。相比把密钥写进脚本，环境变量更适合轮换。
4. **默认不持久化历史。** 每次运行生成带时间戳的 JSON/Markdown 文件；只有用户显式指定输出目录时才保存。工具不写入生产数据库，也不建立后台定时任务。
5. **报告明确区分“未进入前 50”与“查询失败”。** API 返回空结果时标记为 `not_found`，网络、签名或额度问题使用独立状态，避免把技术故障误判为排名为零。

## Risks / Trade-offs

- [凭据泄露] 本地终端或截图可能暴露密钥 → 默认不打印请求头和环境变量，报告只保留脱敏错误；已在聊天中暴露的凭据应在供应商控制台轮换。
- [供应商协议变化] 百度市场接口字段或签名规则变化 → 将客户端封装在独立适配器并加入响应契约测试。
- [排名波动] 百度结果受地域、设备、个性化影响 → 报告记录查询时间、设备类型和数据来源，避免把单次结果当作绝对排名。
- [误用额度] 批量刷新可能消耗查询额度 → 默认限制关键词数量和请求速率，并要求显式确认批量运行。
