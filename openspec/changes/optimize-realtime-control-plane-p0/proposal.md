## Why

生产环境中的桌面与网页心跳会把单条状态更新放大为约 1.18 MB 的全局 Redis 快照重写，失效截图绑定又持续重试；在单 Uvicorn worker 中，同步 Redis 工作会阻塞普通 API、实时字幕和回答请求。需要先完成一个协议兼容的 P0 修复，在不改变产品形态、ASR、字幕、回答和计费行为的前提下消除该放大链路。

## What Changes

- 将设备心跳、网页心跳和会话活动版本改为实体级增量持久化，不再因单条高频更新重写全局运行态快照或全部活动版本。
- 为机器码、设备、活跃绑定和网页租约提供精确 Redis 索引及旧快照兼容读取，避免高频控制请求扫描全局历史状态。
- 对相同失效绑定和截图资格查询提供短时安全复用与非重叠退避提示，保持既有状态码和响应契约，不强制旧伴随程序升级。
- 将短时同步 Redis 控制面操作与异步请求事件循环隔离，并继续让阻塞 Stream 等待使用独立有界资源。
- 增加状态一致性、旧数据恢复、重复心跳、失效绑定风暴、并发负载和回滚回归测试。
- 保留当前 Git 提交与生产镜像作为明确回滚基线；仅在无活跃面试的发布窗口切换。
- 不修改 UI、桌面助手协议、ASR 模型、音频分片、字幕 Partial/Final 语义、快答、自动回答、截图生成、Prompt、计费或隐私策略。

## Capabilities

### New Capabilities

- `incremental-realtime-control-state`: 高频设备、绑定、页面租约和活动状态必须使用有界、实体级、原子且可兼容恢复的持久化。
- `control-plane-retry-containment`: 重复或失效的桌面控制请求不得放大为重复昂贵工作，同时保持旧客户端兼容和正常绑定恢复速度。
- `p0-runtime-rollout-safety`: P0 运行态优化必须具备基线锁定、无活跃面试门禁、生产验收和快速回滚能力。

### Modified Capabilities

无。

## Impact

- Backend：Redis 实时语音仓库、设备/网页心跳与绑定查询、同步 Redis 执行隔离、运行指标。
- Redis：新增版本化实体 Key 与精确索引；旧全局快照在兼容期保留，不删除生产数据。
- Tests：仓库兼容、并发一致性、控制面风暴与用户链路回归。
- Deployment：Backend 镜像与切换流程；Web、Admin、Desktop、PostgreSQL 和模型配置不变。
- Privacy：不新增音频、截图、转写或个人资料内容；诊断仅使用计数、耗时、状态与脱敏标识。
