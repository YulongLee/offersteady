## Context

国际服实际运行 20260922-global-telemetry-p0-1，与脏的本地国服工作区不同。国际服拥有独立邮箱认证、多语言和 Creem 套餐，不能以国服整包替换。四项范围由用户批准。

## Goals / Non-Goals

**Goals:** 移植三个回答可靠性改进，完成 Intel 1.3.2 正式分发，自测后无活动面试切换并保留兼容回滚。

**Non-Goals:** 不修改模型、Prompt、价格、音频、轮询、内存策略、数据库或国服；不引入联网、模拟面试、国服权益和管理页面改动。

## Decisions

1. 从国际服运行发布目录提取无凭证源代码到隔离候选，核对运行容器文件哈希。相较整包本地主分支发布，只移植经过审查的差异可避免跨服能力覆盖。
2. 预留失败结果仅映射支持字段。SSE 在现有线程执行器预取第一事件，业务错误在发响应头之前返回，首事件只发送一次。不新增模型请求或计费调用。
3. 截图日志补齐已有必需参数，只记录异常类型，不记录图片、问题或凭证。
4. 增加向后兼容的 quick-completed 事件与默认 false 的 quick_answer_completed 字段。国际服自有界面识别简单阶段完成，保留简单文本；详细生成仍保持既有顺序。不为此引入联网代码。
5. Intel 包基于已有国际服 1.3.2 源码构建，验证签名、公证、架构和国际服端点，发布时保留其他架构条目。优先复用经过验证的现有正式产物，不能用未公证包替代。
6. Backend/Web 使用现有镜像为父层，仅覆盖审查的代码和静态构建。Admin、数据库等不重建。回滚 Backend 同样包含新增字段的解码兼容性；部署前再次检查活动门禁。

## Risks / Trade-offs

- [跨服代码漂移] → 对比实际运行哈希并执行国际服认证、计费、多语言回归。
- [序列化字段导致旧镜像不能回滚] → 制作仅包含新增默认字段的兼容回滚镜像并测试。
- [公证等待或失败] → 不发布未验证包；报告实际状态，不伪称正式完成。
- [部署时有新面试] → 最后时刻再查 live、页面租约、音频、回答任务；有用户则延后，不强制结束。

## Migration Plan

基线导出与差异审查 → 合成回归与国际服构建 → 正式 Intel 包验证/上传 → 候选和回滚镜像 → 空闲门禁 → 国际服 Backend/Web 切换 → 健康、静态资源、能力及清单验证。环境配置保持不变；没有数据库迁移。失败恢复兼容回滚镜像，不清理用户状态。

## Open Questions

无产品阻塞问题。外部公证服务与线上空闲状态需执行时验证。
