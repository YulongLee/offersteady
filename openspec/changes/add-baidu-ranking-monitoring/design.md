## Context

现有后台已有 FastAPI 管理 API、管理员权限校验、审计记录和独立 worker 入口，但没有百度排名数据表或排名服务。百度 PC 排名接口按 `domain` 与 `keyword` 查询，并返回排名、页面标题和 URL 等结果；查询接口需要服务端认证，不能把截图中的凭据放到客户端。排名属于运营观测数据，不应进入登录、面试或支付请求链路。

## Goals / Non-Goals

**Goals:**

- 每个配置关键词每天在 Asia/Shanghai 时区最多同步一次，并可安全重试。
- 保存可追溯的查询日期、排名状态、排名值、匹配 URL/标题、请求耗时和安全错误码。
- 在后台提供清晰的当前值、与上次结果的变化和最近同步状态。
- 失败或过期数据明确标记，不把“未找到”显示成排名 0。
- 复用现有管理员会话和只读权限，凭据仅服务端可见。

**Non-Goals:**

- 不自动修改 SEO 页面、关键词、URL 或内容。
- 不承诺百度收录、排名提升或市场排名结果。
- 不在用户前台展示排名，不采集用户面试资料或音频。
- 不在本次变更中接入其他搜索引擎或批量创建内容。

## Decisions

1. **服务端适配器与持久化快照**：以可替换的 `BaiduRankingClient` 隔离供应商协议；同步结果写入 PostgreSQL，按 `(domain, keyword, observed_date)` 唯一约束保证幂等。备选方案是每次后台打开实时查询，但会增加延迟、配额消耗并使第三方故障暴露给管理员页面，因此不采用。
2. **独立 worker/cron 入口**：提供 `offersteady-baidu-ranking` 单次运行入口，由现有部署的 cron/worker 每日触发；任务使用数据库锁或唯一约束避免多实例重复执行。备选方案是在 FastAPI 进程内启动定时线程，容易在多副本部署中重复执行且影响服务生命周期，因此不采用。
3. **权限与数据最小化**：新增 `seo.read` 权限并授予需要查看运营数据的角色；关键词维护和手动刷新使用 `seo.manage` 并写入审计。响应只返回脱敏后的 endpoint 状态、排名数据和安全错误码，不返回 AccessKey、Secret、AppCode 或原始认证响应。
4. **状态模型**：`ranked` 保存 1–50 的整数排名；`not_found` 表示接口成功但未在返回范围内找到；`provider_error`、`timeout`、`invalid_config` 分别表达可诊断失败。UI 显示“未进入返回范围/同步失败”，不以 0 代替。
5. **关键词配置**：首批默认使用已确认的 10 个中文关键词和 `mianshiwen.cn`；后台可新增、停用和调整关键词，配置变更不影响历史快照。每个关键词保存并展示供应商返回的最多 50 条结果。关键词来源和日期在后台明确显示，避免把排名当成实时保证。

## Risks / Trade-offs

- [第三方配额或服务波动] → 每日批量调用设置超时、有限重试和退避；展示最近成功快照及“数据可能过期”标记。
- [凭据泄露] → 仅从服务端环境注入，禁止 `VITE_` 前缀、日志打印和前端回显；本次截图中的凭据应先轮换再配置。
- [多实例重复同步] → 使用数据库唯一约束加任务运行锁；重复执行只返回已存在快照。
- [排名语义误读] → 同时展示观察日期、查询域名和“返回范围”说明，不使用未经验证的流量或排名提升结论。
- [任务占用资源] → 同步在独立 worker/cron 中执行，限制并发并与用户请求池隔离。

## Migration Plan

1. 添加表/索引与只读 API，默认不开启外部同步，先以未配置状态部署。
2. 在服务器密钥管理中配置已轮换的百度凭据、域名和关键词，运行一次 dry-run/单次任务验证。
3. 配置每日 Asia/Shanghai 调度，观察成功率、配额和任务耗时。
4. 开放后台“搜索排名”视图；若异常，停用调度即可，历史快照和网站用户链路不受影响。

## Open Questions

- 百度服务最终要求 AccessKey/Secret 还是 AppCode，需以该账号的交付文档为准；实现应支持一种明确协议并在配置校验中拒绝混用。
- 任务调度由现有基础设施的 cron、容器 worker 还是云函数承载，需要在部署环境确认后确定入口。
- 每日手动刷新次数上限和可维护关键词的角色，可在实现时按现有管理员限流策略设定默认值。
