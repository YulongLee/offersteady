## Decisions

### 1. CN 专用 PDF renderer 和最小分发

新增 `app.services.cn_resume_optimizer_export.render_cn_resume_pdf(markdown)`，返回与原 renderer 相同的 bytes/MIME/附件名三元组。CN service 默认 `format=pdf` 才 lazy import 新函数；`docx` 继续调用原共享 renderer，注入测试 exporter 语义保持。共享文件、Global 和原 service 其余守卫字节不改。

复用既有字体和 ReportLab，不下载资源、不改包版本。相比修改共享 helper，此方法能以最小增量阻止 Global 排版不经授权改变；相比浏览器打印或新 HTML→PDF 依赖，不增加运行时或远程请求。DOCX 保持是本轮明确范围取舍，优先让用户实际需要的 PDF 可投递。

### 2. 保守的有序文档模型

解析只在内存建立有序文本块：文档标题/明确姓名行、连续页首联系行、栏目、经历子标题、列表、正文。每块保留对应文本，所有块按原出现顺序输出。只移除明确的 Markdown 结构标记和成对强调，未知/歧义语法作为文字保留；URL、数字/日期、经历/技能和其重复次数不得丢失。不要把当前任意首个短行直接认定为姓名。对常见无 Markdown 简历，仅当原文第一行是短单行、不是联系方式/栏目/长句，且紧随的最多 3 个非空页首行中具有明确 email 或电话联系信息支持时，可仅将该原文行排为文档抬头；这是版式上下文，不创建姓名字段、不新增事实、不移动文本。无此联系证据仍为正文，URL 独占、日期/经历编号等不得替代明确 email/电话证据；首行邮箱/电话或长句也不得提升为抬头。

栏目识别使用小而明确的独立中英栏目白名单及完整行边界，允许末尾冒号或整行强调；“教育：本科”不是只有栏目名，必须完整正文保留。明确 Markdown 子标题或栏目后完整加粗短行可作经历层级；不依靠日期/公司启发式从正文抽事实。缺少姓名或联系方式时不补占位、不凭 targetRole/JD 造事实，未知格式仍是可读单栏正文。

保留原输入安全/长度验证；任何结构标记处理必须有“所有非结构可见文本按顺序保留”的合成回归。事实确认仍针对用户已保存文本，排版不写回。

### 3. 专业商务深蓝 A4 视觉规则（5.x取代首轮黑白外观）

首轮6d466a27…黑白/深灰细线版本已本地验收，其22pt抬头、9.2pt联系方式、11.3pt栏目、10.2pt正文/14.8pt行距和45pt左右页边距是已测历史基准。用户最新明确要求更有设计感，当前5.x设计将外观改为白底深灰正文、受控商务深蓝强调、单栏A4；用抬头细栏/淡色栏目背景与左色条、适当字号/字距、经历重点和留白提升层级。具体色值、绘制尺寸与字号已由root冻结于下表，仍须本轮strict/实施GO后才实现；不得为美观缩小正文成极小字号或强制一页。

使用原有字体的真实文本；不为模拟粗体新增字体资产，可用字号/间距/细线和现有安全样式建立层级。单栏保持文本提取的阅读顺序，长 URL 允许视觉换行但保留字符序列。栏目/短经历标题与首段 keep-with-next，长段落可自然拆分，避免对整段经历 KeepTogether 造成溢出；不额外添加会干扰简历文本的重复页眉/页脚文案。

### 4. 私有与有界处理沿用既有入口

PDF formatter 只接收已授权字符串并返回内存 bytes，不知道 owner、存储、钱包、模型或数据库。原 CN service 渲染前后检查和错误映射保持；HTML 特殊符转义为惰性文本，不激活 URL。字体覆盖不足继续安全失败，不能静默替换字符。

新 PDF 使用专用字体注册名，但新旧 PDF 共享原 helper 的有界 `_PDF_LOCK`（data-only import，旧文件不改），等待上限沿用 2 秒，所有异常以 finally 释放；格式依赖仍 lazy import。依据本地实际 ReportLab 4.4.9 的 `pdfmetrics.registerFont` 行为，不同 fontName 的相同 face 可别名为同一 TTFont 对象，独立新锁不足以保护其可变动态字体状态，必须让新旧 PDF 混合渲染串行，并补混合并发回归。输入 60000 字符上限、现有线程执行边界和按需内存输出保持，不扩大实时面试执行工作。无缓存/新池/后台任务。

### 5. 以真实 PDF 证据而非截图代替测试

合成固定输入生成 PDF，检查签名/MIME/A4 页尺寸、内嵌字体、pypdf 文本提取、所有事实/末尾标记及顺序、无 JS/远程动作。用现有本地 PDF 渲染工具将每一页渲染成 PNG，由 root 逐页检查布局；机器 bbox/边界检查辅助发现重叠和出界，但不能替代视觉验收。

至少一页中文、两页以上中英长经历、无 Markdown 栏目/缺姓名/长 URL/歧义行/页末标题/超长段落边界样例。用户体验交付 experienced/campus 两份纯合成最终 PDF；本地 test-only 预览下载必须是真实新 renderer PDF，不能沿用伪文件签名，样例资产/生成器显式排除生产 build。页面仅加简短专业 PDF 模板说明，不增加选择器或仿 HTML 预览。保留原 DOCX/Global 回归；CN service 通过 injected renderer 与真实新 renderer 验证事实确认、current revision、删除/更新竞争和无收费写入。本轮不新增 AI eval，因为 Prompt/模型/生成完全未改。

## Risks / Trade-offs

- [任意原稿结构无法可靠推断] → 只识别明确结构；裸短首行只在紧随最多 3 非空行的明确 email/电话上下文下作为文档抬头，不能把 URL/日期/编号当依据；其他未知正文保留，不创建姓名字段/改事实/调序，不承诺复刻原版式或推导全部字段。
- [字符覆盖/长 URL/长段落影响布局] → 原字形拒绝保持，使用真实多页/提取/逐页视觉验收，修排版而非删字或缩成极小字号。
- [模板好看但内容失真] → 固定有序文本模型、合成全文序列/数字联系信息断言、无 AI/无写回；用户仍事实确认。
- [共享 formatter 误改 Global] → 新 CN 专用分发、共享 helper/Global 源哈希保持、原两格式回归。
- [本地 CPU 渲染与 ReportLab 同 face 别名共享状态影响并发] → lazy 资源、新旧 PDF 共用原有界锁、原工作量上限与执行边界，测混合并发/锁失败恢复和本地耗时；旧 helper 不改，不将短时样例测试推断为线上容量承诺。
