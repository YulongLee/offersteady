## Context

截图回答使用 OpenAI 兼容接口调用 `qwen3.6-flash` 并开启流式响应。该模型支持混合思考且默认可能进入思考模式，但当前请求未明确传递思考开关；流解析又只消费可见正文，因此模型的不可见推理会表现为用户等待空白。现有任务遥测已有 `firstTextMs`，网页也会回传 `screenshot-first-render`，但前者没有写入持久 AI 用量首字字段，后者没有形成截图专属端到端性能分布，且同一任务的多个流式更新可能重复确认。

本变更横跨视觉网关、用量记录和网页首次渲染确认，但不改变截图采集、Prompt、图片预处理、SSE 消息格式、积分或最终答案状态机。

## Goals / Non-Goals

**Goals:**

- 让截图视觉请求确定性地使用非思考模式，减少首个可见正文之前的空白等待。
- 分别持久记录模型请求到首个非空正文的耗时，以及截图请求创建到浏览器首次渲染的端到端耗时。
- 保持供应商适配器可替换、指标不含敏感内容，并可通过单一配置回滚思考模式行为。

**Non-Goals:**

- 不更换模型、接口、Prompt 或图像参数。
- 不调整流式节流、任务状态、失败重试、积分、ASR、快答或桌面伴随程序。
- 不用前端逐字动画伪造更细粒度的模型流。

## Decisions

### 在视觉请求负载中显式传递 `enable_thinking`

截图视觉适配器从服务端配置读取布尔值并把它写入供应商请求负载，生产默认值为 `false`。该选择直接控制产生空白等待的模型行为，且不会把供应商密钥或逻辑下放到客户端。

替代方案是依赖模型默认值，风险是模型版本或供应商默认行为变化；另一个方案是更换模型，但会改变回答质量与成本，不在本轮范围。

### 保留两个不同口径的首字指标

- `first_token_ms`：视觉请求发出到解析到首个非空可见正文，写入现有 AI 用量记录。
- `screenshotClickToRenderMs`：截图请求创建到浏览器第一次把非空答案提交给 React 更新，通过现有运行时性能回执写入聚合分布。

两者分开可以判断慢在模型前还是模型后。网页对每个截图任务只回执一次，避免后续流式更新污染“首次渲染”分布。

替代方案是只记录总耗时，但无法定位首字；也不新增答案正文日志，因为内容不属于性能监控所需数据。

### 复用现有任务遥测与性能回执协议

不新增第二条 SSE 或数据库表。后端继续通过截图任务遥测暴露阶段数据，浏览器继续使用既有 performance acknowledgement，仅补齐截图阶段的聚合映射和一次性语义。

替代方案是引入新的追踪系统或链路 ID 表，实施和运维复杂度明显超出本轮两个优化点。

## Risks / Trade-offs

- [非思考模式可能轻微改变复杂截图题的回答质量] → 保留服务端配置开关；上线前用现有合成截图回归验证输出结构和流式状态机。
- [浏览器关闭或断网时无法取得首次渲染指标] → 模型首字仍由后端持久记录；端到端指标仅统计收到回执的样本并保留样本量。
- [重复事件导致重复首屏回执] → 网页按截图任务 ID 去重，回归测试覆盖多次 partial 更新。
- [监控写入影响热路径] → 复用现有异步/轻量回执和用量记录，不在模型流循环中增加外部调用。

## Migration Plan

1. 先发布配置和代码，默认关闭截图视觉思考模式。
2. 运行后端、网页定向测试与生产构建；只滚动更新 Backend/Web，不重启 PostgreSQL、Redis 或伴随程序。
3. 部署后核验健康检查、运行配置及容器版本，观察截图首字指标样本。
4. 如发现回答质量或供应商兼容异常，仅把截图思考开关恢复为旧行为并重启 Backend；代码和其他链路无需回退。

## Open Questions

无。用户已确认本轮仅实施关闭思考模式和补齐首字耗时监控。
