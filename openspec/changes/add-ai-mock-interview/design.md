## Context

2026-09-26，用户要求新增独立 AI 模拟面试，并确认两项商业/交互规则：有效期内时间会员免费，积分用户每场 100 积分；用户点击“回答完成”推进下一题，而非静音自动推进。

随后用户补充并确认：积分用户创建收 100 积分、模拟面试每分钟另扣 5 积分；每个用户最多保存 2 条模拟面试记录。最新会员规则为：有效时间会员每日免费创建 3 场，额度内该场免创建费和分钟费；当天第 4 场及以后按积分用户收费，创建 100 积分＋每分钟 5 积分。该规则覆盖此前“时间会员不限次全程免费”的表述。

本地工作区包含未提交的国服回答错误及后台用户搜索改动，必须保留。当前本地 SessionService 只有 `interview` / `written` 两种会话类型；RealtimeSpeechService 开始普通面试会预留首分钟、启动分钟计费，手机音频模式还会把麦克风送入面试问题检测。不能把模拟面试简单标成普通手机面试。

现有资料选择按文档所有者及版本确认，但 ChatService 的简历 prompt 默认仅取最多 900 字摘要。模拟面试需要读取本场已选版本的实际解析结果，并做有界组织，不能把通用处理完成消息或不足的摘要冒充完整简历。

## Goals / Non-Goals

**Goals:**

- 国服独立入口及完整创建、准备、10 题以内互动、报告流程。
- 积分用户创建收费 100 积分、另按每分钟 5 积分计费；有效时间会员每日前三场全程免费，第四场起按积分用户收费。各阶段幂等，不重复扣费，不叠加第二套普通面试分钟账单或逐回答费用。
- 每个账号最多保存 2 条模拟面试记录，服务端并发校验，默认不自动删除旧记录。
- 朗读由用户指定 TTS 模型完成，出题和报告保持可替换文本模型适配器。
- 保护现有普通面试、笔试、手机面试与桌面机器码协议。
- 本地自测覆盖会话、计费、语音门控、跨用户隔离、释放资源及 AI 行为。

**Non-Goals:**

- 不修改已有快答/详细回答模型配置，不自动扩展到国际服或打包/上传正式助手。用户最新授权在完整自测通过、国服无在线面试后部署国服。
- 不做真实人物声音克隆、摄像头采集、数字人视频或精确口型同步。
- 不做静音自动换题、抢话打断、全天候自由聊天或超过 10 题的无限追问。
- 不改变旧轮询策略、P95 指标口径、普通快答提示词或支付渠道。
- 首版设计按国服中文体验；不自动向国际服上线或宣称多语种已验证。

## Decisions

### 1. 独立会话类型及编排

新增 `mock` 会话类型，保留现有默认 `interview`。模拟面试元数据、轮次、模型操作及报告由独立服务管理，通过受控适配器使用现有机器码绑定、资料和音频基础设施。数据库采用加法迁移，更新类型约束，但不重写旧会话。

不使用普通 `mobile` 会话伪装模拟面试：音频仅麦克风可以复用，但自动快答资格、分钟计费、收音阶段和角色映射必须按 `mock` 分支隔离。所有普通创建、重启、开始和回答接口也需要模式校验，防止通过旧接口绕过创建收费或生成额外问题。

### 2. 创建收费与分钟计费分离

新增 `mock_interview_entry` usage kind，收费场次固定 100 积分。有效时间会员每天拥有 3 个免费创建名额；成功使用免费名额的场次免创建费与分钟费，并记录权益凭证及业务日期。免费名额耗尽后的会员场次按积分用户收费。积分套餐不视为时间会员。另设 `mock_interview_minute` 或有明确模式标签的等效用量记录，收费场次费率 5 积分/分钟。

分钟费不能仅通过“当前账号存在有效时间会员”直接豁免：第 4 场即使用户仍是会员也必须收费。用户已确认创建时保存本场收费类别 `daily_pass_free` / `points` 及确认价格，后续按本场类别处理；免费场次跨午夜或会员中途到期不追加收费，收费场次跨午夜也不自动转免费。

创建请求必须携带幂等键；服务端绑定当前认证账号，在数据库原子完成会话创建和账本结算，或使用可恢复的事务工作流确保失败不扣费。重复点击、响应丢失后的重试返回原会话。不得仅用单进程锁保护扣款。

免费额度按账号和业务日期原子占用，和会话创建处在同一事务边界；创建失败不占额，同一幂等请求只占一次，跨日期重试也返回原会话而不是再占新额度。并发争抢最后一个免费名额时只能成功分配给一场。客户端须明确确认当前收费条件；若客户端按免费提交但额度刚被其他请求耗尽，返回价格/额度已变化并请求用户确认收费，不能静默扣除 100 积分。

每日额度不与历史保存记录混算：删除已保存记录不退回当天免费名额，重复查看/续接同一场不再占名额。创建成功后取消仍已使用创建名额；不可恢复故障按已确认补偿政策恢复。用户已确认国服按服务端 `Asia/Shanghai` 自然日（00:00 至次日 00:00）确定额度桶，不使用客户端时间，不按滚动 24 小时重置。无需破坏性清零旧计数，新的业务日期自然获得新的 3 次额度。

“创建成功”与“开始面试”保持用户原要求的区别：创建成功即结算创建费或占用免费名额，随后再选简历和机器码；准备阶段不收面试分钟费。页面须在动作前展示今日剩余免费次数、本次是否免费及收费时的 100 积分创建费和 5 积分/分钟。创建失败无扣费。开始后的语音/模型故障允许同场重试，不重复收创建费，不额外收逐题、语音重试、报告生成费用；同一计费分钟最多结算一次。

分钟账本必须绑定会话与计费序号，刷新、重连、多标签页和 worker 重试不能重复扣除同一段时间。新旧分钟计费器只能有一个权威入口，不能 mock 账单和普通 realtime_minute 同时运行。结束或异常过期后立即停止继续产生分钟用量，生成/查看报告及保存历史记录不延长计费。余额不足时停止未获授权的继续使用，说明原因并保留已完成内容，不静默欠费或无限继续收音。

用户已确认：累计朗读和回答的实际交互时间，每开始一分钟收 5 积分；准备、出题/语音供应商等待、暂停、断线和报告生成不累计。采用服务端单控制连接租约和单调累计：开始交互前购买下一分钟使用权，暂停恢复沿用该分钟剩余时长，按场次/分钟序号唯一记账。心跳只确认连续在线时间；租约过期不追收未确认的离线尾段。余额不足或租约到期立即关闭采集资格，不能因无请求就无限运行。网络断开时尽快暂停，进程故障由短租约兜底，重连不计入中间空档。

### 3. 准备流程与简历证据

创建页展示固定价格、当前会员权益、可选目标岗位和名称。创建后选择本人一份已处理、未删除且解析产物可读的简历，确认本场版本；不允许空简历开始。JD 和知识库扩展不在首版必需范围。

绑定使用现有机器码和同账号设备授权；不能借新功能抢占正在使用的其他会话。准备页说明仅使用麦克风、题目朗读来自网页、推荐佩戴耳机及原始音频不保存。取得平台麦克风权限后才能开始。

只把用户选择的简历版本载入上下文。正文作为不可信资料、不是指令；去除电话、邮箱等出题无关字段。有界上下文保留关键经历并标记截断，不假称完整读取；不把其他用户或其他会话资料混入。本场开始后锁定资料版本。

### 4. 服务端回合状态机

阶段为：`preparing → generating_question → speaking → listening → submitting_answer`，之后进入下一题或 `generating_report → completed`。另有可重试错误、用户提前结束及过期终态。

- 每次只接受当前轮 `questionId`、状态版本和提交幂等键。
- 文本模型输出校验后才计入已发布题目；包含追问的总数不得超过 10，服务端强制上限。
- 用户在 `listening` 阶段说话，实时看到转录；可校正识别错误，点击“回答完成”才提交。
- 静音不能推进，重复请求不能多出题，旧轮提交不能覆盖新轮；拒绝空回答并提示继续回答或主动结束。
- 第 10 题提交后直接进入报告，不生成第 11 题。提前结束基于已完成题目生成部分报告；无有效回答不伪造分数。
- 模型生成使用带截止时间和状态版本的操作声明，不持有数据库事务/连接等待外部模型。不在 HTTP 事件循环中执行同步阻塞请求。
- 刷新/重连拉取服务端当前轮，不能重新收费或无意重放提问。终态拒绝迟到音频、迟到模型结果及新问题生成。

### 5. 文本生成与 TTS 分工

使用独立 mock 文本适配器，默认复用现有已配置文本模型的连接参数，但不修改快答或详细回答配置。首题围绕简历与岗位，后续依据已提交回答选择项目深挖、技能验证、行为场景与适量追问，避免机械连问或编造经历。

TTS 使用 `qwen3-tts-instruct-flash-realtime`。服务端以 WebSocket 连接正确地域端点，通过 `session.update` 配置系统音色、中文、PCM 24kHz 和集中维护的面试官语气指令；通过文本 buffer 事件提交问题，处理音频增量和完成事件。不能误用其他 Realtime 模型的 `response.create` 流程，也不能让 TTS 负责理解简历。

TTS 适配器必须有超时、音频字节上限、有界播放队列、取消和 `finally` 关闭。浏览器只能取得本用户本场题目的音频流，不能取得百炼长期 API Key。TTS 失败保留文字题目，显示“朗读失败，可重试或文字继续”，不能无提示替换成浏览器系统语音并称作百炼成功。

独立配置至少包含 enabled、TTS model/voice/WebSocket endpoint、可选服务端 API Key、超时和并发上限。可复用同地域已有 Key，但必须通过合成文本真实调用验证权限，不能因已有文本模型成功就宣称 TTS 可用。

### 6. 半双工防回声

模拟面试只需要麦克风，不发布电脑系统音频。面试官正在朗读/重播时，后端关闭该轮回答接收门控，丢弃该窗口音频及相应迟到转录；朗读结束后清理边界、展示“请回答”并开启新的采集轮标识。每条接收片段必须匹配 session、question、capture epoch 和有效时间窗。

不能只用前端隐藏转录，也不能只用“过滤与题目相似文本”作为回声保护。旧助手没有新轮次协议，使用下述服务端兼容适配并用真实设备验证；不能只因为旧版识别未知 `sessionMode` 就认为兼容。网页在朗读结束/手动跳过后保留 1.5 秒不计费准备时间，覆盖已发布助手最多 1.2 秒的 VAD 尾段；此间不邀请用户开始回答。不能静默要求用户升级助手。

### 7. 形象和页面

2026-09-26 用户要求将功能名“AI 模拟面试”改为“模拟面试”。统一桌面/移动端导航、新建默认标题、开放状态提示及后续账本描述；保留“AI 模拟面试官 · 非真人”的身份披露，不迁移历史标题或账本，不改路由、费用、模型或业务流程。此命名增量先本地修改、自测，不自动部署。

首版采用原创虚拟面试官肖像/插画资产，左侧面试官卡片与语音状态，右侧当前问题、可核对的转录和“回答完成”，顶部题号进度与结束操作。明确标识“AI 模拟面试官”。生成形象使用 imagegen 技能，不挪用真人照片；状态动画不宣称精确口型同步。

报告页面显示总分、分项、每题证据/不足/建议及下一次练习重点。分项仅评估本场表达内容、专业正确性、项目论证、结构和题目契合程度，不从声音推断人格、健康、情绪或真实招聘结果。建议示范回答中的未知经历使用待用户补充的标记。

2026-09-26 用户追加 Word 下载：仅在本场已完成且报告存在时显示“下载 Word”。点击后懒加载现有 docx 依赖，以已认证获取的本场数据在浏览器生成可编辑 `.docx`，不新增后端接口、模型调用、收费或保存名额。文档包括场次名称、目标岗位、完整/部分状态、总体与分项评分、总结、逐题问题及已提交回答、回答证据、优点、不足、建议和练习重点。缺少分数时明确“不评分”，未作答题不伪造回答或评价；保留 AI 练习反馈说明，不导出音频、完整简历、内部标识或令牌。文件名清理非法字符，正文保留中文、换行与完整长文本。导出中防重复点击，失败可重试，不影响在线报告。先本地实现和验证，部署另行授权。

真实模型评测曾在示范回答中编造百分比及定性成果。因此示范结构改由集中模板与该题逐字引文组合；模型仍输出逐题优点、不足和练习重点。未知经历保持未填写槽位。一个回合只保留首个完整问句，附带追问不同时发布。

2026-09-26 用户确认不升级助手。浏览器控制连接保持独立；已发布助手复用 `interviewAudioMode=mobile` 的麦克风上传和既有 `/publishers`、`/ingest-ws` v2 协议。后端只为已绑定本人 mock 会话签发独立前缀、短期、进程内有界的发布令牌，普通入口不能消费该令牌；不进入普通 ASR、自动快答、转录持久化或普通分钟计费。之前本地专用麦克风协议保留为可选路径，不作为用户前置条件，也不打包发布助手。

准备阶段检查现有助手在线、机器码绑定和麦克风权限即可开始；旧助手在会话进入 live 后才连接上传通道。网页分别显示设备就绪和音频通道就绪，等待通道时不开始回答计时。每轮服务端新建 ASR，关闭时立即撤销 epoch。兼容适配器固定该帧准入时的 epoch、按通道序号去重，并拒绝跨轮旧片段、播放期间、系统声道和超时补发；不把所有收到的帧简单标记为当前题。

2026-09-26 上线验收发现：正式 1.3.2 助手主进程心跳固定上报麦克风 `unknown`，不是系统拒绝授权。用户授权修复后自测并部署。仅对无 mock 专用协议的正式 v2 路径，准备判断允许该未知状态，并明确提示权限由助手本机确认、开始后等待收音通道；不把未知改写成已授权，也不修改设备注册表。明确 denied/restricted、离线、代际/归属不匹配仍拒绝。操作系统继续约束实际麦克风访问，回答仍需已有认证音频通道，等待不启动回答计时。专用 mock 协议仍要求已授权。准备状态返回安全错误码及可操作说明，不再吞掉原因；绑定成功通知与错误分离、状态确认后自动消失。同场重试不重新创建、不额外扣创建积分。

旧协议没有服务端轮次标识，不能保证物理麦克风在朗读时停止采集/上传：服务端丢弃非回答窗口 PCM，不转写、不保存。兼容路径要求电脑系统时间自动同步，使用采集时间与服务端窗口做保守筛选；不静默校正客户端时钟。时间异常或通道断开暂停并提示，等待恢复不计费。建议耳机降低物理回声。用户最新授权先部署再测试，真实扬声器/麦克风验收保持待完成，不能以自动协议测试替代。

### 8. 两条保存上限及隐私边界

每个账号最多持有 2 条已保存模拟面试记录，时间会员同样适用。该限制不是“最多创建两场”或“每天只能练习两场”。报告/逐题问答作为同一场记录计算一次，不把单题分别计数。未保存的运行期状态不能当作长期历史绕过隐私要求。

用户已确认每场结束自动保存。为避免结束时才发现满额，成功创建时原子预留一个名额，运行中的场次计入两个保存名额；满额在扣费前拒绝创建，提示先结束当前场次或手动删除旧记录。重复请求不多占位，并发创建不得超过两条。删除必须由用户明确操作并校验归属；删除成功释放名额，但不删除计费账本或恢复已消费的免费次数。结束及报告重试不能受其他场次占位影响。

结束自动保存题目、已确认回答及报告；不保存原始音频或额外复制完整简历。删除清除上述内容，仅保留幂等、配额、财务必需元数据。创建页明确此行为。

### 9. 生命周期和可观测性

不记录或保存原始音频，运行中简历上下文、转录及报告只按明确的产品留存选择处理。账本只保留计费必需元数据，不含简历或对话正文。日志只记阶段、耗时、脱敏错误分类、题数和资源计数。

用户结束、完成、长时间离线、会话过期和服务关闭均取消出题/TTS、关闭 ASR/播放流、删除有界缓存、解绑会话。报告失败可以在同场重试，不能让收音继续运行。并发和缓冲必须有界，不新增无限生命周期内存字典。后台可区分模拟面试与普通面试用量，不改变现有指标定义。

## Risks / Trade-offs

- [原产品链路耦合] → 模式检查、独立 usage kind、回归测试；不改普通快答 prompt 或分钟费。
- [创建付费后设备或供应商不可用] → 尽早配置/余额预检、同场重试、明确收费时点；退款规则发布前确认。
- [声音被再识别形成自问自答] → 麦克风单通道、服务端轮次门控、迟到转录丢弃、真实耳机/外放用例验证。
- [模型出题笼统或无依据评分] → 读取真实选定简历文本、结构化证据约束、合成 AI evals、人工验收。
- [小规模测试不能证明生产容量] → 独立并发限制、长会话资源回收测试、性能基线对比；未测不宣称容量达标。
- [只有 mock 单测未验证供应商/桌面] → 验证记录分别列明单元、集成、真实 TTS、真实麦克风，不互相替代。

## Migration Plan

1. 审阅提案、规格和隐私/收费边界，确认后进入实现。
2. 独立功能开关默认关闭，数据库加法迁移，仅本地开发及合成数据验证。
3. 后端/前端单测、账本并发集成测试、AI evals、真实 TTS 与真实桌面联调。
4. 2026-09-26 用户最新指示“部署完成后我这边测试”：自动回归及真实供应商检查通过、确认无在线面试后部署国服；真实麦克风/耳机/外放验收移至用户上线后测试，保留待验收状态，不冒充已通过。健康检查失败则回退，保留数据。
5. 回退时关闭 mock 功能入口，保留已付费会话和账本的可恢复状态，不删除数据、不改变普通面试服务。

## Playback waveform follow-up

- 用户确认在面试官头像下方增加随实际播放音量变化的声波条；本轮仅本地展示，不更改后端、计费、收音、模型或部署。
- `MockVoicePlayer` 在现有音频输出旁路连接 `AnalyserNode`；复用固定采样缓冲，以最多 25 Hz 通知独立小组件，不驱动整个工作台刷新。
- 仅有播放源和可见指示器订阅时运行单个动画循环。音频未到达、静音、暂停、结束、异常、断线均不制造假波形，停止时取消循环并清零；关闭播放器释放分析器。
- 系统减少动态效果时使用静态声波与文字状态；合成预览明确标记测试音，不冒充真实女声 TTS，不调用生产服务。
