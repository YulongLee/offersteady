## Context

`AnswerActionBar` 当前同时负责触发快答/截屏回答、根据任务状态禁用按钮，以及展示任务状态。桌面实时工作区直接使用该组件，移动端控制区也复用相同的状态输入。回答结果已经在回答面板中呈现，因此操作栏再展示成功和处理中状态会形成重复反馈并干扰面试。

## Goals / Non-Goals

**Goals:**

- 从桌面和移动端实时面试界面移除快答、截屏回答的可见状态文案。
- 保持按钮标题稳定，避免任务状态导致布局和文字跳变。
- 保留任务状态驱动的禁用、防重、取消、失败恢复和回答渲染。

**Non-Goals:**

- 不改变快答或截屏回答 API、计费、任务状态机和截图权限流程。
- 不隐藏需要用户决策的截图失败对话框。
- 不修改回答区内容、实时转写或伴随程序。

## Decisions

1. 在展示组件边界移除状态文案，而不删除上层状态字段。这样既能立即改善用户界面，也不会破坏业务状态、并发保护或后续诊断。替代方案是删除整套状态字段，但会扩大影响面并增加重复提交风险。
2. 按钮标题始终使用“快答”和“截屏回答”。处理中仍通过 `disabled` 阻止重复提交，但不显示“快答中”“已回答”等状态。替代方案是只移除底部状态行，仍会保留按钮标题跳变，不满足稳定界面的目标。
3. 保留截图失败恢复弹层。它要求用户重试或取消，属于必须操作的错误反馈，不属于本次要隐藏的常规任务状态。

## Risks / Trade-offs

- [处理过程中用户看不到文字进度] → 按钮会暂时不可重复点击，实际结果继续在回答区流式呈现；失败时保留可恢复错误界面。
- [保留未使用的展示字段造成接口冗余] → 暂不扩大重构范围，待后续统一操作状态模型时再清理。

## Migration Plan

仅发布 Web 前端变更；无需数据迁移。若出现异常，可回滚对应前端提交，服务端和桌面端无需回滚。
