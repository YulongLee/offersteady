## Context

实时资源目前分散在 `RealtimeSpeechService`、ASR gateway、frame worker、事件订阅和计费计时器中。显式结束路径已有部分清理，但持久 ASR 模式跳过 stale sweep，且失活回收依赖后续请求触发。目标是先在国际服灰度，保持活跃面试不受影响。

## Goals / Non-Goals

**Goals:**

- 以网页/桌面租约和音频活动识别真正失活会话。
- 用幂等清理器释放所有会话级外部连接、后台任务和内存状态。
- 通过 watchdog 和指标确保资源最终回收，可回归测试。

**Non-Goals:**

- 不改变账号、积分、订单、资料和已持久化转录数据。
- 不设置全局用户数量上限，不因短暂静音结束活跃面试。
- 不更换 ASR/LLM 供应商，不在本变更中拆分部署集群。

## Decisions

1. **租约判定而非单一 ASR 时间戳。** 综合网页心跳、桌面心跳、音频帧和发布者活动；采用疑似失活与宽限两阶段，避免误杀安静中的面试。相比固定连接时长，能适应不同面试长度。
2. **统一 cleanup coordinator。** 所有结束原因进入同一个按 session 加锁的清理入口，逐项释放并记录结果。相比在各路由重复释放，能保证异常路径一致且重复调用安全。
3. **后台 watchdog。** 每 15–30 秒扫描 live 租约并触发清理；请求路径仍可即时回收，但不再依赖请求流量。相比只在心跳时清理，可处理浏览器和桌面端同时消失的情况。
4. **持久 ASR 受租约约束。** 活跃租约内复用连接；租约过期并经过宽限后关闭连接。相比永久持有或每帧重连，在延迟和资源之间取平衡。
5. **灰度开关和观测。** 先提供 dry-run 记录，再启用真实回收；指标包括回收原因、耗时、连接/worker/缓冲释放数和 RSS 变化。异常时可关闭开关并回滚应用版本。

## Risks / Trade-offs

- [误判网络抖动] → 使用宽限期和多信号租约，回收前通知前端并允许重连。
- [清理竞态] → session 级锁、状态机 `active/suspect/closing/closed` 和幂等操作。
- [watchdog 自身增加负载] → 有界扫描批次、固定间隔、只扫描 live 会话。
- [释放不完整] → 对每类资源计数并在测试中验证重复关闭和异常关闭。

## Migration Plan

先在国际服启用 dry-run 与指标，确认无误杀后开启真实回收；观察一个完整业务高峰，再考虑国服。回滚时关闭开关并恢复上一镜像，不删除数据库或 Redis 持久数据。
