## Context

快答入口当前根据“手动问题或最近面试官问题是否存在”决定是否禁用。空问题状态下按钮不可触发，因此 `submitManual` 中已有的空问题提示分支永远无法通过真实点击到达。通用通知区域虽然可以显示原因，但其默认补充文案把所有非计费通知都描述为“回答没有成功启动”，不够准确。

## Goals / Non-Goals

**Goals:**

- 让用户在没有可用问题时点击快答即可得到明确解释。
- 不发起后端回答请求、不创建回答任务、不扣费。
- 新问题可用后及时清除旧提示。
- 保持处理中防重和安静操作栏设计。

**Non-Goals:**

- 不自动猜测或生成不存在的面试官问题。
- 不修改 ASR 问题判断、回答模型或计费链路。
- 不恢复快答处理、成功或完成状态文案。

## Decisions

1. 仅移除“没有问题”对按钮的禁用条件，仍保留页面只读和快答处理中禁用条件。这样用户能表达操作意图，而并发保护不变。替代方案是在按钮旁常驻说明，但会增加现场视觉噪声，且不能确认用户是否需要快答。
2. 复用实时页已有通知区域，使用专门的 `missingQuestionNotice` 分支显示“未能识别到面试官的问题”和恢复建议。替代方案是在操作栏中恢复状态行，会与已确认的安静操作栏需求冲突。
3. 手动输入发生变化时清除缺问题提示；实时识别出面试官问题后也自动清除。其他错误通知不被该自动清理逻辑误删。

## Risks / Trade-offs

- [用户连续点击空快答] → 只重复设置同一前端通知，不产生请求或计费。
- [旧提示在识别成功后仍停留] → 监听最新面试官问题由空变为非空，仅清理专用缺问题提示。
- [移除禁用被误解为总能生成回答] → 点击后的明确提示解释当前缺少输入，并保留按钮 title 引导。

## Migration Plan

仅部署 Web 前端，无数据迁移。异常时可回滚前端提交，后端、ASR 与桌面伴随程序无需回滚。
