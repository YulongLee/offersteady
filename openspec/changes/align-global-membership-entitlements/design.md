## Context

国际服已经通过 Global Commerce 保存套餐、订阅和会员权益，但 Web 端仍调用国服 `/api/v1/billing/state`，导致国际用户看到积分、国服商品和不完整的会员状态。Global 会员目前只有布尔型知识库权限，没有 Token 使用量，也没有将订阅周期和权益额度完整呈现给用户。

## Goals / Non-Goals

**Goals:**

- 国际服前端以 Global Commerce 为唯一计费事实来源，显示当前会员、剩余时间、续费状态和权益。
- Free、1 天、7 天、30 天、90 天套餐使用分层的实时回答、截图和知识库权益。
- 付费会员的实时回答与截图不从国服积分钱包扣费；Free 继续使用有限体验额度。
- 知识库按解析后的 Token 额度预留、结算和释放，额度与会员权益绑定并可审计。
- 让历史订单继续使用购买时的套餐快照，新发布版本才使用新额度。

**Non-Goals:**

- 不修改国服积分、会员、支付宝或微信支付逻辑。
- 不修改 Creem 验签、订单状态机或订阅取消流程。
- 不把“无限”实现为绕过公平使用策略；服务端仍可执行反滥用限制。
- 不保存原始音频、截图或知识库原文作为计费依据，只保存必要的 Token 计数和权益流水。

## Decisions

1. **Global Commerce 作为国际服计费唯一来源。** 新增 Global billing state 适配层，前端根据运行版次调用 `/api/v1/global-commerce/state`、`/catalogue` 和现有 checkout API；不在客户端拼接价格或权益。保留国服 `/api/v1/billing/*` 供国内版使用。

2. **套餐额度采用版本化快照。** 新套餐版本的推荐知识库额度为：1 天 0 Token、7 天 50,000 Token、30 天 200,000 Token、90 天 1,000,000 Token。额度写入 `GlobalPlan` 和购买后的 `GlobalEntitlement`，已购买权益不因后台修改当前目录而改变。选择 200,000 而不是 200,000,000，是为了避免不可控的模型和索引成本；90 天额度高于 30 天，保持升级激励。

3. **截图和实时回答使用会员权益。** 保持 Global 的 `screen_assist_uses = NULL` 表示会员内含；Free 保留 3 次截图和 15 分钟实时回答。付费权益不创建国内积分流水，但仍通过 Global reservation 和公平使用策略限制异常调用。替代方案是继续复用积分钱包，会让跨版次账单混淆，因此不采用。

4. **知识库计费以 Token 为单位。** 扩展 Global entitlement 和 usage reservation 的知识库字段；上传报价使用服务端规范化文本 Token 估算，先锁定额度，索引成功结算，失败/取消释放。替代“按文件数量”无法反映文件大小和成本，因此只作为 UI 辅助，不作为唯一限制。

5. **订阅剩余时间由服务端计算并在前端倒计时。** `currentPeriodEndMs`、当前权益 `endsAtMs`、下一次续费和取消状态由 API 返回；前端显示剩余天/小时和绝对到期时间，页面聚焦或到边界时刷新。客户端时间只用于展示，权限校验仍使用服务端时间。

6. **全球套餐页面隐藏国服积分模块。** Global billing view 显示套餐、订阅、用量和知识库额度，不显示积分余额、积分流水、兑换码或国服支付通道。账户没有有效权益时只显示 Free 剩余额度与升级入口。

## Risks / Trade-offs

- [Token 估算与最终解析结果不同] → 先按估算锁定，使用最终规范化文本 Token 结算差额；失败自动释放。
- [已有 Global 表结构缺少知识字段] → 使用向前兼容迁移，旧行默认 0，不回写历史订单快照。
- [多次购买或订阅续费并发] → 复用现有 Global repository 事务和订单幂等键，对额度更新使用同一用户级事务边界。
- [客户端仍缓存国服页面] → 根据 edition 在启动时选择 adapter，并在切换页面/聚焦时重新读取 Global state；部署后验证静态资源版本。
- [会员“无限”被滥用] → 保留现有 fair-use decision 和服务端速率/并发限制，不在 UI 宣称无条件无限。

## Migration Plan

1. 添加数据库迁移和 Global domain 字段，旧数据默认兼容值。
2. 更新 Global service、知识库 adapter、API payload 和前端 Global billing 页面。
3. 运行 Global Commerce、知识库计费、前端类型检查、构建和回归测试。
4. 在国际服先部署，验证 catalogue/state/checkout、会员倒计时、截图和知识库额度；不触碰国服部署。
5. 若失败，回滚应用版本；迁移保留向后兼容字段，不删除订单或用户权益。
