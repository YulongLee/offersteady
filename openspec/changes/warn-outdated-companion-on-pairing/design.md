## Context

桌面伴随程序已在注册和心跳中上报 `appVersion`、`platform`、`architecture` 等 capabilities，设备绑定响应会把这些字段返回给 Web；Web 聚合状态也已包含服务端控制的发布清单。当前准备页连接设备后没有比较两者，因此旧客户端仍可进入，但用户不知道有新版可用。

## Goals / Non-Goals

**Goals:**

- 成功连接后准确识别同平台、同架构的旧版本客户端。
- 用轻量、可忽略的提醒提供匹配安装包下载入口。
- 复用页面已有数据，不增加请求、轮询或实时链路负载。
- 面试模式与笔试模式行为一致，且任何版本信息异常都不阻断开始流程。

**Non-Goals:**

- 不强制升级，不改变协议兼容策略。
- 不修改伴随程序、不新增权限、不改变音频、ASR、SSE 或回答链路。
- 不引入自动安装、后台下载或版本上报持久化。

## Decisions

1. **在 Web 准备页派生升级状态。** 使用绑定对象的 capabilities 和已加载的 `state.releaseManifest` 纯计算得出提醒。相比新增后端检查接口，这避免额外往返和服务端负载，也保持发布清单为唯一版本事实源。
2. **严格匹配平台和架构。** 只选取与设备 capabilities 中标准化后的平台、架构完全匹配、拥有可用下载地址且发布状态允许展示的最新条目，避免把 Intel、Apple Silicon 或 Windows 安装包推荐错。
3. **使用兼容当前版本格式的结构化比较。** 将数字段逐段比较，并把数字相同但带尾缀的版本（例如 `1.2.10a`）视为低于无尾缀正式版；无法安全解析时返回未知而不是猜测。
4. **提醒按绑定身份可关闭。** 用户点击“继续使用”后，本次绑定不再重复展示；重新绑定另一设备或版本时重新判断。相比持久化忽略设置，这不会让用户永久错过后续版本。
5. **下载沿用同源 manifest URL。** “立即下载”直接使用匹配条目的现有受控 URL，不生成永久对象存储地址。

## Risks / Trade-offs

- [旧客户端不提供平台、架构或版本] → 不展示升级判断，也不阻断当前流程。
- [发布清单存在多条同目标版本] → 使用结构化版本比较选最高版本；同版本保持清单稳定顺序。
- [非标准版本字符串比较错误] → 仅支持数字点分段加可选尾缀，其他格式降级为未知。
- [提示干扰准备流程] → 采用现有视觉体系中的紧凑提示，默认不抢焦点，开始按钮始终可用。

## Migration Plan

1. 仅发布新的 Web 静态镜像，Backend 与 Desktop 保持不变。
2. 上线前运行版本工具测试、准备页交互测试、Web 全量测试和构建。
3. 等活跃面试为零后替换 Web 容器，并验证首页、准备页、静态资源和 API 健康。
4. 保留部署前 Web 镜像标签；若提示或页面出现异常，仅回滚 Web 镜像。

## Open Questions

无。产品规则已确认采用非强制提醒。
