## Context

现有复盘页已能读取所属用户的持久化场次快照，并在浏览器本地生成 Markdown。新需求不需要改变后端数据或权限边界，只需要把相同的可信复盘模型转换为 Office Open XML 文档。导出的内容含面试转写等敏感文本，因此仍需保持用户主动触发、本地生成、不上传服务端的边界。

## Goals / Non-Goals

**Goals:**

- 生成可被 Microsoft Word、WPS 和主流 DOCX 工具打开及继续编辑的 `.docx` 文件。
- 用标题、元数据、角色标签和问题块清晰区分真实语音转写与 AI 回答建议。
- 支持长问题、长回答、中文和缺失内容，不截断用户数据。
- 在浏览器本地完成生成和下载，沿用现有会话所有权与删除边界。

**Non-Goals:**

- 服务端保存导出文件、OSS 归档、公开分享链接或批量导出。
- 导出原始音频、Prompt、模型供应商原始响应或未确认的 ASR 中间片段。
- 自动评分、重写候选人回答或新增复盘结论。
- 修改桌面助手或实时面试协议。

## Decisions

### Generate DOCX in the browser from the existing review model

Web 使用成熟的 OOXML 文档构建库把当前 `InterviewReview` 模型生成 `.docx` Blob，并沿用现有 Object URL 下载机制。该方案不增加服务端文件生命周期，也不需要把敏感复盘内容再次上传。

替代方案是由后端生成文档并返回文件流，但会增加临时文件、下载鉴权、清理和审计复杂度；对当前单场复盘没有必要。手工拼接 XML/ZIP 虽可减少依赖，但容易产生 Word/WPS 兼容和转义错误，因此不采用。

### Use a restrained business-report layout

文档采用 A4 纵向、中文友好字体、清晰标题层级和页脚页码。第一页展示标题及场次元数据；“真实对话记录”按时间和角色排列；“问题与 AI 回答建议”按问题分节。AI 内容明确标注为建议，避免与用户实际回答混淆。

选择段落式布局而不是宽表格，因为长转写和长回答在表格中容易拥挤、跨页异常，也不利于后续编辑。

### Keep generation pure and testable

把文档结构构建与浏览器下载拆开：前者接收复盘模型并返回 DOCX Blob/字节，后者只负责触发文件下载。测试会解压 OOXML 并检查必需文本、内容类型、文件名及空态；另生成合成示例，通过 LibreOffice 渲染成页面图片进行视觉检查。

### Make Word the primary action without deleting Markdown internals

复盘页主按钮改为“下载 Word”。现有 Markdown 纯函数先保留，避免不必要的破坏性删除，并方便以后提供更多格式；本轮不额外增加多格式菜单，保持界面简单。

## Risks / Trade-offs

- [Risk] DOCX 库增加 Web 包体积 → 在复盘路由中动态加载生成模块，只在用户点击下载时加载相关代码。
- [Risk] 不同 Office 工具渲染略有差异 → 使用标准 OOXML、通用中文字体回退、简单段落布局，并通过 LibreOffice 视觉验收。
- [Risk] 超长复盘生成时短暂占用浏览器内存 → 生成过程保持线性，不嵌入图片/音频；按钮显示生成状态并防止重复点击。
- [Risk] 用户在共享电脑下载敏感内容 → 下载旁保留隐私提示，且仅在用户主动点击时创建本地文件。
- [Risk] 历史场次数据不完整 → 文档明确显示“暂无持久化记录”，不补写或推断缺失内容。

## Migration Plan

1. 发布 Web 依赖、DOCX 生成器和测试，不改变后端 API 或数据库。
2. 将复盘下载按钮切换为 Word，并保留异常提示与重试能力。
3. 运行生成结构、渲染、Web 完整测试、类型检查和生产构建。
4. 回滚时恢复原 Markdown 下载按钮；既有复盘数据和服务端无须迁移。
