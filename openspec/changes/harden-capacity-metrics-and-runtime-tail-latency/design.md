## Context

容量峰值功能已经按 5 分钟与上海自然日写入 `admin_metric_snapshots`，但原表约束只接受 `hourly`、`daily`，而初始化迁移列表没有后续修复迁移。采样器捕获并吞掉该异常，保证用户请求没有直接失败，却让线上每 30 秒产生一次 PostgreSQL 约束错误且历史峰值缺失。

实时会话 SSE 使用同步 Redis repository，并通过 `asyncio.to_thread` 执行 `XREAD BLOCK`。当前 `wait_for_events_after` 在阻塞前后多次 `XRANGE` 全量读取最多 1,000 条事件；会话路由收到任意事件后又重新读取完整事件、转写和候选列表。阻塞读取与短任务还共享默认执行器。事件增长或并发连接增加时，这些行为会放大 Python JSON 解析、Redis I/O 和线程竞争，符合线上观察到的 CPU 饱和和健康检查长尾特征。

## Goals / Non-Goals

**Goals:**

- 恢复 5 分钟容量峰值的可靠、幂等持久化，并消除周期性数据库错误。
- 把会话事件等待的工作量从“每次扫描全部保留事件”降低为“按游标读取增量事件”。
- 隔离阻塞 Redis 等待，避免实时长连接耗尽通用线程资源。
- 避免无关事件触发完整转写、候选和历史事件重读。
- 保持升级前 Redis Stream、断线恢复、旧桌面客户端和现有 Web 事件契约兼容。
- 用合成负载证明健康检查和普通 API 不会因 SSE 空闲等待而出现明显长尾。

**Non-Goals:**

- 不修改 ASR、聊天或视觉模型及 Prompt。
- 不改变用户点击快答/截图回答的显式控制、答案顺序、计费或页面布局。
- 不把音频、截图、问题或答案写入新的存储。
- 不在本变更中引入独立消息队列或替换 Redis。

## Decisions

### 1. 使用向前迁移扩展快照粒度约束

新增幂等 SQL migration，将 `admin_metric_snapshots_granularity_check` 更新为允许 `capacity_5m`、`hourly`、`daily`，并纳入后端启动迁移列表。保留同一张快照表和唯一键，不复制现有数据。

替代方案是把 5 分钟峰值改写到 Redis 或新表。拒绝该方案，因为现有分析查询已经以快照表为权威，修正约束是最小且一致的方案。

### 2. 为 Redis Stream 增加有界游标索引

每次 `XADD` 后把 `cursor -> stream_id` 写入按 cursor 排序的有界 ZSET，并与事件 Stream 使用相同 TTL。增量读取先检查首条保留事件判断游标是否可恢复，再通过索引定位 stream id，仅读取其后的记录。升级前没有索引的旧数据走一次兼容扫描，并在后续新事件中自然进入快速路径。

替代方案是清空现有 Stream 并让 Redis Stream ID 直接等于业务 cursor。拒绝该方案，因为线上升级不能破坏仍在连接的客户端游标恢复。

### 3. 直接消费阻塞读取结果

`XREAD BLOCK` 返回后直接解码新增记录，不再再次全量 `XRANGE`。无事件超时时只读取轻量版本信息。终端状态与 `resumable` 语义保持不变。

### 4. 阻塞等待使用专用有界执行器

会话页面 SSE 与桌面截图 SSE 的 `XREAD BLOCK` 使用同一个专用 `ThreadPoolExecutor`，worker 数通过生产安全配置控制；授权校验、快照读取等短操作仍使用通用执行器。应用关闭时主动关闭专用执行器。

替代方案是立即把整个 repository 迁移到 async Redis。该方案长期更理想，但会扩大本次修复面并增加状态仓库双实现风险，因此暂不采用。

### 5. 按事件类型刷新会话快照

会话 SSE 初始连接仍返回完整 runtime、transcripts、candidates 和 events。后续更新不再读取完整历史 events；只有 `transcript-updated` 刷新 transcripts，只有 `question-candidate`/`question-confirmed` 刷新 candidates，其他事件复用连接内缓存并仅发送增量事件。

### 6. 以长尾和命令放大率作为验收指标

测试使用合成/脱敏事件，覆盖长 Stream、多个空闲 SSE 等待、事件唤醒和并行健康请求。验收关注 P95/P99、每次空闲等待的全量 `XRANGE` 次数、线程池隔离和游标恢复，而不使用平均值掩盖长尾。

## Risks / Trade-offs

- [旧 Stream 没有游标索引] → 保留一次扫描兼容路径；新事件写入后快速路径生效，不清理用户会话。
- [专用执行器 worker 小于长连接数] → 等待任务会有界排队而不是占用通用线程；事件仍可通过超时和重连恢复，worker 数可配置回滚。
- [快照按事件类型缓存遗漏状态变化] → 初始快照保持完整，事件类型与状态写入同源；回归测试覆盖转写、候选、截图、设备和重连。
- [迁移短暂锁表] → 快照表只保存聚合数据，约束替换在后端发布前执行且可重复；写入失败仍保持旁路降级。
- [性能问题还有供应商或主机因素] → 本变更解决已证实的本地放大机制，并保留运行时遥测继续观察生产 P95/P99。

## Migration Plan

1. 先运行新增数据库迁移并验证 `capacity_5m` 实际 upsert。
2. 部署包含兼容游标索引和专用等待执行器的后端；Web/桌面无需更新。
3. 观察 24 小时 PostgreSQL 约束错误、Redis `XRANGE/XREAD` 命令量、后端 CPU、健康检查 P95/P99 与会话重连率。
4. 若事件恢复异常，可关闭快速游标索引并回退旧扫描路径；数据库新增允许值无需回滚。
