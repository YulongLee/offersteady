## Context

客服微信账号目前同时存在于后端默认配置、国服前端文案、SEO 联系页和测试夹具。运行时客服信息来自后端 `BillingService`，而未登录公开页面和法律页存在静态文案，因此只修改单一位置会造成线上展示不一致。

## Goals / Non-Goals

**Goals:**

- 让国服运行时 API 和公开页面统一展示 `mianshiwen_01`。
- 保证本地测试状态和生产默认值一致。
- 在部署前通过搜索、测试和线上接口检查确认旧账号不再出现在活跃国服产品路径。

**Non-Goals:**

- 不变更国际服客服账号。
- 不修改微信登录、微信支付或账号绑定逻辑。
- 不改写历史审计快照、归档发布记录或第三方平台缓存内容。

## Decisions

- **统一替换活跃产品源文件。** 直接更新配置默认值、运行时 fallback、前端法律/SEO 文案和测试夹具；相比只改环境变量，这能避免未配置环境变量时恢复旧账号。
- **保留邮箱渠道。** 用户仅要求停用旧微信账号，邮箱 `contact@oneshowailab.com` 仍是现有客服补充渠道，不删除。
- **国服单独部署。** 国际服代码和运行时配置不改，发布时只重建国服服务，降低跨版本影响面。

## Risks / Trade-offs

- [缓存风险] 搜索引擎或 CDN 可能短暂保留旧文案 → 通过更新版本资源并检查线上 HTML/API；历史快照不作为当前产品展示。
- [配置覆盖风险] 生产环境变量可能覆盖代码默认值 → 部署前检查线上 `OFFERSTEADY_SUPPORT_WECHAT_ID`，部署后以 `/api/v1/web/state` 和公开页面双重验证。

## Migration Plan

1. 更新活跃源文件、测试夹具和 OpenSpec 回归场景。
2. 运行前端/后端相关测试并搜索旧账号残留。
3. 备份线上国服配置，更新客服配置并重建必要服务。
4. 验证健康检查、运行时客服状态和公开联系页；若异常，恢复备份配置并重启原服务。

## Open Questions

- CDN/搜索引擎缓存刷新时长由线上基础设施决定，本变更不承诺即时清除历史快照。
