## Context

当前 2.0.0 国服候选与三平台哈希、签名状态及验证缺口记载于独立工作树的 `docs/releases/cn-companion-2.0.0-local-candidate-20261114.md`。原 1.3.6 发布控制器固定历史镜像、旧清单、组件、目录和标签，不可直接重放。

## Goals / Non-Goals

目标：仅经明确授权发布这三个候选，并通过 Backend 最小列表过滤保留历史下载，保存精确当前基线、只读工作门禁、不可变文件及可验证的增量发布材料。非目标：修复 Zoom、发布其他业务改动、干扰正在进行的工作、读取或导出用户内容。

## Decisions

1. 从当前实际运行容器取得新鲜基线，冻结镜像 ID、容器及组件生命周期、完整业务文件散列、运行配置摘要、精确清单和重建配置摘要；未知、失败或漂移均停止，不接受旧文档值替代。
2. 各对象上传前检查版本路径不得覆盖不同内容，完成后完整读回比较长度与哈希；保留历史对象与 latest。不将临时或未公证 Mac 包作为正式包。Windows 按 unsigned 如实记录。
3. 六条清单保留三条旧版本精确下载，旧条目标识 `hiddenFromListing: true`。基于实际 Backend 源的 `_release_manifest` 加入对该标志严格为 true 时跳过列表；无标志行为不变，精确下载仍读取完整清单，版本门槛仍取最高已发布版本。新三条优先排序。基于实际固定镜像构造仅清单及该一个业务文件的候选与回滚材料，完整对照 Config、原层、所有运行输入、路由/模式和功能。必须保证用户工作空闲和生命周期归属后受控重建 Backend，不能终止用户工作；新后端启动短暂不可用风险需验证并报告。
4. 每一步均以唯一归属及哈希检查作为重试、恢复和回滚条件；回执未知先只读确认，不盲重试。无明确归属或门禁失败停止，不清理用户工作。
5. 验证公开版本、全部对象下载与旧精确版本链接、健康和不变组件；保存结果、固定重建材料及限制。不能用结构或合成测试声称真实音频、Windows 实机或所有会议软件通过。

## Risks / Trade-offs

清单版本门槛会影响旧助手的新绑定和新开始，并可能影响已有会话重复调用开始接口；用户已明确接受旧版需升级。不能主动关闭已有会话，切换前须确认没有受保护工作。缺乏充分门禁、基线或完整来源对照时停止发布，报告具体原因。
