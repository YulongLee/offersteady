## Context

当前收费域已经具备服务端商品目录、官方订单、PostgreSQL 持久化、支付回调审计、积分与会员幂等发放以及异常对账，但下单和通知路由直接依赖 MZFPay。第三方聚合平台最终仍可能落入个人转账场景，用户已经遇到支付宝交易风控。后续将以个体工商户身份创建支付宝开放平台自用型应用，因此需要先把支付边界改造成可替换适配器，并实现支付宝官方电脑网站支付。

## Goals / Non-Goals

**Goals:**

- 新增支付宝官方电脑网站支付的 RSA2 下单和异步通知验签。
- 保持商品、金额、积分、会员、兑换码和用量计费行为不变。
- 让新旧支付提供方订单安全共存并可审计。
- 在商户参数未取得时保持功能关闭或回退，不产生假支付。
- 为后续主动查单、退款和账单对账保留清晰扩展边界。

**Non-Goals:**

- 本轮不代替用户申请营业执照、支付宝商家认证、产品签约或应用审核。
- 本轮不实现自动续费、花呗分期、营销券或多商户分账。
- 本轮不改商品价格、会员规则、积分费率和退款政策。
- 本轮不删除历史 MZFPay 订单或迁移其交易号。

## Decisions

### 1. 以适配器替换路由中的硬编码提供方

后端根据 `checkout_provider` 解析 `MzfpayPaymentProvider` 或 `AlipayPaymentProvider`。适配器统一提供启用状态、支付 URL 和通知解析结果，业务服务只处理标准化后的订单号、交易号、金额、验签结果和支付状态。

替代方案是在现有 MZFPay 类中增加支付宝分支。该方案改动较少，但会继续混淆渠道与提供方，难以实现回调隔离，因此不采用。

### 2. 订单持久化支付提供方

订单新增 `provider` 字段，历史数据迁移为 `mzfpay`。回调处理时必须比较通知提供方与订单提供方，避免相同订单号被错误渠道确认。`channel` 继续表达用户支付渠道，`provider` 表达接入平台。

替代方案是根据支付 URL 域名推断提供方。URL 可变且历史动作可能过期，不适合作为账务依据。

### 3. 直接实现支付宝开放平台 RSA2 协议

支付宝官方请求采用 `RSA2`、`SHA256WithRSA`、UTF-8 和 JSON `biz_content`。后端使用 `cryptography` 读取应用私钥并签名，使用支付宝公钥验证异步通知。密钥支持以环境变量注入，换行转义在服务端规范化。

相比引入维护状态不明确的第三方支付宝 SDK，协议边界较小且更容易审计；所有字段和签名规则集中在单一适配器中。

### 4. 浏览器返回与支付通知严格分离

`return_url` 只把用户带回收费页，不确认订单。只有验签、身份、金额和交易状态全部通过的异步通知才能调用现有 `confirm_checkout_paid`。

### 5. 配置驱动灰度切换

`OFFERSTEADY_CHECKOUT_PROVIDER` 默认留空，取得商户资质并完成沙箱与小额验收后再切换为 `alipay`。空配置时不创建新支付订单，但不影响商品、积分、会员和历史订单查询。支付宝配置包括网关、应用 ID、应用私钥、支付宝公钥、卖家 ID、通知地址、返回地址和支付有效期。

## Risks / Trade-offs

- [商户应用尚未审批，无法真实付款验收] → 默认不启用支付宝，新实现先通过合成密钥和通知测试，正式参数到位后执行小额验收。
- [密钥格式错误导致签名失败] → 启动时按需校验 PEM，并返回明确的配置错误，不记录密钥正文。
- [伪造通知尝试入账] → 强制 RSA2、应用与卖家身份、订单提供方、金额和状态联合校验。
- [切换后旧订单仍等待回调] → 每个订单持久化提供方，两个通知入口并存直到旧订单过期。
- [支付宝仍可能执行商户风控] → 使用真实商品名称、服务端金额和合规经营类目；技术接入不承诺绕过平台风控。

## Migration Plan

1. 增加订单 `provider` 字段，历史记录默认迁移为 `mzfpay`。
2. 部署支付适配器和支付宝通知入口，但保持默认提供方为空，不开放新支付订单。
3. 个体工商户认证后创建支付宝开放平台自用型网页应用，配置 RSA2 密钥并签约电脑网站支付。
4. 在沙箱验证下单、验签、金额不匹配、重复通知和权益幂等。
5. 生产环境执行小额真实支付、异步通知、主动查看订单和权益到账验收。
6. 将 `OFFERSTEADY_CHECKOUT_PROVIDER` 切换为 `alipay`；异常时回滚该变量即可恢复旧提供方，新旧订单均保留。

## Open Questions

- 个体工商户应用最终获批的支付产品是否包含电脑网站支付；若只获批手机网站支付，需要补充 WAP 请求模式。
- 正式商户签约后返回的卖家 ID 使用 PID 还是账号字段，以控制台信息为准配置。
