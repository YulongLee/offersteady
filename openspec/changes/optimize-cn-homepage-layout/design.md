## Context

国服首页由 React 展示层和 Vite 首页入口共同构建，现有导航、下载页、公开价格页及面试流程已经稳定。当前问题主要是展示层级：首屏行动入口不够集中，下载和公开价格入口需要更容易发现，内容区在不同宽度下的间距与栅格节奏不一致。

## Goals / Non-Goals

**Goals:**

- 让首屏在桌面和移动端都清晰呈现产品定位、免费使用和下载两个主要行动。
- 保留现有导航、页脚和首屏 Windows/macOS 下载入口，不增加重复入口或新说明。
- 让匿名用户从首页进入公开 `/pricing`，不被内部账单路由打断。
- 通过 CSS 调整统一首页容器宽度、垂直节奏和小屏栅格，不改变业务状态。

**Non-Goals:**

- 不改 URL 结构、后端接口、登录、支付、面试会话或下载逻辑。
- 不新增首页业务模块、不添加未经核实的产品数据或性能承诺。
- 不修改海外版页面。

## Decisions

1. **沿用现有入口并强化层级**：保留 HomepageDownloads 的真实 manifest 下载、Mac 架构菜单和键盘交互，只统一两按钮宽度。不改变下载地址和可用性判断。
2. **公开价格优先**：首页价格卡的匿名查看入口改为 `/pricing`。内部 `/app/billing` 仍由已登录用户使用，避免将认证逻辑混入营销页。
3. **CSS 优先的响应式调整**：通过已有 class 调整 grid、gap、max-width 和断点，避免引入依赖或重写组件。桌面保持双栏，窄屏自然堆叠。
4. **静态入口与 React 保持一致**：若首页静态入口存在对应 CTA 或链接，则同步更新；否则只修改实际渲染该区域的组件，避免重复内容。
5. **真实生产副本**：当前主工作区首页落后于线上，不向主工作区覆盖生产 App。独立源码副本用于实现/测试，交付限定文件补丁；本轮不部署。
6. **首页样式隔离**：使用 `.cn-commercial-home` 及其首页父容器限定选择器，保持其他公开页、登录和海外版不变。移动导航保留合作伙伴入口；卡片使用既有 `--panel-bg-soft` 变量。
7. **第二轮展示深化**：2026-09-12 用户确认在当前设计上继续优化商业表达。保留品牌、H1、下载、导航和业务入口，用项目现有宣传视频的合成示例截图展示真实界面；截图明确标为演示内容，不声称真实用户记录。只用不含价格和个人信息的截图。
8. **先理解再购买**：将已有操作教程放在套餐之前，保留两段视频但避免同时自动加载/播放；套餐金额与时长继续来自 state.billing，权益表述复用 BillingPage 与现有公开 pricing 文档。不得编造销量、折扣、退款承诺或审核结论。
9. **既有代码迭代而非重做**：本轮继续修改隔离候选，不使用新模板，不新增网站路由；预览 fixture 和 noindex 入口仍不进入生产构建。
10. **第三轮视觉修正**：基于用户认可的复查方向直接迭代已有页面，不更换品牌或新建模板。首屏桌面尽量两行标题，现有截图按右侧回答区域展示并明确为局部预览，保留查看完整截图入口；不修改图片内容。
11. **套餐选择代替重复卡片**：所有有效已发布时长与金额仍可见，默认选择目录中最短有效期，用户选择后更新统一价格与知识材料权益。只改变展示状态，不创建订单；目录更新导致当前选择失效时回退到首个有效套餐。
12. **减少页面重复**：三步使用说明并入教程侧栏；岗位提供直接可见摘要与已有内部链接，完整场景仍可展开；FAQ 统一为左侧介绍、右侧问题列表，合作伙伴横幅改为次级文字入口。

## Risks / Trade-offs

- [首屏信息增加后视觉密度上升] → 使用次级样式和有限文案，不增加新的说明段落。
- [首页价格链接变化导致旧书签行为不同] → 仅改变匿名首页 CTA 目标，登录后的账单路由保持不变。
- [样式调整影响既有断点] → 运行类型检查、构建和测试，并检查桌面/移动端布局。
